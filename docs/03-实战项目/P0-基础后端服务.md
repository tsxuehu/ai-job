# P0：基础后端服务

## 项目定位

实现一个多用户任务管理服务。重点不是业务创意，而是证明可以独立完成一个正确、可测试、可运行的后端服务。

也可以替换为记账、书签、课程或内容管理等领域，但必须保留本项目的工程验收项。

## 用户故事

- 用户可以注册、登录和管理自己的会话。
- 用户可以创建、查询、更新和删除任务。
- 用户只能访问自己的数据。
- 用户可以按状态、标签、时间分页查询任务。
- 重复提交不会产生意外的重复数据或状态覆盖。

## 必做能力

### API 与安全

- REST API、统一错误格式、参数校验和分页。
- 密码安全存储、认证、对象级权限检查。
- 请求 ID、访问日志、敏感字段脱敏和基本限流。

### 数据库

- 关系型数据库、迁移、约束、索引和事务。
- 使用执行计划分析至少一个查询。
- 使用乐观锁、条件更新或等价机制处理并发修改。

### 工程质量

- 清晰的模块边界和配置管理。
- 单元测试、数据库集成测试和 API 端到端测试。
- 健康检查、优雅停机和结构化日志。
- Dockerfile 和一条命令启动的本地依赖环境。
- OpenAPI 文档和可复现的 README。

## 推荐里程碑

1. 写出需求边界、API 草案和数据模型。
2. 完成数据库迁移与用户、任务核心流程。
3. 加入认证、权限、校验和错误处理。
4. 补齐单元、集成和端到端测试。
5. 完成容器化、文档、日志和健康检查。
6. 分析慢查询与并发修改，记录实验结果。

## 必须测试的失败场景

- 重复注册、错误密码和过期凭证。
- 越权访问其他用户的数据。
- 非法分页、过长输入和未知字段。
- 并发修改导致的覆盖。
- 数据库连接失败和服务关闭时的在途请求。

## 验收门槛

- [ ] 新环境可以根据 README 一条命令启动。
- [ ] 数据库结构完全由迁移创建，不依赖手工操作。
- [ ] 核心流程和权限边界有自动化测试。
- [ ] 日志不泄露密码、令牌和敏感字段。
- [ ] 能解释表结构、索引、事务和错误模型。
- [ ] 有一份慢 SQL 或并发正确性实验报告。
- [ ] 能在五分钟内演示系统，并说明三个已知限制。

## 面试证据

完成后整理：架构图、ER 图、OpenAPI、测试报告、关键提交、一个 ADR 和五分钟项目讲解。
