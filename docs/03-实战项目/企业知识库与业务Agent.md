# 带权限控制的企业知识库与业务 Agent

## 1. 项目目标

用户可以上传或同步企业文档，在权限范围内检索并获得带引用的答案；Agent 可以调用受控业务工具，高风险动作需要人工审批，所有操作可追踪和审计。

## 2. 核心模块

### 传统后端

- 用户、组织、租户、角色和权限。
- 文档上传、对象存储、异步解析和任务状态。
- PostgreSQL/MySQL、Redis 和消息队列。
- API 鉴权、限流、幂等、重试和审计。
- Docker、CI/CD、日志、指标和 Trace。

### RAG

- 文档解析、清洗、Chunk、元数据和 embedding。
- 关键词 + 向量混合检索及 rerank。
- 检索前可信权限过滤、来源引用和拒答。
- 增量更新、删除、重建和索引版本。

### Agent

- 结构化工具调用和服务端参数校验。
- 工具最小权限、状态、超时、幂等和补偿。
- 高风险操作审批、沙箱、步骤/token 预算。
- 可恢复任务、执行轨迹和审计记录。

## 3. 推荐迭代顺序

1. 单体 API、用户与文档 CRUD。
2. 异步解析、对象存储和任务重试。
3. 基础检索、引用和小型评测集。
4. 混合检索、重排、权限与增量索引。
5. 一个只读工具和一个需审批的写工具。
6. 限流、超时、降级、观测与成本记录。
7. 压测、故障演练、回归评测和部署。

## 4. 必须演练的故障

- 文档解析失败或消息重复消费。
- 数据库提交成功但异步事件发送失败。
- 模型超时、限流、输出格式错误或供应商不可用。
- 向量索引更新滞后或权限元数据错误。
- Agent 重复调用、无限循环或越权请求。
- 单一租户突发流量拖慢系统。

每个故障都应记录：发现方式、影响范围、止损、恢复、数据修复和防复发措施。
