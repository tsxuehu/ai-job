# 实战项目阶梯

项目用于把知识转化为可运行、可验证、可面试的工程证据。项目数量不必多，但必须能够启动、测试、观测、解释和复盘。

## 三级项目

| 项目 | 目标阶段 | 核心能力 | 完成后的主要证据 |
| --- | --- | --- | --- |
| [P0 基础后端服务](P0-基础后端服务.md) | L1 | API、数据库、鉴权、测试、容器 | 可运行服务、OpenAPI、测试和慢 SQL 分析 |
| [P1 生产级业务系统](P1-生产级业务系统.md) | L2 | 缓存、消息、幂等、观测、压测、恢复 | 架构图、压测报告、ADR 和事故复盘 |
| [P2 企业知识库与业务 Agent](企业知识库与业务Agent.md) | L2 AI 专项 | RAG、Agent、权限、评测、安全、成本 | 评测集、质量报告、审计轨迹和安全测试 |

推荐顺序是 P0 → P1 → P2。AI 应用岗位也不应跳过 P0 和 P1，因为模型功能同样依赖数据库、权限、异步任务、可靠性和生产工程。

## 统一交付物

每个项目都应包含：

- 需求边界、架构图、数据模型和 API 文档。
- 可复现的本地环境、数据库迁移和启动说明。
- 单元、集成、端到端及关键并发测试。
- 日志、指标、Trace 和主要告警。
- 性能或质量基线、实验结果和限制说明。
- 架构决策记录、故障演练及项目复盘。
- 一分钟概述、十分钟深挖和常见追问材料。

可以使用 [项目 README 模板](../../templates/项目README模板.md)、[架构决策记录模板](../../templates/架构决策记录模板.md) 和 [事故复盘模板](../../templates/事故复盘模板.md)。

## 数据真实性

- 所有 QPS、延迟、成功率和成本都要注明环境、数据规模与测量方法。
- 个人项目不要伪造用户数、业务收益或生产事故。
- 没有真实业务数据时，说明这是实验结果，并明确不能外推的范围。
- 面试时能够现场解释每个数字的来源和计算过程。
