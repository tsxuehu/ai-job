# C++：运行时与性能

C++ 通常提前编译为机器码，没有语言级垃圾回收；但标准库、异常、RTTI、分配器、线程库和操作系统共同构成实际运行环境。

## 执行模型与成本

- 自动对象按作用域逆序析构，动态对象由所有权对象决定释放时机。
- 虚函数通常动态分派；模板通常编译期实例化和单态化。
- 异常的常规路径成本取决于实现，但抛出和展开栈不是免费的。
- “零开销抽象”表示不用的能力不付费，不表示所有抽象都没有成本。
- 编译器优化可能改变指令布局，但不能修复未定义行为。

## 主要性能因素

1. 算法复杂度和数据规模。
2. 数据布局、缓存局部性与内存带宽。
3. 动态分配、复制、虚调用和分支预测。
4. 锁竞争、线程调度、系统调用和网络等待。
5. 序列化、日志和跨进程边界。

连续容器常因缓存局部性优于节点容器；批量处理可减少调用和同步开销。SIMD、对象池、arena 和无锁结构只应在热点明确后使用。

## 性能分析方法

```text
定义负载和指标 → 建立基线 → profiler 定位热点
→ 单变量修改 → 正确性回归 → 重新测量
```

同时记录吞吐、P50/P95/P99、CPU、内存、分配和队列等待。基准测试要防止编译器消除无用计算，并固定编译模式、机器和数据集。

## 易错点

- 用 Debug 构建结果评价 Release 性能。
- 看到一次耗时就下结论，忽略预热、噪声和尾延迟。
- 为避免一次复制引入共享所有权，反而增加分配和同步。
- 优化单函数，却让整体 IO、锁竞争或数据布局更差。

## 验收

- 能解释对象析构、虚函数、模板、异常和分配的主要成本。
- 能用 profiler 和基准数据定位瓶颈，而不是凭直觉改代码。
- 每个性能结论都包含环境、负载、统计数据和正确性验证。
