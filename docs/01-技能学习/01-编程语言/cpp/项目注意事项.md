# C++：项目特性与注意事项

这篇不是第十三个公共知识分类，而是 C++ 项目中必须额外建立的检查清单。C++ 最特殊的地方是：源码看起来相近的操作，可能具有完全不同的所有权、生命周期、ABI 和运行时成本。

## C++ 项目的核心心智模型

```text
对象由谁拥有
→ 哪些位置只是借用
→ 借用能持续多久
→ 资源如何确定释放
→ 代码以什么编译/链接配置进入最终程序
```

## 项目中最需要注意的事项

| 事项 | 为什么特殊 | 项目做法 |
| --- | --- | --- |
| 所有权不写在统一类型系统里 | 裸指针、引用可能拥有，也可能只观察 | 字段和签名约定：值/`unique_ptr` 拥有，引用/裸指针默认不拥有 |
| 视图可能悬垂 | `string_view`、`span`、迭代器不延长底层寿命 | 不返回局部对象视图，不让视图进入比数据更长的异步任务 |
| 容器扩容使引用失效 | `vector` 扩容会移动存储 | 修改容器前检查 invalidation 规则，不能保留旧地址 |
| 未定义行为不保证复现 | 越界、data race 等可能在优化后表现完全不同 | CI 分别运行 ASan、UBSan、TSan，并开启严格警告 |
| RAII 与异常安全 | 资源能自动释放，但业务状态可能修改一半 | 资源全部 RAII；状态更新采用先构造、后提交 |
| 多态析构 | 通过基类指针删除派生对象需要虚析构 | 多态基类声明 `virtual ~Base() = default` |
| ABI 与编译配置 | 编译器、标准库、宏和选项会改变二进制边界 | 固定工具链、运行库和关键编译选项；跨边界保持窄接口 |
| ODR 与静态初始化 | 多份定义或跨文件初始化顺序会产生隐蔽故障 | 减少全局对象，理解 inline/模板定义位置 |

## 异步任务中的生命周期

```cpp
auto service = std::make_shared<Service>();

executor.submit([service, request = std::move(request)] {
    service->handle(request);
});
```

- 按引用捕获局部变量后异步执行，任务开始时对象可能已经销毁。
- 捕获 `this` 不拥有当前对象；必要时由明确拥有者等待任务结束，或捕获受控的共享所有权。
- 不要把所有对象都改成 `shared_ptr`。默认仍应是值和 `unique_ptr`，共享所有权只用于真实的共同生命周期。
- 关闭顺序通常是：停止接收 → 通知任务 → 等待线程 → 再销毁任务依赖。

## 构建也是语言语义的一部分

C++ 项目必须记录：语言标准、编译器、标准库、Debug/Release 选项、异常/RTTI 策略、依赖版本、目标架构和 sanitizer 构建方式。头文件、宏和编译选项不一致可能让相同源码产生不兼容类型或 ABI。

## PR 必查

- [ ] 新增指针、引用和视图的所有者与有效期是否明确？
- [ ] 异步回调是否捕获了可能提前销毁的对象？
- [ ] 容器修改后是否继续使用旧迭代器、引用或地址？
- [ ] 异常和早返回是否仍保持资源与业务状态正确？
- [ ] 多态基类是否能被安全析构，复制/移动行为是否合理？
- [ ] 新依赖和编译选项是否影响 ABI、产物和部署环境？
- [ ] 内存、未定义行为和并发检测是否覆盖新增路径？
