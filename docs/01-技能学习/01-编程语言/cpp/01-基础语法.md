# C++：基础语法

本章只建立阅读和编写 C++ 程序所需的最小语法框架。真正决定 C++ 代码是否可靠的所有权、生命周期和资源管理，分别放在后续章节。

## 程序结构

```cpp
#include <iostream>

int main() {
    const int port{8080};
    std::cout << "listen on " << port << '\n';
    return 0;
}
```

- `#include` 在预处理阶段引入声明；不要把它理解成运行时导入模块。
- 语句通常以分号结束，代码块使用花括号。
- `main` 是普通可执行程序的入口，返回 `0` 表示成功。
- 名称放进 `namespace`，避免大型项目中的命名冲突。

## 声明、定义和初始化

```cpp
int retries{3};                 // 声明、定义并初始化
extern int global_limit;        // 只有声明，定义在其他翻译单元
auto timeout = std::chrono::milliseconds{500};
```

优先使用花括号初始化，它能阻止部分窄化转换。局部变量应靠近使用位置并立即初始化；`auto` 适合右侧类型明显的表达式，不应隐藏关键的精度、单位和所有权。

## 需要认识的语法设施

- `//` 和 `/* */` 是注释；注释解释约束和原因，不复述代码。
- `using` 可以创建类型别名；避免在头文件写 `using namespace ...`。
- `enum class` 提供有作用域的枚举，优于无作用域枚举和魔法数字。
- 属性如 `[[nodiscard]]`、`[[fallthrough]]` 能把意图交给编译器检查。
- 宏只是预处理文本替换，优先使用常量、函数、模板和 `constexpr`。

## 编译基线

学习时至少使用 C++20，并开启高等级警告；警告不是风格提示，而是潜在缺陷线索。需要能区分语法错误、类型错误、链接错误和运行时错误。

## 易错点

- 把声明当成定义，最终得到未定义符号或重复定义。
- 忘记初始化基础类型，随后读取不确定值。
- 宏参数发生重复求值，或宏名称污染其他代码。
- 根据缩进判断作用域，而忽略实际的花括号。

## 验收

- 能从入口、声明、表达式和代码块解释一个最小程序。
- 能说明声明与定义、编译期与运行时、宏与函数的区别。
- 能配置严格警告并看懂最常见的编译、链接错误。
