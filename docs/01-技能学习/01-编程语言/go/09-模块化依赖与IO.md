# Go：模块化、依赖与 IO

Go 工程通过 module 管理版本，通过 package 建立编译和可见性边界，通过小接口组合模块与 IO。

## package by capability

Go package 应围绕业务能力或稳定技术能力组织，而不是把所有 controller、service、model 分别堆在全局技术层目录中。

```text
cmd/server                 # composition root
internal/task              # 任务领域和用例
internal/task/httpapi      # HTTP adapter
internal/task/postgres     # 存储 adapter
internal/platform/clock    # 少量稳定跨业务能力
```

- `internal` 提供编译器可执行的导入限制，但仍要保持公开名称最少。
- 接口由消费方定义，只包含调用方真正需要的方法；具体 package 不必提前导出庞大接口。
- 核心 package 不导入 HTTP 框架、数据库 driver 和具体 SDK，adapter 负责转换。
- `cmd` 负责显式创建具体实现和组装依赖，不通过 `init` 或全局注册表隐藏依赖。
- Go 禁止 import cycle。出现环时重审职责、移动消费方接口或合并本就同一职责的 package，不能一律搬进 `common`。

不要创建 `utils`、`common`、`models` 大杂烩；它们会让所有 package 互相耦合。共享代码只有在语义稳定且确实被多个业务消费时才上移。

## module 与 package

```text
project/
├── go.mod
├── cmd/server/main.go
├── internal/service/
├── internal/storage/
└── tests/
```

- module 是版本与依赖管理单元，由 `go.mod` 标识。
- package 是代码组织和编译单元，同目录源码通常属于同一 package。
- `internal` 限制目录树外导入，用于隐藏实现。
- `cmd/<name>` 放可执行入口，只负责配置、依赖组装和进程生命周期。
- 避免 `utils` 大杂烩，按业务职责和稳定能力划分包。

`init` 隐藏调用和顺序，优先显式初始化。导入环通常说明职责或依赖方向需要调整。

## Reader、Writer 与流式 IO

```go
func CopyLimited(dst io.Writer, src io.Reader, limit int64) error {
	_, err := io.Copy(dst, io.LimitReader(src, limit))
	return err
}
```

小接口让文件、网络、内存、压缩流复用同一逻辑。使用缓冲降低小系统调用，同时处理部分读取/写入、总大小、最大行长、超时和取消。

## JSON、HTTP 与外部协议

- DTO 与领域模型分离，明确必填、未知字段、数字精度和时间格式。
- HTTP client 复用并设置超时；请求通过 context 传播截止时间。
- server 设置读取、写入、空闲、头部和请求体限制。
- 关闭响应体，按需要读取剩余数据以支持连接复用。

## 依赖治理

`go.mod` 声明版本，`go.sum` 校验内容；用 `go mod tidy` 保持依赖一致。外部库通过适配层隔离，升级后运行测试、兼容性和性能检查，避免提交仅本机有效的 replace 路径。

## 验收

- 能画出 package 导入图，并说明接口为何定义在消费方。
- task 核心可以不启动 HTTP 和数据库独立测试。
- 不存在 common/utils 大包、隐藏 init 依赖和跨模块内部数据修改。
- 能解释 module、package、internal 和 cmd 的职责。
- IO/HTTP 边界有大小、超时、取消、错误和资源关闭限制。
- 新环境可根据 `go.mod/go.sum` 完成构建与测试。
