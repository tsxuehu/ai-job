# Go：测试与工程实践

Go 的统一工具链适合把格式、静态检查、测试、竞争检测和性能剖析固化为工程门禁。

## 工具链门禁

- `gofmt`：统一格式。
- `go vet`：发现部分可疑代码和 API 误用。
- `go test`：运行单元、集成、示例和 fuzz 测试。
- `go test -race`：检测实际执行路径中的数据竞争。
- `go test -bench`：执行基准测试。
- CI 固定 Go 版本并校验 module 依赖。

race detector 只能发现测试覆盖路径上的竞争，不能证明没有竞争。

## 测试方式

- 表驱动测试覆盖正常、边界和错误输入。
- subtest 组织场景，并行时避免共享可变夹具。
- 小接口和内存实现隔离数据库、消息系统等外部依赖。
- `httptest` 测 handler、client 和协议边界。
- fuzz 面向解析器、序列化和不可信输入。
- 并发测试覆盖超时、取消、重复、关闭和 goroutine 泄漏。

## 生产基线

- HTTP client/server 显式配置超时、连接池和大小限制。
- 外部调用传播 context，总预算不能被层层重置。
- 后台任务可停止、可等待、可观察错误。
- 连接、goroutine、队列、缓存和响应体都有容量上限。
- 提供 readiness、liveness、优雅停机和过载保护。
- 日志、指标和 trace 覆盖流量、错误、延迟和饱和度。

## 综合项目

实现有界任务 API，包含参数校验、存储接口、超时、取消、并发限制、错误映射、优雅停机与指标；用表驱动测试、fuzz、race、benchmark、pprof 和 trace 验证。

## 最终验收

- [ ] 能独立构建、测试、剖析和部署 Go 服务。
- [ ] 能用 race、pprof 和 trace 定位不同类型问题。
- [ ] 能证明 goroutine、连接、队列和请求都有生命周期边界。
- [ ] CI 和生产观测足以复现竞争、泄漏与性能故障。
