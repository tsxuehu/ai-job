# Go：测试、调试与性能实践

本章只讲如何写测试、复现故障和分析性能。package/module、构建、CI/CD 和部署放在 [13-工程化](13-工程化.md)。

## 1. 表驱动测试

```go
func TestNewOrder(t *testing.T) {
	tests := []struct {
		name   string
		amount int64
		want   error
	}{
		{"valid", 100, nil},
		{"zero", 0, ErrInvalidAmount},
		{"negative", -1, ErrInvalidAmount},
	}

	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) {
			_, err := NewOrder("o-1", tt.amount)
			if !errors.Is(err, tt.want) {
				t.Fatalf("got %v, want %v", err, tt.want)
			}
		})
	}
}
```

测试稳定行为，不比较完整错误文本。可以使用 `package order_test` 强制只通过公开 API 测试；确需验证内部算法时才使用同 package 测试。

## 2. 取消、并发和资源测试

```go
func TestWorkerStopsAfterCancel(t *testing.T) {
	ctx, cancel := context.WithCancel(context.Background())
	done := make(chan struct{})
	go func() {
		defer close(done)
		_ = RunWorker(ctx)
	}()

	cancel()
	select {
	case <-done:
	case <-time.After(time.Second):
		t.Fatal("worker did not stop")
	}
}
```

并发测试还要运行 race detector。timer、response body、Rows 和 goroutine 的关闭路径都应覆盖。

## 3. fuzz 与 benchmark

```go
func FuzzParseOrder(f *testing.F) {
	f.Add([]byte(`{"id":"o-1","amount":100}`))
	f.Fuzz(func(t *testing.T, input []byte) {
		_, _ = ParseOrder(input) // 目标：不能 panic、越界或无限分配
	})
}

func BenchmarkParseOrder(b *testing.B) {
	input := []byte(`{"id":"o-1","amount":100}`)
	b.ReportAllocs()
	for b.Loop() { _, _ = ParseOrder(input) }
}
```

## 4. 一组能直接执行的命令

```bash
gofmt -w .
go vet ./...
go test ./...
go test -race ./...
go test -fuzz=FuzzParseOrder -fuzztime=10s ./...
go test -bench=. -benchmem ./...
```

pprof 定位 CPU、分配和保留，trace 观察调度、阻塞和系统调用。逃逸或分配只有在 profile 证明是热点时才需要优化。

## 5. 验收

- [ ] 表驱动测试覆盖正常、边界和错误。
- [ ] 超时、取消、关闭和 goroutine 泄漏有测试。
- [ ] race、fuzz 和 benchmark 使用固定命令运行。
- [ ] 能用 pprof/trace 解释一次真实瓶颈。
