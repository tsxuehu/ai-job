# Go：并发与异步

goroutine 很轻量，但不是免费资源。启动前必须回答：谁拥有、怎样停止、谁等待、错误如何传播。

## goroutine 生命周期

```go
group, ctx := errgroup.WithContext(ctx)
group.Go(func() error {
	return worker.Run(ctx)
})
if err := group.Wait(); err != nil {
	return err
}
```

重要任务不能“go 一下就不管”。使用任务组、WaitGroup 或明确协议管理启动、取消、等待和失败。

## channel 与 select

- 无缓冲 channel 让发送接收同步，有缓冲 channel 提供有限排队。
- channel 容量来自背压设计；无界 goroutine 不能代替无界队列。
- 通常由生产流程所有者关闭；关闭表示以后不再发送。
- nil channel 会永久阻塞，可动态禁用 select 分支，也可能造成泄漏。

```go
select {
case task, ok := <-tasks:
	if !ok { return nil }
	return handle(ctx, task)
case <-ctx.Done():
	return ctx.Err()
}
```

## context、锁与 atomic

context 作为第一个参数传播取消、截止时间和请求元数据，不存入长期结构；派生后及时调用 cancel。取消是协作式的，阻塞 API 必须支持 context 或有其他中断手段。

mutex 保护一组共享不变量；channel 适合传递工作和所有权；atomic 适合简单计数、标志和已证明的状态转换。不要把“用 channel”当成所有并发问题的固定答案。

## 常见故障

- producer 在 consumer 退出后永久阻塞，或 goroutine 等待无人操作的 channel。
- 多个 goroutine 并发读写 map。
- 无界创建任务压垮调度器、内存和下游。
- 请求取消后后台工作继续执行，timer/ticker 未停止。

## 验收

- 每个 goroutine 有所有者、停止条件、等待和错误路径。
- 能根据状态所有权选择 channel、mutex 或 atomic。
- 能实现有容量、取消、错误传播和优雅停机的 worker pool。
