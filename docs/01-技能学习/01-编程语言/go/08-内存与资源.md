# Go：内存与资源

Go 用垃圾回收管理普通对象内存，但文件、连接、响应体、事务、goroutine 和定时器仍需要确定的业务生命周期。

## GC、逃逸与分配

- 局部变量放栈还是堆由逃逸分析决定，不能只看 `new` 或取地址语法。
- 高分配率、大量短命对象和长期存活引用都会增加 GC 工作。
- 小 subslice 可能持有整个大数组，必要时复制所需区域。
- map、全局缓存、goroutine 和 timer 都可能形成逻辑泄漏，GC 无法回收仍可达对象。

使用编译器逃逸信息和 pprof 观察真实行为，不要把所有参数改成指针来“减少复制”。

## 资源关闭

```go
resp, err := client.Do(req)
if err != nil {
	return err
}
defer resp.Body.Close()
```

- 文件、响应体、数据库 rows、事务和连接按 API 契约关闭。
- 持久化写入要检查 flush 和 close 阶段错误。
- `defer` 紧邻成功获取资源的位置。
- timer/ticker 停止，goroutine 通过 context 或 channel 退出。

## 复制与共享

赋值 struct 会复制所有字段，但其中的指针、slice、map、channel 仍指向共享数据。`sync.Mutex` 等同步对象通常不应在使用后复制；含锁类型的方法常用指针 receiver。

API 必须说明返回集合是否共享内部状态，必要时深复制。对象池只在 profile 证明分配为热点后使用，并清理残留数据。

## 验收

- 能区分 GC 管理的内存与必须主动关闭的业务资源。
- 能用逃逸分析和 pprof 定位分配、保留和逻辑泄漏。
- 能识别 struct 复制后的内部共享与同步对象复制问题。
