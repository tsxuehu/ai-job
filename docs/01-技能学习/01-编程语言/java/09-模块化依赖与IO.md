# Java：模块化、依赖与 IO

Java 工程通常以 package 建立源码边界，以 Maven/Gradle module 建立构建边界，以 NIO、HTTP 和 JDBC 接入外部系统。

## package by feature 与模块化单体

Spring Bean 能被扫描和注入，只说明运行时容器找得到它，不说明架构依赖合理。优先围绕业务能力组织 package：

```text
task/
├── domain
├── application
├── adapter/in/web
├── adapter/out/persistence
└── config
```

- domain/application 不依赖 Spring MVC、JPA entity、数据库 driver 和外部 SDK。
- package-private 类型可把内部实现限制在模块包中；公开 API 保持最小。
- adapter 依赖核心端口并实现接口，composition/config 负责 Bean 组装。
- HTTP DTO、领域对象与 persistence entity 分离，避免一个实体穿透所有模块。
- 使用架构测试或构建 module 规则阻止跨业务模块导入内部 package。

小型项目先做 package 级模块化单体；确需独立构建、复用或强隔离时再拆 Maven/Gradle module。JPMS 能通过 exports/requires 强化可见性，但采用前需要验证 Spring、反射和第三方生态。不要建立所有模块都依赖的 `common` JAR。

## 项目与模块

```text
src/main/java/
src/main/resources/
src/test/java/
pom.xml 或 build.gradle
```

package 按业务职责或稳定能力划分，避免 controller/service/util 大杂烩。JPMS 的 `module-info.java` 可声明 requires/exports，但多数框架项目是否采用需要结合反射与生态支持。

## 构建与依赖

- Maven/Gradle 只选一个作为项目标准，并提交 wrapper/锁定策略。
- 区分直接、传递、编译期、运行时和测试依赖。
- 使用依赖收敛或版本平台解决同库多版本，不盲目排除。
- 记录 JDK、构建工具和关键插件版本，生成可复现产物。
- 依赖升级检查许可证、漏洞、二进制兼容和行为变化。

## 文件、HTTP 与序列化

- Files/NIO 提供路径、流式读取和异步/通道能力；大文件避免一次全部载入。
- 明确 Charset，不依赖平台默认编码。
- HTTP client 配置连接、请求和总体超时，复用连接并限制响应体。
- JSON DTO 与领域模型分离，运行时校验必填、未知字段、大小和版本。

## JDBC 边界

连接、Statement 和 ResultSet 使用 try-with-resources；事务明确 begin/commit/rollback。连接池设置容量、超时与泄漏检测，SQL 参数使用预编译语句。ORM 不能消除 N+1、事务和锁问题。

## 验收

- 能区分 Java package、JPMS module、Maven/Gradle module 和部署服务。
- 核心业务不依赖 Spring/JPA 具体类型，适配器可以独立替换。
- 架构规则能够发现跨模块内部访问和错误依赖方向。
- 能建立可复现 Maven/Gradle 构建并解释依赖范围。
- 文件/HTTP/JSON 具备编码、大小、超时和错误限制。
- JDBC 操作有资源关闭、事务和连接池容量边界。
