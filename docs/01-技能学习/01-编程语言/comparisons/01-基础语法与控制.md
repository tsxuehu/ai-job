# 五门语言的基础语法与控制：校验一笔订单

> 目标：用同一个“金额必须大于 0，状态必须可处理”的判断，看懂五门语言最常见的声明、分支、循环和穷举方式。

## 1. 先看结论

| 语言 | 代码块 | 局部变量 | 有限状态的常见表达 |
|---|---|---|---|
| C++ | `{}` | `const`、`auto` | `enum class + switch` |
| Go | `{}` | `:=`、`var` | 具名常量 + `switch` |
| Java | `{}` | 显式类型、`var`、`final` | `enum/sealed + switch` |
| Node.js/TS | `{}` | `const`、`let` | 判别联合 + `switch` |
| Python | 缩进 | 名称直接绑定对象 | Enum/类模式 + `match` |

共同原则只有三条：先拒绝非法输入；有限状态尽量穷举；不要把副作用塞进复杂条件。

## 2. 同一个判断怎么写

### C++

```cpp
Result validate(const Order& order) {
    if (order.amount_cents <= 0) return Result::invalid_amount;

    switch (order.status) {
    case Status::pending: return Result::ok;
    case Status::paid: return Result::already_paid;
    }
    throw std::logic_error("unknown status");
}
```

### Go

```go
func validate(order Order) error {
	if order.AmountCents <= 0 {
		return ErrInvalidAmount
	}
	switch order.Status {
	case StatusPending:
		return nil
	case StatusPaid:
		return ErrAlreadyPaid
	default:
		return ErrUnknownStatus
	}
}
```

### Java

```java
Result validate(Order order) {
    if (order.amountCents() <= 0) return Result.INVALID_AMOUNT;
    return switch (order.status()) {
        case PENDING -> Result.OK;
        case PAID -> Result.ALREADY_PAID;
    };
}
```

### Node.js / TypeScript

```ts
function validate(order: Order): Result {
  if (order.amountCents <= 0) return { kind: "invalidAmount" };
  switch (order.status) {
    case "pending": return { kind: "ok" };
    case "paid": return { kind: "alreadyPaid" };
    default: return assertNever(order.status);
  }
}
```

### Python

```python
def validate(order: Order) -> Result:
    if order.amount_cents <= 0:
        return Result.INVALID_AMOUNT
    match order.status:
        case Status.PENDING:
            return Result.OK
        case Status.PAID:
            return Result.ALREADY_PAID
        case _:
            raise ValueError("unknown status")
```

## 3. 循环最容易混淆什么

| 问题 | C++ | Go | Java | Node.js/TS | Python |
|---|---|---|---|---|---|
| 遍历值 | range-for | `range` | enhanced for | `for...of` | `for...in iterable` |
| 遍历对象键 | map iterator | `range map` | `entrySet` | `Object.keys`/`Map` | `dict.items` |
| 异步串行 | 框架/协程决定 | 普通循环调用 | 普通循环调用 | `for...of + await` | `for + await` |
| 顺序是否稳定 | 看容器 | map 不保证 | 看集合 | Map 有序、对象有规则 | dict 保持插入顺序 |

Node.js 的 `for...in` 遍历属性键，不是数组值；Go 的 map 顺序不能作为业务契约；C++ 修改容器时要检查迭代器失效。

## 4. 项目检查

- 金额、长度和索引在计算前检查范围。
- `switch/match` 新增状态时能得到编译提示或明确失败。
- 条件表达式不隐藏网络、写库等副作用。
- 循环有终止条件、容量上限和错误路径。
- 异步循环明确是串行还是有界并发。

## 5. 面试怎么问

**为什么早返回通常比多层 if 更清楚？** 失败路径先结束，主流程保持从上到下，资源清理由 RAII、defer、try-with-resources、finally 或 with 保证。

**switch 是否一定能穷举？** 不一定。C++/Go 的 default、TypeScript 的宽泛类型、Python 的动态对象都可能隐藏新增状态；要结合封闭类型和检查工具。

**异步函数放进普通循环会怎样？** 取决于是否立即等待。Node/Python 中逐次 await 是串行；一次创建全部任务是并发，还必须增加上限、取消和等待。
