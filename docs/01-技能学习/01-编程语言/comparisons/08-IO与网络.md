# 五门语言的 IO 与网络：读取订单并调用库存服务

> 目标：看懂五门语言如何表达文本、字节、流、HTTP、JSON 和数据库 IO，以及哪些资源必须关闭。

统一流程：读取订单文件 → 解析 JSON → 调库存 HTTP 接口 → 写数据库。

## 1. 一张表先看结论

| 语言 | 字节类型 | 流式抽象 | 常见关闭方式 |
|---|---|---|---|
| C++ | `byte`/`char` 容器 | iostream、span、框架 buffer | RAII |
| Go | `[]byte` | `io.Reader/Writer` | `defer Close` |
| Java | `byte[]`/ByteBuffer | InputStream、Reader、NIO Channel | try-with-resources |
| Node.js/TS | Buffer/Uint8Array | Stream、AsyncIterable | pipeline/finally/框架生命周期 |
| Python | bytes/bytearray | file-like object、iterator | with/async with |

GC 只能回收普通对象，不能代替文件、响应体、数据库事务和连接的业务关闭协议。

## 2. 流式复制的代码形态

### C++

```cpp
std::ifstream input(path, std::ios::binary);
std::ofstream output(target, std::ios::binary);
output << input.rdbuf();
if (!input.eof() || !output) throw IoError{};
```

### Go

```go
input, err := os.Open(path)
if err != nil { return err }
defer input.Close()
_, err = io.CopyN(output, input, maxBytes)
return err
```

### Java

```java
try (var input = Files.newInputStream(path);
     var output = Files.newOutputStream(target)) {
    input.transferTo(output);
}
```

### Node.js / TypeScript

```ts
await pipeline(
  createReadStream(path),
  byteLimit(maxBytes),
  createWriteStream(target),
);
```

### Python

```python
with path.open("rb") as source, target.open("wb") as sink:
    shutil.copyfileobj(source, sink, length=64 * 1024)
```

示例只展示代码形态。真实项目还要处理总量限制、部分读写、磁盘满、取消、临时文件和原子替换。

## 3. HTTP 调用必须共同回答的问题

- 总 deadline、连接和读取超时分别是多少？
- 请求取消后底层 socket/任务是否真的停止？
- client 和连接池是否复用？
- body 是否有大小上限并被关闭/消费？
- 哪些状态码可重试，操作是否幂等？
- DNS、代理和重定向是否可能访问不允许的地址？

C++ 通常由所选网络库提供取消；Go 传播 context；Java 结合客户端超时和任务中断；Node 使用 AbortSignal；Python 同步/异步客户端必须与入口模型一致。

## 4. JSON 和数据库不是“解析成功就安全”

JSON 还要校验未知字段、字符串/数组长度、金额精度、时间和业务状态。TypeScript 类型和 Python 类型标注不会运行时校验输入。

数据库必须使用参数化 SQL，事务要有提交/回滚边界，rows/cursor/result set 要关闭，连接池要有容量和获取超时。不要让 ORM 隐藏 N+1、锁和事务传播问题。

## 5. 语言专项风险

| 语言 | 高频风险 |
|---|---|
| C++ | 部分读写、buffer 生命周期、库回调悬垂 |
| Go | 忘关 response body/Rows、默认 client 无完整超时策略 |
| Java | 文本编码默认值、JDBC 多层资源、阻塞任务占满线程 |
| Node.js | 忽略 Stream 背压、Buffer/RSS 增长、超时只做 Promise.race |
| Python | async 中调用同步 SDK、文件默认编码、生成器未关闭 |

## 6. 面试怎么问

**为什么大文件不能直接 readAll？** 内存与延迟随输入增长，攻击者还能放大资源消耗；流式处理配合总量限制和背压更稳定。

**超时和取消有什么区别？** 超时决定何时发出取消；取消只有被底层 IO 和调用链观察后才真正停止工作。

**连接池为什么既不能太小也不能无限大？** 太小造成等待，太大把压力推给数据库或下游；容量应由实例并发、事务时间和下游承载共同决定。
