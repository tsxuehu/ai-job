# 五门语言的容器与迭代：保存和查找订单

> 目标：根据顺序、查找、修改、共享和内存需求选择容器，而不是只背 API 名称。

统一需求：按创建顺序保存订单；按订单号快速查找；输出时保持稳定顺序；处理十万条数据时不能无界复制。

## 1. 常用容器对照

| 需求 | C++ | Go | Java | Node.js/TS | Python |
|---|---|---|---|---|---|
| 动态序列 | `vector` | slice | `ArrayList` | Array | list |
| 键值查找 | `unordered_map` | map | `HashMap` | Map | dict |
| 有序键 | `map` | 排序后的 key slice | `TreeMap` | 排序 key | 排序 key |
| 去重 | `unordered_set` | `map[T]struct{}` | `HashSet` | Set | set |
| 队列 | `deque` | slice/channel | `ArrayDeque` | Array/专用队列 | deque |

理论复杂度只是起点。连续内存、分配、哈希成本、对象大小和访问模式都会改变真实性能。

## 2. 同一个“按 ID 建索引”

### C++

```cpp
std::unordered_map<OrderId, Order> index;
for (const auto& order : orders) {
    index.insert_or_assign(order.id(), order);
}
```

### Go

```go
index := make(map[OrderID]Order, len(orders))
for _, order := range orders {
	index[order.ID] = order
}
```

### Java

```java
var index = new HashMap<OrderId, Order>();
for (var order : orders) {
    index.put(order.id(), order);
}
```

### Node.js / TypeScript

```ts
const index = new Map<OrderId, Order>();
for (const order of orders) {
  index.set(order.id, order);
}
```

### Python

```python
index: dict[OrderId, Order] = {
    order.id: order for order in orders
}
```

五段代码看起来相似，但值是否复制不同：C++/Go 的值对象可能被复制；Java、Node.js、Python 容器通常保存对象引用。修改取出的对象前先回答“是在改副本还是共享对象”。

## 3. 迭代时修改为什么危险

- C++ 插入、删除、扩容可能让迭代器、引用或指针失效。
- Go `range` 得到元素值副本；修改 struct 副本不会写回 slice。
- Java 直接修改集合结构可能触发并发修改异常，应使用 Iterator 或集合 API。
- Node.js 数组的 `sort/reverse/splice` 会原地修改，`map/filter` 返回新数组。
- Python 遍历 dict/set 时改变大小会失败；生成器只能消费一次并可能持有资源。

## 4. 大数据要流式处理

不要把数据库所有行、完整 HTTP body 或巨大文件先装进列表。优先 iterator、generator、Stream、Reader 或分页游标，并明确：批次大小、总量上限、错误、取消和关闭。

## 5. 项目检查

- 业务是否需要稳定顺序？
- key 的相等和哈希在生命周期内是否稳定？
- 返回容器时是共享、浅复制还是深复制？
- 迭代时修改是否使当前位置失效？
- 队列、缓存、索引和结果集合是否有容量上限？
- 大数据能否逐批处理并及时释放资源？

## 6. 面试怎么问

**为什么默认序列通常不是链表？** 连续数组的缓存局部性和较少分配常常胜过链表的理论中间插入优势，最终要按负载测量。

**浅复制容器后，里面的对象是否独立？** 通常不独立。浅复制只复制外层结构，嵌套对象或引用仍可能共享。

**HashMap 的平均 O(1) 为什么仍可能慢？** 哈希计算、冲突、扩容、内存布局、对象分配和缓存失效都产生实际成本。
