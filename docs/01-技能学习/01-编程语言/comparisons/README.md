# 五门编程语言横向对比

> 目标：使用同一个后端案例，对比 C++、Go、Java、Node.js/TypeScript、Python 的代码形式和运行语义。

横向对比不是背语法表。每篇都从一个具体问题开始：复制订单改了谁、创建失败怎么传播、连接由谁关闭、并发任务怎样取消。

## 学习顺序

| 顺序 | 对比方面 | 统一案例 | 核心问题 |
|---:|---|---|---|
| 1 | [数据与类型](01-数据与类型.md) | 复制并修改订单 | 两个变量是独立数据还是共享对象？ |
| 2 | [面向对象与抽象](02-面向对象与抽象.md) | 订单选择支付渠道 | 如何封装状态、替换实现、避免继承滥用？ |
| 3 | [错误处理](03-错误处理.md) | 创建订单失败 | 错误如何表示、传播、转换和重试？ |
| 4 | [内存与资源](04-内存与资源.md) | 导出订单报表 | 谁关闭数据库连接、文件和后台任务？ |
| 5 | [并发与异步](05-并发与异步.md) | 同时支付 100 个订单 | 如何限流、超时、取消、等待和避免竞争？ |
| 6 | [运行时与性能](06-运行时与性能.md) | 一次创建订单请求 | 代码如何执行，性能问题应该去哪里找？ |
| 7 | [工程化](07-工程化.md) | 把订单功能变成可交付服务 | 如何组织代码、构建、测试、发布和生产运行？ |

## 三个层次

```text
语言语义
数据、错误、资源、并发、运行时
        ↓
代码设计
面向对象、抽象
        ↓
工程落地
功能模块、仓库结构、构建、测试、发布和运行
```

建议先掌握语言语义，再学习模块和工程结构。否则目录看起来正确，代码仍可能因为共享数据、资源泄漏或取消失效而出问题。

## 阅读方式

每篇不需要同时精读五门语言：

1. 先看开头案例和总览表；
2. 精读自己的主语言；
3. 选择一门辅助语言对照；
4. 最后看项目检查清单；
5. 用同一个案例自己写一遍。

对比时始终回答：

- 代码看起来有什么不同？
- 底层语义有什么不同？
- 哪种差异会在真实项目中产生 Bug？
- 面试时能否用具体案例说明？
