# Rust：容器与迭代

Rust 容器 API 把所有权和借用体现在迭代方式中，很多“边遍历边破坏容器”的问题会在编译期被拒绝。

## 常用集合

| 类型 | 适合场景 | 关键点 |
| --- | --- | --- |
| `Vec<T>` | 默认动态序列 | 连续布局，扩容可能移动元素 |
| `VecDeque<T>` | FIFO、两端操作 | 环形分段存储 |
| `HashMap<K, V>` | 按键查找 | `entry` 可避免重复查询 |
| `BTreeMap<K, V>` | 有序键、范围查询 | 对数复杂度 |
| `HashSet<T>` | 去重和成员判断 | 需要 `Hash + Eq` |
| `BTreeSet<T>` | 有序集合 | 需要 `Ord` |

已知规模时使用 `with_capacity`，但容量应来自负载而非随意猜测。

## 三种迭代语义

```rust
for task in tasks.iter() { /* 借用 &Task */ }
for task in tasks.iter_mut() { /* 独占借用 &mut Task */ }
for task in tasks.into_iter() { /* 消费集合，得到 Task */ }
```

迭代器适配器是惰性的，必须由 `collect`、`sum`、`for_each` 或循环消费。链式表达过长时拆成有名称的步骤，避免为了函数式外观牺牲可读性。

```rust
let ids: Vec<_> = tasks.iter()
    .filter(|task| task.is_ready())
    .map(Task::id)
    .collect();
```

## 借用驱动的算法设计

不能在持有元素引用时同时扩容或任意修改容器。可先收集键、使用 `retain`/`drain`/`entry`，或拆分为两个阶段；不要第一反应就是克隆整个集合。

## 验收

- 能按顺序、查找和布局选择集合，并说明复杂度。
- 能区分 `iter`、`iter_mut`、`into_iter` 的所有权效果。
- 能重构“遍历时修改容器”的算法而不使用无意义 clone。
