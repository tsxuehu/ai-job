# Rust：测试与工程实践

Rust 类型系统能排除一部分错误，不能证明业务规则、协议兼容、取消安全和 unsafe 不变量。

## 质量门禁

- `cargo fmt`：统一格式。
- `cargo check`：快速类型和借用检查。
- `cargo clippy`：发现惯用法和常见缺陷。
- `cargo test`：运行单元、集成和文档测试。
- CI 使用锁定依赖，对实际部署目标执行 release 构建。

警告策略应统一，不能为了通过门禁大范围允许 lint。

## 测试分层

- 模块内单元测试覆盖私有逻辑和状态转换。
- `tests/` 集成测试只通过 library crate 的公开 API。
- 文档测试保证示例可编译并与 API 同步。
- 属性测试和 fuzz 适合解析器、状态机、不可信输入。
- 并发测试覆盖超时、取消、关闭、任务 panic 和资源释放。

## 安全与调试工具

- backtrace 和调试器定位 panic、崩溃和调用链。
- Miri 检查部分 unsafe、别名和未定义行为。
- sanitizer 辅助检查内存和线程问题，支持范围依目标工具链而定。
- unsafe/FFI 模块必须有安全不变量说明、边界测试和 fuzz。
- 依赖审计是补充，不能替代升级后的兼容与性能测试。

## 生产基线

- 记录构建版本、rustc、feature、目标和锁文件。
- 统一错误响应，监控 panic、任务失败和线程退出。
- 请求、连接、任务、队列和响应体全部设置上限。
- 支持超时、取消、背压和优雅停机。

## 最终验收

- [ ] 能独立构建、测试、调试和发布 Rust 服务。
- [ ] 能定位一次阻塞、锁竞争、分配或任务泄漏。
- [ ] 能说明所有 unsafe、panic 和后台任务的生产策略。
- [ ] 能用测试和观测验证错误、资源与关闭边界。
