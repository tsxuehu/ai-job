# Rust：表达式与逻辑控制

Rust 将条件、模式匹配和循环都设计成表达式，使“状态是否完整覆盖”能进入类型检查。

## if 与 match

```rust
let label = if score >= 60 { "pass" } else { "fail" };

let message = match state {
    State::Ready { id } => format!("ready: {id}"),
    State::Failed(reason) => format!("failed: {reason}"),
};
```

- `if` 条件必须是 `bool`，不会把整数或指针隐式当真假。
- `if` 两个分支作为表达式时必须产生兼容类型。
- `match` 必须覆盖全部状态，特别适合 enum、`Option` 和 `Result`。
- `if let`、`let ... else` 适合只关心某个模式并尽早退出。

## 模式与解构

模式可用于 `let`、参数、`match`、`if let` 和循环：

```rust
let (host, port) = endpoint;
let Some(user) = current_user else {
    return Err(AuthError::MissingUser);
};
```

`_` 忽略一个值，`..` 忽略剩余字段。对业务状态使用过宽的 `_` 分支，可能掩盖以后新增的 enum 变体。

## 循环

- `for` 遍历实现 `IntoIterator` 的值，优先于手写下标。
- `while` 适合条件驱动，`while let` 适合重复模式解构。
- `loop` 是无限循环，也可通过 `break value` 产生结果。
- 标签可从嵌套循环退出，但复杂控制流应考虑提取函数。

## 易错点

- 块尾误加分号，得到 `()` 而不是预期值。
- `match` 中使用通配符，遗漏未来状态的处理。
- 在范围和容量计算中忽略溢出。
- 为满足借用规则把循环全部改成索引，反而引入越界。

## 验收

- 能使用 `if`、`match` 和模式表达完整业务状态。
- 能选择 `for`、`while`、`while let` 和 `loop`。
- 能解释块尾值、穷举检查和显式布尔条件的意义。
