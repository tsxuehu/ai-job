# Rust：错误处理

Rust 将可恢复失败放进返回类型，让调用方在编译器约束下处理、转换或传播。

## Option、Result 与 ?

```rust
fn load(path: &Path) -> Result<Config, ConfigError> {
    let text = std::fs::read_to_string(path)
        .map_err(ConfigError::Read)?;
    parse(&text).map_err(ConfigError::Parse)
}
```

- `Option<T>` 表达值可能不存在，但不解释原因。
- `Result<T, E>` 表达成功值或结构化错误。
- `?` 在失败时提前返回，并通过 `From` 等规则转换错误。
- 库提供稳定错误类型；应用边界补充上下文并转成协议响应。

## panic 的边界

`panic!` 适合被破坏的程序不变量或确实无法继续的初始化状态，不用于普通用户输入、找不到记录和网络超时。`unwrap`/`expect` 在测试、示例或已经证明不可能失败的局部位置使用，并写出理由。

线程、异步任务、FFI 和请求入口要定义 panic 策略。panic 展开不能跨越不允许展开的 FFI 边界。

## 错误设计

- 领域错误保持可枚举和可判断，不依赖解析文本。
- 系统错误保留 source 链、操作对象和必要上下文。
- 只在请求或任务边界记录一次，避免每层重复日志。
- 错误信息和 Debug 输出不得泄露密钥与敏感输入。
- 重试只针对可重试类别，并包含退避、上限和整体截止时间。

## 易错点

- 到处 `unwrap`，把普通失败变成进程或任务 panic。
- 把所有错误擦成字符串，失去类型判断和来源链。
- 用 `Option` 表达本应区分权限、格式和依赖失败的操作。
- 捕获 panic 后假设所有业务状态仍然一致。

## 验收

- 能根据语义选择 `Option`、`Result` 或 panic。
- 能设计可判断、带来源链且适合协议映射的错误类型。
- 能说明错误记录、转换、重试与 panic 隔离发生在哪一层。
