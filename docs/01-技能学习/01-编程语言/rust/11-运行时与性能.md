# Rust：运行时与性能

Rust 通常提前编译成本地代码，没有语言级 GC。所有权检查主要发生在编译期，不意味着程序不需要运行时库或不会分配内存。

## 执行成本模型

- 值离开作用域时执行 `Drop`；释放时机通常确定。
- 泛型通常单态化，运行快但可能增加编译时间和二进制体积。
- `dyn Trait` 使用动态分派，适合运行时替换和稳定边界。
- async 函数编译为状态机，大小受跨 `.await` 保存的数据影响。
- panic 策略可选择展开或 abort，影响清理、二进制和部署行为。
- allocator、链接方式、LTO 和 feature 会影响产物特征。

## 常见热点

- 无意义 `clone`、`String` 转换和短命分配。
- 哈希、序列化、系统调用与数据复制。
- 锁竞争、跨 await 保存过大状态、执行器上的阻塞调用。
- 不合理数据布局和算法复杂度。

不要为消除一次 clone 引入贯穿全系统的复杂生命周期；先测量 clone 是否真的在热点。

## 分析流程

1. 固定 release profile、工具链、硬件、负载和输入。
2. 记录吞吐、P95/P99、CPU、内存、分配和队列。
3. 使用 benchmark、火焰图和系统 profiler 定位热点。
4. 一次改变一个主要因素并重新运行正确性测试。

基准代码要阻止无用计算被优化掉，并区分微基准与服务级容量测试。

## 验收

- 能解释单态化、动态分派、Drop、panic 与 async 状态机的成本。
- 能通过 profiler 区分分配、锁、系统调用和算法热点。
- 性能结论包含环境、负载、统计数据和正确性回归。
