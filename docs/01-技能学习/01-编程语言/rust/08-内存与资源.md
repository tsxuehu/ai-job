# Rust：内存与资源

Rust 通过所有权、借用和 `Drop` 在没有语言级 GC 的情况下管理内存和业务资源。

## 所有权与借用规则

每个值有一个所有者，所有者离开作用域时资源被释放。一个值在同一有效范围内可以有多个共享借用，或者一个独占可变借用，但不能同时两者都有。

这些规则同时防止 use-after-free、无效别名和许多数据竞争。生命周期标注只描述引用关系，不会延长真实寿命。

## 资源与指针类型

| 类型 | 用途 |
| --- | --- |
| `Box<T>` | 堆分配、递归类型、独占 trait object |
| `Rc<T>` / `Weak<T>` | 单线程共享所有权与非拥有关系 |
| `Arc<T>` / `Weak<T>` | 跨线程共享所有权与非拥有关系 |
| `Cell<T>` / `RefCell<T>` | 单线程内部可变性，部分规则运行时检查 |
| `Mutex<T>` / `RwLock<T>` | 跨线程同步保护的内部可变性 |

引用计数只解决“活多久”，不解决“谁能改”。`Rc`/`Arc` 环会造成逻辑泄漏，父子或观察者关系使用 `Weak`。

## Drop 与资源清理

文件、socket、锁守卫等在离开作用域时通过 `Drop` 清理。不要依赖精确的临时值销毁时机完成业务提交；需要提前释放锁时使用更小作用域或显式 `drop(guard)`。

## unsafe 与 FFI

`unsafe` 允许执行编译器无法证明安全的操作，不会自动保证这些操作正确：

- 把 unsafe 限制在小模块，对外提供安全 API。
- 为每个块记录指针有效性、长度、对齐、别名、线程等不变量。
- FFI 明确谁分配谁释放、字符串编码、错误和 panic 边界。
- 使用 Miri、sanitizer、模糊测试辅助验证。

## 验收

- 能画出 move、borrow 和 drop 的时间线。
- 能按单/多线程、独占/共享、可变/不可变选择指针类型。
- 能说明每个 unsafe 或 FFI 边界由什么不变量保证安全。
