# Go：变量、数据与类型

Go 的变量和参数都按值复制，但被复制的值内部可能包含指针，因此必须区分“复制描述符”和“复制底层数据”。

## 1. 基础类型和业务类型

- `bool`。
- `int`、`int64`、`uint64` 等；协议和存储字段使用明确宽度。
- `float32`、`float64`；精确金额使用整数最小单位或十进制方案。
- `string` 是不可变字节序列，通常承载 UTF-8 文本。
- `byte` 是 `uint8` 别名，`rune` 是 `int32` 别名，表示 Unicode 标量值。
- 指针保存地址，但普通 Go 代码没有指针运算。

```go
type UserID string
type Timeout time.Duration
```

具名类型可以阻止相同底层类型的业务值被随意混用，并可定义自己的方法。

本章使用下面这个最小订单类型讲值、复制和内存关系：

```go
type Order struct {
	id          string
	amountCents int64
}
```

因此后文物理图中的 `Order` 就由一个 string 字段和一个 int64 字段组成。订单状态、支付编号和行为会在 [05-面向对象与抽象](05-面向对象与抽象.md)中加入，避免在学习内存模型时同时引入过多业务字段。

## 2. 零值与 nil

每种类型都有零值。设计类型时尽量让零值可用；做不到时由构造或方法明确校验。nil pointer 解引用会 panic，nil slice 可读取和 append，nil map 可读取但写入会 panic。

## 3. 变量、指针和实际数据

先把三个概念分开：

| 概念 | 它是什么 |
| --- | --- |
| 变量 | 一个保存值的位置，例如 `n`、`order`、`p` |
| 指针 | 一种值，内容是另一个变量或对象的地址 |
| 实际数据 | `int` 数字、`Order` 字段、slice 底层数组或 map 键值等真正被使用的内容 |

下面的“物理图”按常见 64 位 Go 实现画出主要机器字，帮助理解复制和共享。必须先说明边界：Go 语言规范规定的是语义，不承诺具体字节布局；编译器还可能把值放进寄存器、栈或堆，甚至完全消除。图中不画具体地址，也不把当前 runtime 实现当成业务代码可以依赖的 ABI。

| Go 值 | 变量中大致保存什么 | 常见 64 位实现 |
| --- | --- | --- |
| `int` | 整数本身 | 1 个机器字 |
| `[3]int` | 3 个连续的 int 元素 | 3 个机器字 |
| `*Order` | `Order` 的地址 | 1 个机器字 |
| `string` | 字节数据地址、字节长度 | 2 个机器字 |
| `[]Order` | 底层数组地址、长度、容量 | 3 个机器字 |
| `map[K]V` | 指向 runtime map 状态的引用 | 通常 1 个机器字 |
| interface | 动态类型/方法信息、动态值 | 通常 2 个机器字 |
| struct | 各字段依次组成，可能有对齐填充 | 由字段决定 |

### 3.1 普通值：变量直接保存数据

```go
n := 10
```

可以理解为：

```text
变量 n
┌────────────┐
│ int：10    │
└────────────┘
```

赋值会复制 `n` 中的值：

```go
copy := n
copy = 20

fmt.Println(n)    // 10
fmt.Println(copy) // 20
```

结构体也是值。直接赋值会复制字段：

```go
first := Order{id: "order-1", amountCents: 100}
second := first
second.amountCents = 200

fmt.Println(first.amountCents)  // 100
fmt.Println(second.amountCents) // 200
```

此时有两个独立的 `Order` 结构体值。`id` 字段是 string 描述值，复制后可以安全地共享不可变字符串字节：

```text
变量 first                         变量 second
┌──────────────────────┐          ┌──────────────────────┐
│ id.data ─────────────┼────┐ ┌───┼─ id.data             │
│ id.len = 7           │    │ │   │ id.len = 7           │
│ amountCents = 100    │    │ │   │ amountCents = 200    │
└──────────────────────┘    │ │   └──────────────────────┘
                            ▼ ▼
                    ┌─────────────────┐
                    │ order-1 的字节   │
                    └─────────────────┘
```

“复制结构体”准确地说是复制全部字段。字段是 `int64` 时复制数字；字段是 string 时复制“地址和长度”；字段是 pointer、slice 或 map 时，也会复制其中的引用，因此仍可能共享底层数据。

### 3.2 指针：变量保存的是地址

```go
order := Order{id: "order-1", amountCents: 100}
p := &order
```

`order` 保存结构体字段，`p` 的静态类型是 `*Order`，运行时值主要是 `order` 的地址：

```text
编译期：p 的静态类型是 *Order

变量 p                  变量 order                         字符串字节
┌──────────────┐        ┌──────────────────────┐          ┌─────────┐
│ order 地址 ──────────▶│ id.data ───────────────────────▶│ order-1 │
└──────────────┘        │ id.len = 7           │          └─────────┘
                        │ amountCents = 100    │
                        └──────────────────────┘
```

普通指针值里没有“类型指针”或“方法表指针”，`Order` 结构体里也不会因为定义了方法就多出一个隐藏的 vptr。编译器已经从源码知道 `p` 的静态类型是 `*Order`。

```go
func (o *Order) AmountCents() int64 {
	return o.amountCents
}

amount := p.AmountCents()
```

对普通 `*Order` 调用方法时，目标方法可在编译期确定，可以近似理解为把 `p` 作为接收者参数传给 `(*Order).AmountCents`。方法代码位于程序代码区，不存放在每个 `Order` 值中。

runtime 确实还维护 GC、反射和接口分派需要的类型信息与栈图，但这些信息不等于“每个普通指针后面都隐藏一个类型指针”。当普通值被装进 interface 时，interface 才形成下面要讲的动态类型信息。

`*p` 表示沿地址找到实际的 `Order`。Go 访问结构体字段时会自动处理这次解引用，因此通常直接写：

```go
p.amountCents = 200

fmt.Println(order.amountCents) // 200
fmt.Println((*p).amountCents)  // 200，与上一行含义相同
```

复制指针只复制地址，不复制它指向的数据：

```go
p2 := p
p2.amountCents = 300

// p、p2 都指向 order
fmt.Println(order.amountCents) // 300
```

图只表达引用关系，不表示 `order` 一定在栈或堆；实际位置由逃逸分析和优化决定。

### 3.3 interface：动态类型和动态值一起保存

运行时多态需要同时知道“当前装的具体类型”和“具体值在哪里”。这部分信息保存在 interface value 中，而不是塞进普通 struct：

```go
type Payer interface {
	Pay() error
}

type Alipay struct {
	merchantID string
}

func (Alipay) Pay() error { return nil }

alipay := &Alipay{merchantID: "merchant-1"}
var gateway Payer = alipay
```

对非空接口 `Payer`，当前 Go runtime 可以近似理解为：

```text
interface 变量 gateway（两个机器字）
┌────────────────────────────┐
│ itab 地址 ─────────────────┼──▶ 接口类型：Payer
│                            │    具体类型：*Alipay
│                            │    Pay 的方法入口 ───▶ 程序代码区
├────────────────────────────┤
│ data 地址 ─────────────────┼──▶ Alipay{merchantID: "merchant-1"}
└────────────────────────────┘
```

`itab` 是 runtime 的实现概念，它把接口类型、具体类型和所需方法入口关联起来。因此：

```go
gateway.Pay()
```

需要根据 interface 中的动态类型做运行时分派。空接口 `any` 没有要调用的方法，可以近似理解为“具体类型信息 + 动态值”。这些布局是理解当前实现的模型，不是 Go 规范保证的字段结构。

这里的动态值仍遵守按值复制：把 `*Alipay` 装入 interface，复制的是指针；把一个非指针 `Order` 装入 `any`，interface 保存的是那个 `Order` 值的字段副本，不会自动变成指向原变量的引用。如果结构体字段本身是 slice、map 或 pointer，复制后依然可能共享这些字段指向的底层数据。

还要特别注意“带类型的 nil”：

```go
var alipay *Alipay = nil
var gateway Payer = alipay

fmt.Println(alipay == nil)  // true
fmt.Println(gateway == nil) // false
```

此时 `gateway` 的动态类型部分是 `*Alipay`，只有 data 部分是 nil；interface 只有动态类型和动态值都为空时才等于 nil。

与 C++ 的典型虚函数实现相比：C++ 多态对象通常在对象内部带 vptr；Go 普通 struct 不带 vptr，动态分派信息位于 interface value 中。

### 3.4 slice：三个字段描述底层数组

slice 不是数组本身。slice value 保存底层数组地址、当前长度和容量：

```go
names := make([]string, 2, 3)
names[0] = "a"
names[1] = "b"
```

```text
变量 names（slice header，三个机器字）      底层数组
┌──────────────────────┐                  ┌─────┬─────┬─────┐
│ data 地址 ─────────────────────────────▶│ a   │ b   │     │
│ len = 2              │                  └─────┴─────┴─────┘
│ cap = 3              │
└──────────────────────┘
```

复制 slice 会得到另一个 header，但两个 header 可以指向同一个数组：

```go
other := names
other[0] = "changed"

fmt.Println(names[0]) // changed
```

```text
names header ──┐
               ├──▶ 同一个底层数组
other header ──┘
```

修改 `other[0]` 是修改共享数组；修改 `other` 自己的 len、cap 或 data 地址，不会自动改写 `names` 的 header。因此 `append` 必须返回新的 slice value，调用者必须接住。

### 3.5 map：值引用 runtime 管理的哈希表

```go
counts := make(map[string]int)
counts["book"] = 1
```

当前 runtime 中，map value 可以近似理解为指向 map 管理结构的引用；管理结构再找到哈希存储区域和键值数据：

```text
变量 counts               runtime map 状态                 哈希存储区域
┌──────────────┐          ┌──────────────────────┐         ┌──────────────┐
│ map 引用 ──────────────▶│ 数量、哈希与增长状态 ───────────▶│ "book" → 1   │
└──────────────┘          └──────────────────────┘         └──────────────┘
```

不同 Go 版本可能改变 map 的 bucket/group 等内部组织。业务代码不能依赖实际字段和布局，只需要掌握 nil map 没有可写的运行时状态，非 nil map 能找到已经初始化的哈希表。

复制 map value 后，两个变量仍引用同一个 map：

```go
other := counts
other["book"] = 2

fmt.Println(counts["book"]) // 2
```

map 和 slice 都可能共享底层数据，但它们不是同一种结构：slice value 明确具有 data、len、cap；map 的具体结构由 runtime 决定。

### 3.6 `new(map)` 为什么仍然得到 nil map

```go
p := new(map[string]int)
```

`new(T)` 创建一个用于保存 `T` 的位置，把它设为 `T` 的零值，再返回这个位置的地址。map 的零值是 nil，因此关系是：

```text
变量 p                         map 变量
┌──────────────────┐          ┌──────────────────────┐
│ map 变量的地址 ─────────────▶│ runtime map 引用：nil │
└──────────────────┘          └──────────────────────┘
                                         │
                                         └── 没有已初始化的哈希表
```

所以 `p` 和 `*p` 判断的是两件事：

```go
fmt.Println(p == nil)  // false：p 确实指向一个 map 变量
fmt.Println(*p == nil) // true：这个变量保存的 map 值是 nil
```

手动初始化就是把一个有效 map 放进 `p` 指向的位置：

```go
*p = make(map[string]int)
(*p)["book"] = 1
```

初始化后的关系是：

```text
变量 p                    map 变量                   runtime map 状态与哈希存储
┌──────────────┐          ┌────────────────┐         ┌──────────────────┐
│ 地址 ─────────────────▶│ map 引用 ───────────────▶│ "book" → 1 等数据 │
└──────────────┘          └────────────────┘         └──────────────────┘
```

实际项目通常不需要“指向 map 变量的指针”这一层，直接使用 `m := make(map[string]int)`。

## 4. 值的创建与初始化

Go 没有统一的“创建对象”语法。基础值、结构体、指针和内置容器的创建方式不同：

| 写法 | 得到的类型 | 含义 |
| --- | --- | --- |
| `var n int` | `int` | 声明变量，使用该类型的零值 |
| `n := 10` | `int` | 在函数内声明变量，并用右侧结果初始化 |
| `Order{...}` | `Order` | 创建并初始化一个结构体值 |
| `&Order{...}` | `*Order` | 创建结构体值，并取得它的指针 |
| `new(Order)` | `*Order` | 创建零值结构体，并返回指针 |
| `make(map[string]int)` | `map[string]int` | 初始化可直接写入的 map |
| `NewOrder(...)` | 由函数决定 | 执行校验和初始化的普通工厂函数 |

`var` 只声明时使用零值；`:=` 在函数内声明并使用右侧结果初始化。`Order{...}` 产生结构体值，`&Order{...}` 产生指向结构体的指针。它们的复制和共享关系见上一节。

### 4.1 `new` 与 `make`

```go
p := new(int)                      // *int，指向零值 0
order := new(Order)                // *Order，字段都是零值
names := make([]string, 0, 8)      // []string，长度 0、容量 8
counts := make(map[string]int)     // 可写入的 map[string]int
jobs := make(chan Job, 10)         // 可使用的 chan Job
```

- `new(T)` 可用于任意类型，创建零值 `T` 并返回 `*T`。
- `make(T)` 只用于 slice、map、channel，初始化内部运行时状态并返回 `T`。
- 对结构体，`new(Order)` 和 `&Order{}` 结果接近；需要设置字段时通常使用 `&Order{...}`。
- `new(map[string]int)` 得到指向 nil map 变量的指针，不能代替 `make(map[string]int)`。

### 4.2 `NewXxx`：项目定义的工厂函数

Go 没有构造函数关键字。`NewOrder` 只是一个普通函数，惯例上用它集中校验参数并创建合法值：

```go
func NewOrder(id string, amountCents int64) (*Order, error) {
	if id == "" {
		return nil, errors.New("订单 ID 不能为空")
	}
	if amountCents <= 0 {
		return nil, errors.New("订单金额必须大于 0")
	}

	return &Order{
		id:          id,
		amountCents: amountCents,
	}, nil
}
```

调用者得到一个经过校验的订单：

```go
order, err := NewOrder("order-1", 100)
if err != nil {
	return err
}
```

`new(Order)` 只能得到 ID 为空、金额为 0 的零值订单；`NewOrder(...)` 则可以保证 ID 和金额符合本章的业务规则。

### 4.3 这些写法不决定栈或堆

`new`、`make` 和 `&` 描述需要什么值，不直接指定内存必须放在栈还是堆。Go 编译器通过逃逸分析决定实际存放位置：

```go
func calculate() int {
	p := new(int)
	*p = 10
	return *p
}
```

这里的值只在函数内部使用，编译器可能把它放在栈或寄存器中，甚至完全消除分配。

```go
func createOrder() *Order {
	return &Order{id: "order-1"}
}
```

这里返回的指针在函数结束后仍要使用，`Order` 通常会逃逸到堆。无论编译器选择哪里，Go 都保证指针有效；业务代码应先写清值、指针和所有权关系，再通过编译诊断或 profile 检查实际分配。

## 5. array、slice 与 map

[《The Go Programming Language》](https://www.gopl.io/)第 4 章按照 array、slice、map、struct 的顺序讲复合类型：先理解真正保存元素的 array，再理解 slice 如何共享 array，最后理解 map 的键值语义。这里沿用这条主线，并补上现代 Go 标准库与生产边界。

### 5.1 array：长度属于类型，赋值复制所有元素

```go
first := [3]int{10, 20, 30}
second := first
second[0] = 99

fmt.Println(first[0])  // 10
fmt.Println(second[0]) // 99
```

`[3]int` 变量直接包含三个 int。`[3]int` 和 `[4]int` 是不同类型；`[...]int{10, 20, 30}` 可以让编译器计算长度。array 只有在“长度本身有业务含义”时经常直接使用，例如固定哈希值、矩阵行或协议字段。一般变长序列使用 slice。

如果元素类型可比较，array 也可使用 `==` 比较；slice 不能和另一个 slice 直接比较。

### 5.2 slice：区分 nil、空值、长度和容量

```go
var nilOrders []Order             // nil，len=0，cap=0
emptyOrders := []Order{}          // 非 nil，len=0，cap=0
orders := make([]Order, 0, 100)   // 非 nil，len=0，cap=100
```

三者都能读取 `len`，也都能交给 `append`：

```go
nilOrders = append(nilOrders, Order{id: "order-1", amountCents: 100})
```

但 nil slice 和已初始化的空 slice 在与 nil 比较、标准库 `encoding/json` 编码及部分 API 契约中可能不同。slice 只能与 nil 比较，不能用 `==` 比较两个 slice 的元素。

最常见的初始化错误是混淆长度与容量：

```go
order := Order{id: "order-1", amountCents: 100}

orders := make([]Order, 100)    // 已经有 100 个零值元素
orders = append(orders, order)  // 现在长度是 101

orders = make([]Order, 0, 100) // 长度 0，预留容量 100
orders = append(orders, order)  // 现在长度是 1
```

`make` 的容量只是预留空间，不是最大长度；业务上限仍需单独校验。

### 5.3 切片操作共享底层数组

```go
all := []string{"a", "b", "c", "d"}
part := all[1:3]

fmt.Println(part)      // [b c]
fmt.Println(len(part)) // 2
fmt.Println(cap(part)) // 3：从 all[1] 到底层数组末尾
```

```text
all  header ────────────────▶ [ a | b | c | d ]
                                  ▲   ▲
part header：data=&all[1] ─────────┘   │  len=2，cap=3
```

切片表达式不会复制元素：

```go
part[0] = "changed"
fmt.Println(all[1]) // changed
```

三下标切片可以限制新 slice 的容量：

```go
part := all[1:3:3] // low=1, high=3, max=3；len=2，cap=2
part = append(part, "new")
```

因为 `len == cap`，这次 append 必须使用新的底层数组，不会覆盖 `all[3]`。它仍不是“深复制”；append 之前的两个元素起初来自同一数组。

### 5.4 append 返回新的 slice value

`append` 可能复用原数组，也可能分配新数组。无论哪种情况，它都会返回更新后的 slice value：

```go
func addOrder(orders []Order, order Order) []Order {
	return append(orders, order)
}

orders := make([]Order, 0, 10)
order := Order{id: "order-1", amountCents: 100}
orders = addOrder(orders, order)
```

不能只写：

```go
addOrder(orders, order) // 返回的新 len、cap、data 被丢弃
```

容量足够时，返回值可能仍指向原数组；容量不足时，返回值会指向新数组。容量具体怎样增长属于 runtime 实现细节，代码不能假设每次翻倍。

`copy` 复制元素，并返回实际复制数量；源和目标重叠也能正确处理：

```go
n := copy(dst, src)
```

从超大数组取一个很小的 slice，仍可能让整个数组不能被回收。需要独立保存时显式复制：

```go
small := slices.Clone(big[:10]) // 浅复制十个元素
```

`Clone` 是浅复制：元素中的 pointer、slice 或 map 仍可能共享底层数据。

### 5.5 map：初始化、查询、修改和删除

```go
orders := make(map[string]*Order, 1000) // 1000 是容量提示，不是上限
orders["order-1"] = &Order{id: "order-1", amountCents: 100}

order, ok := orders["order-1"]
if !ok {
	fmt.Println("订单不存在")
}

delete(orders, "order-1")
clear(orders) // Go 1.21+：删除全部键值
```

读取不存在的 key 会得到 value 类型的零值，因此需要区分“key 不存在”和“value 恰好是零值”时，必须使用 `value, ok := m[key]`。

```go
var counts map[string]int

fmt.Println(counts["paid"]) // 0：nil map 可以读取
counts["paid"] = 1          // panic：nil map 不能写入
```

map 字面量和 `make` 都能得到可写的 map：

```go
counts := map[string]int{"paid": 1}
empty := make(map[string]int)
```

### 5.6 map 的 key、比较和元素地址

map 的 key 必须支持 `==`，所以可以使用 string、数字、pointer，以及字段都可比较的 array/struct；不能使用 slice、map 或 function 作为 key。interface 类型可以作为 key，但放入其中的动态值也必须可比较，否则运行时会 panic。

map 自身只能与 nil 比较，不能用 `==` 比较两个 map。需要比较内容时，使用明确循环或 `maps.Equal`，并先确认 value 的相等语义。

map 元素可能在扩容时移动，因此不能取得稳定地址，也不能直接修改结构体 value 的字段：

```go
type Counter struct {
	Value int
}

counters := map[string]Counter{"paid": {Value: 1}}
// counters["paid"].Value++ // 编译错误：map 元素不可寻址

counter := counters["paid"]
counter.Value++
counters["paid"] = counter
```

如果 map 保存的是 pointer，复制出来的是 pointer，可以修改它指向的对象；这也意味着多个调用者会共享同一个对象。

### 5.7 map 遍历没有稳定顺序

```go
for id, order := range orders {
	fmt.Println(id, order.amountCents)
}
```

不能依赖 map 的遍历顺序，同一个 map 多次遍历也不保证相同。输出、签名或测试需要稳定顺序时，先取出 key 并排序：

```go
ids := make([]string, 0, len(orders))
for id := range orders {
	ids = append(ids, id)
}
slices.Sort(ids)

for _, id := range ids {
	order := orders[id]
	fmt.Println(id, order.amountCents)
}
```

遍历过程中插入的 key 可能出现也可能不出现。删除尚未遍历到的 key 后，它不会再出现；业务代码不应把这种行为当成有序处理流程。

### 5.8 slice 和 map 的并发边界

- 普通 map 允许多个 goroutine 在没有写入时并发读取；只要存在并发写，就必须同步。
- 常用方案是由一个 goroutine 独占、使用 `sync.Mutex/RWMutex`，或在特定场景使用 `sync.Map`；`sync.Map` 不是普通 map 的默认替代品。
- 多个 goroutine 修改同一个 slice header，或者修改同一底层数组的重叠位置，同样可能产生 data race。
- 锁住 map 不等于锁住 map 中 pointer 指向的对象；容器和元素的并发规则要分别设计。
- 使用 `go test -race ./...` 验证并发路径，但 race detector 不能代替所有权设计。

### 5.9 标准库辅助函数仍然是浅操作

现代 Go 的 `slices` 和 `maps` package 提供 `Clone`、`Equal`、`Sort`、`Copy` 等常用泛型函数。它们减少重复循环，但不会自动深复制对象，也不会让操作获得线程安全。

选择 `[]Order`、`[]*Order`、`map[string]Order` 或 `map[string]*Order` 时，真正要回答的是：复制元素还是共享对象、谁能修改、对象是否需要稳定地址、并发由谁保护。

## 6. string、byte 与 rune

string 值包含字节数据地址和字节长度，字符串字节不可通过 string 修改：

```go
s := "Go语言"
```

```text
变量 s（string header，两个机器字）       UTF-8 字节
┌──────────────────────┐                ┌────────────────────────────┐
│ data 地址 ───────────────────────────▶│ G o 语的3字节 言的3字节    │
│ len = 8              │                └────────────────────────────┘
└──────────────────────┘
```

`len(s)` 得到 8 个字节，不是 4 个 Unicode 标量，也不一定等于用户看到的字符数。`range` 字符串时索引是 rune 的起始字节位置；协议处理通常按 `[]byte`，Unicode 标量处理按 `range` 或 `[]rune`，用户可见字形还需要更高层 Unicode 库。

## 7. 转换

Go 不做大多数数值隐式转换。显式转换只改变表示，不自动检查溢出和业务范围。字符串与字节切片转换通常会复制，性能敏感路径先用 profile 验证。

## 8. 与其他语言对照

| Go | 可以类比 | 不能照搬 |
| --- | --- | --- |
| 普通值 `Order` | C++ 值对象 | Java/Python 对象变量通常不是复制整个对象 |
| `*Order` | C/C++ 结构体指针 | Go 没有指针算术，字段仍用 `.` 访问 |
| slice | 数组视图/动态数组描述符 | 不是 Java List 或 Python list 对象本身 |
| map | `HashMap*` 的使用感觉 | Go map 不是可解引用的裸指针，初始化使用 `make` 或字面量 |
| interface | Java 接口引用 | 实现关系是隐式的；分派信息在 interface value 中，不在普通 struct 内 |
| 零值 | Java 字段默认值 | Go 局部变量也必须先拥有确定值，不存在未初始化读取 |

特别记住：`map[string]int` 可以暂时类比 C 的 `HashMap*`，因此 `*map[string]int` 就像多套了一层 `HashMap**`；这只是理解模型，不是 Go 规范承诺的真实内存布局。

## 9. 常见错误及结果

| 错误认知 | 实际结果 |
| --- | --- |
| 看到 `&` 就认为一定在堆上 | 栈/堆由逃逸分析和优化决定 |
| struct 赋值后完全独立 | slice、map、pointer 字段仍可能共享底层数据 |
| `*Order` 自带类型和方法表 | 普通指针主要保存地址；静态类型由编译器掌握，interface 才携带动态分派信息 |
| interface 的 data 是 nil，所以 interface 等于 nil | 只有动态类型和动态值都为空，interface 才等于 nil |
| `make([]Order, 100)` 只是预留容量 | 它已经创建 100 个零值元素；只预留容量应写 `make([]Order, 0, 100)` |
| 调用 `append` 后原 slice 自动更新 | `append` 返回新的 slice value，必须赋值或返回 |
| 两个 slice 一定完全独立 | 它们可能共享数组；修改元素和 append 都要分析 len/cap |
| map 查到零值就表示 key 存在 | 缺失 key 也返回零值，需要用 `value, ok := m[key]` 区分 |
| map 遍历顺序稳定 | 顺序不保证；稳定输出必须提取并排序 key |
| map 中的 struct 字段可以直接修改 | map 元素不可寻址，应取出、修改后写回，或明确保存 pointer |
| map/slice 像“引用类型”就天然线程安全 | 共享 map、slice header 或底层数组仍需明确同步和所有权 |
| `new(map)` 等于创建空 map | 得到指向 nil map 变量的指针，仍不能写入 |
| `const` 等于只读变量 | Go 常量只能是编译期可表示的常量值 |
| string 下标取得字符 | 下标得到 byte，Unicode 标量通常用 range/rune |
| int 与 int64 可自动混用 | Go 要求显式转换，转换仍不检查业务溢出 |

## 10. 动手验证

1. 分别复制 array、`Order`、`*Order`、slice 和 map，画出变量本身与共享数据。

3. 从同一个数组建立两个 slice，分别在“容量充足”和“容量不足”时 append，预测原数组变化。

## 11. 掌握标准

- 能画出普通值、结构体指针、string、slice、map、interface 与实际数据之间的关系。
- 能区分普通指针的静态方法调用和 interface 的运行时动态分派。
- 知道普通 struct 不携带 vptr，并能解释 interface 中动态类型、动态值和带类型 nil。
- 能区分 `var`、`:=`、结构体字面量、`new`、`make` 和工厂函数。
- 能说明 `&Order{}`、`new(Order)` 和 `NewOrder(...)` 的用途差异。
- 知道创建语法不直接决定栈或堆，实际位置由逃逸分析决定。
- 能解释 array 的值复制，以及 slice/map value 与底层数据的共享关系。
- 能区分 nil/空 slice、len/cap，并预测切片、append、copy 和 Clone 是否共享数组。
- 能正确使用 map 的初始化、`value, ok`、delete、遍历、key 约束和元素更新规则。
- 能为 slice/map 的共享、并发和稳定输出设计明确边界。
- 能区分 byte、rune、字节位置和用户字符。
- 能正确处理零值、nil、具名类型和数值范围。
