# Go：函数与作用域

函数不只是“封装一段代码”。在 Go 中，学函数要真正搞懂四件事：

1. 参数传入函数时复制了什么；
2. 函数能不能修改调用者的数据；
3. 变量在哪个范围内有效；
4. 函数结束时，资源和局部变量怎么处理。

## 1. Go 的参数都是值传递

“值传递”的意思是：调用函数时，Go 会把参数的值复制一份给函数。

先看普通数值：

```go
func changeAmount(amount int) {
	amount = 200
}

amount := 100
changeAmount(amount)
fmt.Println(amount) // 100
```

函数收到的是 `100` 的副本。修改副本，不会改变外面的 `amount`。

### 传结构体：复制整个值

```go
type Order struct {
	Status string
}

func markPaidCopy(order Order) {
	order.Status = "paid"
}

order := Order{Status: "pending"}
markPaidCopy(order)
fmt.Println(order.Status) // pending
```

`markPaidCopy` 修改的是 `Order` 副本，原订单没有变。

### 传指针：复制地址，两边指向同一个对象

```go
func markPaid(order *Order) {
	order.Status = "paid"
}

order := Order{Status: "pending"}
markPaid(&order)
fmt.Println(order.Status) // paid
```

`&order` 表示取得 `order` 的地址。传入函数的仍然是一个副本，但这次复制的是地址：

```text
调用者的 order ──→ 同一个 Order 对象
函数里的指针  ──↗
```

所以，Go 没有“一会儿值传递，一会儿引用传递”。它始终是值传递，只是有时复制普通数据，有时复制地址或内部描述信息。

## 2. slice 和 map 为什么看起来像“引用传递”

slice 参数也会被复制，但 slice 中保存着底层数组的信息。复制后的两个 slice 通常仍然指向同一个底层数组：

```go
func renameFirst(names []string) {
	names[0] = "paid-order"
}

names := []string{"pending-order"}
renameFirst(names)
fmt.Println(names[0]) // paid-order
```

但在函数内对 slice 执行 `append`，不会自动改变调用者持有的 slice 长度。应该返回新 slice：

```go
func addName(names []string, name string) []string {
	return append(names, name)
}

names = addName(names, "new-order")
```

map 参数的副本与调用者共享同一份 map 数据，因此新增、修改和删除元素都能被调用者看见：

```go
func markPaid(statusByID map[string]string, id string) {
	statusByID[id] = "paid"
}
```

| 参数类型 | 函数收到什么 | 函数内的修改是否影响调用者 |
| --- | --- | --- |
| `int`、`bool`、`string`、结构体 | 值的副本 | 直接赋值不影响 |
| `*Order` | 地址的副本 | 通过指针修改对象会影响 |
| `[]Item` | slice 描述信息的副本 | 修改共享元素会影响；新 slice 需要返回 |
| `map[K]V` | map 描述信息的副本 | 修改 map 内容会影响 |
| `interface` | 接口值的副本 | 取决于其中装的是值还是指针 |

## 3. 多返回值：结果和失败一起返回

Go 函数可以返回多个值。后端项目最常见的是“结果 + `error`”：

```go
func CreateOrder(amount int64) (*Order, error) {
	if amount <= 0 {
		return nil, errors.New("amount must be positive")
	}
	return &Order{Status: "pending"}, nil
}

order, err := CreateOrder(100)
if err != nil {
	return err
}
fmt.Println(order.Status)
```

查询 map 时常用“值 + 是否存在”：

```go
status, ok := statusByID["order-1"]
if !ok {
	// 订单不存在
}
```

返回值应明确表达结果。不要通过可变的全局变量偷偷传递函数结果。

## 4. 作用域：变量在哪里有效

变量从声明它的位置开始，只在当前代码块及其内部代码块中有效。

```go
if amount := command.Amount; amount <= 0 {
	return errors.New("invalid amount")
}

// 这里已经不能使用 amount
```

这种写法能把临时变量限制在真正需要它的地方。

### `:=` 可能意外创建同名变量

```go
err := saveOrder()

if needRetry {
	err := retrySave() // 新的内层 err
	fmt.Println(err)
}

return err // 返回的是外层 err
```

内层的 `err` 把外层 `err` 遮住了，这叫“变量遮蔽”。如果目的是修改已有变量，应该使用 `=`：

```go
if needRetry {
	err = retrySave()
}
```

不是所有内层 `err` 都是问题。下面的写法是常见且清晰的，因为 `err` 只用于当前判断：

```go
if err := validate(command); err != nil {
	return err
}
```

## 5. 函数也可以当作数据

函数可以保存在变量中、作为参数传入，也可以从另一个函数返回：

```go
type Discount func(amount int64) int64

func Checkout(amount int64, discount Discount) int64 {
	return discount(amount)
}

tenPercentOff := func(amount int64) int64 {
	return amount * 90 / 100
}

finalAmount := Checkout(1000, tenPercentOff) // 900
```

这种写法常用于回调、中间件、排序规则和可替换策略。

## 6. 闭包：函数记住了外层变量

内层函数使用了外层函数的变量，这个内层函数就是闭包：

```go
func NewCounter() func() int {
	count := 0

	return func() int {
		count++
		return count
	}
}

next := NewCounter()
fmt.Println(next()) // 1
fmt.Println(next()) // 2
```

`NewCounter` 已经结束，但返回的函数仍然需要 `count`，所以 `count` 会继续存在。这也是局部变量可能发生逃逸的场景。

闭包捕获的是变量本身，不是创建闭包时的永久快照。如果多个 goroutine 同时调用上面的计数器，就会并发修改同一个 `count`，需要锁或原子操作保护。

## 7. `defer`：函数结束前执行清理

`defer` 的意思是：先记下这个操作，等当前函数要结束时再执行。

```go
func ReadConfig(path string) ([]byte, error) {
	file, err := os.Open(path)
	if err != nil {
		return nil, err
	}
	defer file.Close()

	return io.ReadAll(file)
}
```

无论 `io.ReadAll` 成功还是返回错误，`ReadConfig` 结束前都会调用 `file.Close()`。

多个 `defer` 按相反顺序执行：

```go
defer fmt.Println("first")
defer fmt.Println("second")

// 输出：second、first
```

`defer` 后面的函数参数在注册 `defer` 时就会求值：

```go
name := "pending"
defer fmt.Println(name)
name = "paid"

// 函数结束时输出 pending
```

不要在大循环里不断累积 `defer`。因为资源要到整个外层函数结束时才会释放，可以把单次处理抽成小函数：

```go
func processFile(path string) error {
	file, err := os.Open(path)
	if err != nil {
		return err
	}
	defer file.Close()

	// 处理一个文件
	return nil
}
```

对写文件、提交事务等操作，`Close`或 `Commit` 本身也可能失败，不能一律忽略它们的错误。

## 8. 局部变量在函数结束后一定消失吗

不一定。如果返回了局部变量的指针，或者返回的闭包仍在使用它，Go 会保证该变量继续有效：

```go
func NewOrder() *Order {
	order := Order{Status: "pending"}
	return &order
}
```

这在 Go 中是安全的。编译器会通过逃逸分析决定如何分配该变量，详见 [运行时与性能](11-运行时与性能.md#逃逸分析先看值要活多久)。

## 9. 项目中怎么选值参数和指针参数

| 情况 | 常见选择 |
| --- | --- |
| 小型、只读、复制后彼此独立的值 | 传值 |
| 函数要修改同一个对象 | 传指针 |
| 对象很大，或明确表示“同一个实体” | 通常传指针 |
| 结构体含锁等不应复制的状态 | 传指针，且避免复制 |
| slice 需要 `append` | 返回新 slice |

不要因为“指针可能更快”就把所有参数改成指针。指针会引入 `nil`、共享修改、逃逸和并发同步问题；是否更快需要用 benchmark 证明。

## 10. 后端项目的函数约定

- 需要超时和取消时，把 `context.Context` 放在第一个参数，不要保存到长期对象里。
- `error` 通常放在最后一个返回值。
- 函数名和返回值表达业务意图，不依赖可变全局状态传递结果。
- 复杂函数少用命名返回值，避免裸 `return` 让返回内容变得隐蔽。
- 闭包和 goroutine 使用外层变量时，确认它的生命周期以及是否并发共享。

## 学完检查

- 能用代码解释“全部按值传递”为什么与“可以修改共享数据”不矛盾。
- 能判断普通值、指针、slice 和 map 参数的修改是否影响调用者。
- 能识别 `:=` 导致的变量遮蔽。
- 能说清闭包为什么能记住外层变量，以及并发使用时的风险。
- 能把 `defer` 放在正确作用域，并知道哪些关闭错误不能忽略。
