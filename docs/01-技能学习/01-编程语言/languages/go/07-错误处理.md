# Go：错误处理

Go 的 error 是普通值。调用方必须明确处理、转换或传播，而不是把失败隐藏在异常控制流中。

## 错误链

```go
task, err := store.Get(ctx, id)
if err != nil {
	return Task{}, fmt.Errorf("load task %s: %w", id, err)
}
```

- `%w` 包装错误并保留原因链。
- `errors.Is` 判断稳定错误类别，`errors.As` 获取具体错误类型。
- sentinel error 适合少量稳定类别；自定义类型适合结构化上下文。
- 错误文本面向排障，程序判断依赖类型或哨兵，不解析字符串。

每层只补充自己知道的上下文，通常在请求或任务边界记录一次，避免同一个错误重复打印多遍。

## 领域错误与协议映射

核心业务返回领域错误，HTTP/RPC 边界集中映射状态码和外部消息。内部日志保留原因链，外部响应不泄露 SQL、路径、令牌和敏感数据。

重试必须根据 `errors.Is/As` 判断可重试类别，并设置退避、次数上限和整体 context 截止时间。

## panic 与 recover

- panic 用于被破坏的程序不变量或无法继续的初始化，不处理普通业务失败。
- recover 只在同一 goroutine 的 defer 中有效。
- 请求或任务最外层可恢复单次 panic、记录堆栈并转为失败。
- recover 后不能盲目假设共享状态仍然一致。

## 易错点

- 忽略 error，或用 `_` 丢掉关闭/写入错误。
- 包装时使用 `%v`，造成 `errors.Is/As` 无法追踪原错误。
- 每一层都记录日志，产生噪声和重复告警。
- 用 panic 代替输入校验和普通分支。

## 验收

- 能设计可判断、带上下文且不重复记录的错误链。
- 能建立领域错误到 HTTP/RPC 的单一转换边界。
- 能说明 panic 恢复的位置、作用域和无法保证的事项。
