# Go：用订单集合看懂容器与迭代

Go 的核心集合只有 array、slice 和 map。真正需要掌握的不是 API 数量，而是变量保存什么、赋值复制什么、底层数据是否共享，以及扩容和并发会带来什么结果。

## 1. 一个内存订单簿

```go
type OrderBook struct {
	byID map[string]*Order
}

func NewOrderBook() *OrderBook {
	return &OrderBook{
		byID: make(map[string]*Order),
	}
}

func (b *OrderBook) Add(order *Order) error {
	if _, exists := b.byID[order.ID()]; exists {
		return ErrDuplicateOrder
	}
	b.byID[order.ID()] = order
	return nil
}
```

这段代码包含三个层次：`OrderBook` 拥有 map 描述值，map 指向运行时键值数据，键值中的 `*Order` 又指向订单对象。复制其中任一层，都要判断最终是否仍共享对象。

## 2. array：长度属于类型

```go
var recent [3]string
recent[0] = "order-1"
```

`[3]string` 和 `[4]string` 是不同类型。array 赋值复制全部元素：

```go
first := [2]int{100, 200}
second := first
second[0] = 999

fmt.Println(first[0]) // 100
```

array 适合固定大小数据和作为底层存储；业务集合通常使用 slice。

## 3. slice：描述值指向底层数组

```go
amounts := []int64{100, 200}
```

可以简化理解为：

```text
slice 变量 amounts               底层数组
┌──────────────────┐            ┌─────┬─────┬─────┐
│ 数组地址 ────────────────────▶ │ 100 │ 200 │     │
│ len: 2           │            └─────┴─────┴─────┘
│ cap: 3           │
└──────────────────┘
```

复制 slice 只复制地址、长度和容量，通常共享底层数组：

```go
copyOfHeader := amounts
copyOfHeader[0] = 999

fmt.Println(amounts[0]) // 999
```

如果需要独立元素，显式复制：

```go
independent := append([]int64(nil), amounts...)
// 或者：independent := slices.Clone(amounts)
```

## 4. `append` 为什么必须接收返回值

```go
amounts = append(amounts, 300)
```

运行时先检查容量：

```text
容量足够
→ 在原底层数组写入
→ 返回长度增加后的 slice 描述值

容量不足
→ 分配更大数组
→ 复制旧元素
→ 写入新元素
→ 返回指向新数组的 slice 描述值
```

无论是否扩容，调用者持有的旧 slice 长度都不会自动改变，所以必须接住返回值：

```go
func addAmount(amounts []int64, amount int64) []int64 {
	return append(amounts, amount)
}

amounts = addAmount(amounts, 300)
```

不要通过“当前容量刚好够”来依赖函数内修改可见，这会让代码在数据规模变化后失效。

## 5. subslice 会保留底层数组

```go
payload := make([]byte, 100<<20)
header := payload[:100]
```

只要 `header` 仍指向这个底层数组，整个大数组就可能继续存活。长期只保留少量数据时复制需要的区域：

```go
header := append([]byte(nil), payload[:100]...)
```

这不是“GC 失效”，而是对象仍然可达。

## 6. map：初始化、查询和共享

```go
orders := make(map[string]*Order)
orders["order-1"] = order
```

map 变量是描述值。复制 map 不复制键值数据：

```go
alias := orders
delete(alias, "order-1")

fmt.Println(len(orders)) // 0
```

查询使用 `value, ok` 区分“不存在”和“存在但值是零值”：

```go
order, ok := orders[id]
if !ok {
	return nil, ErrOrderNotFound
}
```

nil map 和空 map 都可读取、求长度和遍历，但只有初始化后的 map 可以写入：

```go
var nilMap map[string]int
emptyMap := make(map[string]int)

fmt.Println(len(nilMap), len(emptyMap)) // 0 0
// nilMap["a"] = 1                     // panic
emptyMap["a"] = 1                      // 正常
```

## 7. map 顺序和并发边界

map 遍历顺序不构成契约。需要稳定输出时排序 key：

```go
ids := make([]string, 0, len(orders))
for id := range orders {
	ids = append(ids, id)
}
slices.Sort(ids)
```

普通 map 不能在没有同步的情况下并发读写。选择方式：

- 单个 goroutine 独占 map，通过 channel 接收命令；
- 使用 `sync.Mutex` 保护一组操作；
- 极少数适用模式使用 `sync.Map`；
- 数据库或外部存储承担共享状态。

“查询后写入”是两个步骤，仅给单次访问加锁仍可能破坏业务不变量。

## 8. range：拿到的是值的复制

```go
orders := []Order{{AmountCents: 100}}
for _, order := range orders {
	order.AmountCents = 200
}
```

循环变量 `order` 是元素副本，原 slice 不变。修改原元素使用索引：

```go
for i := range orders {
	orders[i].AmountCents = 200
}
```

遍历 map 时得到的 key/value 也不是可取地址的稳定容器槽位；需要修改结构体值时，取出、修改、再写回，或者让 map 保存指针。

## 9. set、队列和排序

Go 通常用基础容器组合：

```go
seen := map[string]struct{}{}
seen[id] = struct{}{}

queue := []Job{}
queue = append(queue, job) // 入队
job, queue = queue[0], queue[1:] // 简化出队
```

长期高频队列不能无限保留已出队元素引用，应使用环形缓冲或定期清理。排序通常原地修改 slice，API 必须说明是否改变调用方数据。

泛型可以抽取通用集合算法，但简单循环通常更符合 Go 的可读性和调试体验。

## 10. 与其他语言对照

| Go | 容易套用的旧认知 | 必须修正 |
| --- | --- | --- |
| array | C++/Java 数组 | Go array 赋值复制全部元素，长度属于类型 |
| slice | Java List/Python list | slice 是视图描述值，可能共享数组，append 可能换数组 |
| map | Java HashMap/JS Map | map 变量复制后共享，顺序不稳定，并发读写需同步 |
| range value | Python/Java 对象变量 | Go 取得元素值的复制，结构体修改可能只改副本 |

## 11. 动手验证

1. 对同一底层数组创建两个 slice，修改元素并画出共享关系。
2. 分别在容量足够和不足时 append，打印地址、长度和容量。
3. 保存 100 MB slice 的 100 字节 subslice，用 heap profile 观察保留。
4. 对普通 map 启动并发读写，使用 `go test -race` 观察报告。
5. 实现一个带锁的 `OrderBook`，保证“检查不存在并写入”整体原子。

## 12. 掌握标准

- 能画出 array、slice 描述值、底层数组、map 和对象之间的关系。
- 能解释 append 的两条运行路径以及为何必须接收返回值。
- 能识别 subslice 保留大数组、range 修改副本和 map 共享问题。
- 能为 map 定义清晰的初始化、顺序、并发和所有权边界。
- 性能判断使用 benchmark/pprof，不凭容器表面语法猜测。
