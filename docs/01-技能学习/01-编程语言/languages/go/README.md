# Go：面向资深多语言开发者的速成路线

这套资料默认你已经熟悉 Java、Node.js、Python 和 C++。目标不是再学一遍“什么是变量、函数和面向对象”，而是建立 Go 的语义模型，并能在生产环境解释代码为什么这样运行。

贯穿全套资料的是一个订单服务：创建订单、调用支付/库存接口、保存数据、并发处理任务、测试并上线。每章都从同一业务继续向下挖，避免语法点互不相关。

> 示例基线：Go 1.27。先运行[订单示例](../../examples/README.md#可运行订单示例)，再边改代码边阅读。

> 完成语言学习后，使用[Go 分类面试题与答案](../../面试题/go/README.md)检查表达能力。面试题不能替代实际编码、race、profile 和故障分析。

## 1. 你最终要具备的能力

学完后，不以“记住多少语法”为标准，而以能否回答这些问题为标准：

- 一次赋值复制了实际数据，还是只复制了指向数据的描述值？
- 一个方法为什么会改变原值，另一个方法为什么只改了副本？
- interface 调用如何找到具体实现，为什么带 nil 指针的 interface 不等于 nil？
- `append`、map 写入、interface 装箱和闭包分别可能发生什么分配？
- 一个请求会创建多少 goroutine，在哪里阻塞，是否占用 OS 线程？
- goroutine 谁启动、谁停止、谁等待，错误和 panic 到哪里？
- HTTP Body、Rows、Tx、文件、timer 和连接分别由谁关闭？
- package、module、`internal`、`cmd` 各解决什么工程问题？
- 性能或内存异常时，应选择 benchmark、race、pprof 还是 trace？

如果只能写出能跑的代码，却回答不了这些问题，还不算掌握 Go。

## 2. 贯穿案例如何逐章生长

```text
创建 Order 值
→ 用方法维护订单状态
→ 用 interface 隔离支付实现
→ 用 error 表达失败
→ 通过 HTTP/JSON/数据库跨边界
→ 用 goroutine + channel 处理任务
→ 用 context 控制取消与停机
→ 用 test/race/fuzz/profile 提供证据
→ 按 package/module 组织成可交付服务
```

先建立一条完整主线，再回头研究语言细节。不要把每个关键字当成孤立知识背诵。

## 4. 从已有语言迁移时要换掉什么习惯

| 你已有的直觉 | 在 Go 中改成 |
| --- | --- |
| Java：class、继承、异常、DI 容器 | struct + method、组合、interface、显式 error、main 显式组装 |
| Node.js：单事件循环、Promise/async | 多 goroutine 可并行；阻塞写法配合 runtime；共享数据仍需同步 |
| Python：动态协议、异常、对象引用 | 编译期接口、显式错误、所有参数都按值传递 |
| C++：`. / ->`、RAII、模板、手动生命周期 | 指针和值都用点号；`defer` 关闭资源；泛型 + interface；GC 管内存但不管连接 |

Go 的难点通常不在语法，而在“语法看起来简单，却隐含共享、分配、调度和生命周期”。每读到一个例子，都问：值在哪里、谁持有、是否共享、何时停止、出错给谁。

## 5. 七天专家速成安排

| 天 | 阅读与编码 | 当天证据 |
| ---: | --- | --- |
| 1 | 01—03：重写订单模型和状态转换 | 能画内存关系，并解释每次复制 |
| 2 | 04—07：函数、方法、interface、容器、错误 | 完成支付抽象和错误链测试 |
| 3 | 08—09：逃逸、资源、HTTP、JSON、数据库 | 所有 IO 有大小、超时、关闭和取消 |
| 4 | 10：worker pool、channel、context、停机 | 压测有界队列，证明 worker 可退出 |
| 5 | 11：调度、栈、GC、内存模型、profile | 用 profile 解释一次真实热点或保留 |
| 6 | 12：单元、集成、race、fuzz、benchmark | 保存完整命令和结果，修复一个注入故障 |
| 7 | 13—15：工程边界、命令、交付和生产陷阱 | 将案例整理成 API + worker，完成构建与停机演练 |

七天适合建立高密度认知，不代表七天获得生产经验。之后应反复做容量压测、故障注入、profile 分析和代码审查，把判断变成条件反射。

## 6. 每章的正确学习动作

1. 先运行示例，不预判结果；
2. 用自己的话画出值、实际数据和所有者；
3. 修改一个条件，预测编译结果和运行结果；
4. 用测试、race、benchmark 或 profile 验证；
5. 与 Java/Node.js/Python/C++ 对照，只记录语义差异；
6. 把错误写法、生产后果和修复方式连成一条因果链；
7. 最后完成章节“掌握标准”，不能回答就回到代码实验。

只看文字会产生“好像懂了”的错觉。Go 的值语义、interface nil、slice 扩容和并发生命周期必须用小实验确认。

## 7. 最终验收项目

实现一个有界订单任务服务：

- HTTP API 接收、校验并查询订单；
- Worker 从有限队列消费任务，调用支付和库存接口；
- Repository 同时有内存版和真实数据库版；
- 错误链能映射为稳定 HTTP/任务结果；
- 每个外部调用传播 context，并有总 deadline；
- SIGTERM 后停止接收、取消、等待并在期限内关闭；
- 单元、HTTP、数据库、取消和停机测试齐全；
- `go test -race ./...` 没有已执行路径上的竞争；
- benchmark 和 pprof 能解释一处 CPU/内存优化；
- README 能说明 package 依赖、容量参数、运行和故障排查方式。

验收时不要只演示成功请求。还要演示无效输入、下游超时、队列满、数据库失败、重复任务和进程关闭。

## 8. 权威资料怎么配合使用

- [A Tour of Go](https://go.dev/tour/)：快速动手看语法和语言特性；
- [Effective Go](https://go.dev/doc/effective_go)：理解惯用写法，但注意它不是完整现代 Go 指南；
- [Go Language Specification](https://go.dev/ref/spec)：对语义有争议时查最终定义；
- [Go Memory Model](https://go.dev/ref/mem)：判断并发可见性和同步关系；
- [Go Documentation](https://go.dev/doc/)：module、诊断、fuzz、安全等专题入口；
- [Standard library](https://pkg.go.dev/std)：以接口和示例理解标准库契约。

Tour 适合入门，Specification 适合裁决精确语义，标准库文档适合写项目时查询。这套仓库资料负责把它们连接成订单后端的完整学习路径。
