# Go：编译、运行与调试命令

Go 把编译、依赖、测试、格式化和诊断统一在 `go` 命令下。下面的命令默认从 module 根目录执行；先理解 package pattern，再记具体参数。

## 1. 检查环境和 package pattern

```bash
go version
go env GOROOT GOPATH GOMOD GOCACHE GOPROXY GOOS GOARCH
go help
go help test
```

常用路径：

| 写法 | 含义 |
| --- | --- |
| `.` | 当前 package |
| `./...` | 当前目录及子目录中的所有 package |
| `./cmd/api` | 指定入口 package |
| `example.com/app/internal/order` | 完整 import path |

## 2. 创建、运行和编译

```bash
go mod init example.com/order-service
go run .
go run ./cmd/api
go build ./...
go build -o bin/order-api ./cmd/api
./bin/order-api
```

`go run` 会临时编译后运行，适合开发；`go build` 生成或验证构建产物。只执行 `go build ./...` 时，普通 library package 只做编译检查，main package 的产物不会统一留在当前目录。

查看实际参与构建的 package：

```bash
go list ./...
go list -deps ./cmd/api
```

## 3. module 和依赖

```bash
go mod tidy
go mod download
go mod verify
go list -m all
go mod graph
go mod why -m github.com/google/uuid
```

添加或调整项目依赖：

```bash
go get github.com/google/uuid@latest
go get github.com/google/uuid@v1.6.0
```

安装命令行工具：

```bash
go install github.com/go-delve/delve/cmd/dlv@latest
```

区别是：`go get` 修改当前 module 的依赖；带版本的 `go install` 安装可执行工具，通常不修改当前项目的 `go.mod`。

## 4. 测试、覆盖率和 benchmark

```bash
go test ./...
go test -v ./...
go test -count=1 ./...
go test -run TestNewOrder ./internal/order
go test -run 'TestOrder.*' ./...
```

覆盖率：

```bash
go test -cover ./...
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

benchmark：

```bash
go test -bench=. -benchmem ./...
go test -bench=BenchmarkCheckout -benchmem ./internal/order
```

`go test` 会缓存成功结果；需要真正重跑时使用 `-count=1`，不要通过随意修改源码绕过缓存。

## 5. 格式、静态检查和生成代码

```bash
go fmt ./...
gofmt -w .
gofmt -d .
go vet ./...
go generate ./...
```

`go generate` 只执行源码中的 `//go:generate` 指令，`go build` 和 `go test` 不会自动执行它。生成代码应标记来源、固定生成器版本，并在 CI 中检查是否需要重新生成。

## 6. 使用 Delve 调试

Delve 不是 Go 标准命令，安装后先检查：

```bash
dlv version
```

调试入口：

```bash
dlv debug ./cmd/api -- --config config/dev.yaml
```

调试测试：

```bash
dlv test ./internal/order -- -test.run TestNewOrder
```

常用 Delve 命令：

```text
break main.main
break order/service.go:42
continue
next
step
print order
locals
args
goroutines
goroutine 12 bt
stack
quit
```

IDE 远程调试通常使用：

```bash
dlv debug ./cmd/api --headless --listen=127.0.0.1:2345 --api-version=2
```

调试端口只绑定本机或受控网络，不暴露到公网。

## 7. race、fuzz 和逃逸分析

检测数据竞争：

```bash
go test -race ./...
go run -race ./cmd/api
go build -race -o bin/order-api-race ./cmd/api
```

运行 fuzz：

```bash
go test -fuzz=FuzzNewOrder ./internal/order
```

查看逃逸和内联决定：

```bash
go build -gcflags="all=-m=2" ./...
```

`-race` 和详细编译诊断会增加成本，用于验证和排障，不作为普通生产构建参数。

## 8. pprof 和 trace

对 benchmark 生成 profile：

```bash
go test -bench=. -cpuprofile=cpu.out ./internal/order
go test -bench=. -memprofile=mem.out ./internal/order
go tool pprof cpu.out
go tool pprof mem.out
```

生成执行 trace：

```bash
go test -trace=trace.out ./internal/order
go tool trace trace.out
```

服务通过 `net/http/pprof` 暴露诊断端点时，可以抓取：

```bash
go tool pprof 'http://127.0.0.1:6060/debug/pprof/profile?seconds=30'
```

pprof 端点包含敏感运行信息，必须只放在受控管理网络并进行访问限制。

## 9. 跨平台构建

```bash
GOOS=linux GOARCH=amd64 go build -o bin/order-api-linux-amd64 ./cmd/api
GOOS=linux GOARCH=arm64 go build -o bin/order-api-linux-arm64 ./cmd/api
```

纯 Go 项目通常可以直接交叉编译；使用 cgo 时还需要目标平台 C 工具链和库，不能只改 `GOOS/GOARCH`。

查看产物信息：

```bash
go version -m bin/order-api
```

## 10. cache 和 workspace

清除测试缓存：

```bash
go clean -testcache
```

查看构建缓存位置：

```bash
go env GOCACHE
```

不要把 `go clean -modcache` 当日常修复命令，它会删除全部 module 下载缓存，之后必须重新下载依赖。

多 module 本地开发：

```bash
go work init
go work use ./service-a ./service-b
go work sync
```

单 module 项目不需要 `go.work`。

## 11. 推荐的日常命令顺序

```bash
go mod tidy
go fmt ./...
go vet ./...
go test ./...
go test -race ./...
go build ./...
```

提交前确认 `go mod tidy` 和代码生成没有产生未提交变化；性能问题再按证据使用 benchmark、pprof 和 trace。

## 12. 掌握标准

- 能从零创建 module，运行和构建指定 main package。
- 能解释 `.`、`./...`、目录和 import path 的区别。
- 能使用 `go get`、`go install`、`go mod tidy/why/graph` 管理依赖。
- 能运行普通测试、指定测试、race、fuzz、覆盖率和 benchmark。
- 能使用 Delve 调试 goroutine、变量和调用栈。
- 能使用逃逸分析、pprof 和 trace 选择证据。
- 能交叉构建并判断 cgo 带来的限制。
