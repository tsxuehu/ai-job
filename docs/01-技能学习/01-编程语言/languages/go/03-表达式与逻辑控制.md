# Go：用订单状态流转学习表达式与逻辑控制

本章围绕“创建订单、校验金额、支付状态流转”讲表达式、`if`、`switch`、`for` 和 `range`。重点不是记关键字，而是把状态和失败路径写得完整、平直、可检查。

## 1. 从一个业务规则开始

```go
func CanPay(order Order) bool {
	return order.Status == StatusPending && order.AmountCents > 0
}
```

表达式先计算，再产生值：

```text
order.Status == StatusPending   → bool
order.AmountCents > 0           → bool
左边 && 右边                    → bool
```

`&&` 和 `||` 短路求值。左侧已经决定结果时，右侧不会执行：

```go
if order != nil && order.Status == StatusPending {
	// order 为 nil 时，不会继续访问字段。
}
```

短路适合保护访问，也要避免把有副作用的关键操作藏进右侧表达式。

## 2. Go 表达式的几个边界

- 运算两边通常要求类型兼容，不做 JavaScript 式宽松转换。
- `++`、`--` 是语句，不能嵌入另一个表达式。
- Go 没有三元表达式；重要分支写成 `if`。
- 多值函数调用、map 查询、类型断言和 channel 接收可产生多个结果。
- 多重赋值先计算全部右侧，再写入左侧。

```go
left, right = right, left

amount, err := strconv.ParseInt(raw, 10, 64)

order, ok := orders[id]
```

`value, ok` 将“值是零值”和“值不存在”分开：

```go
amount, ok := discounts[customerID]
if !ok {
	return 0, ErrDiscountNotFound
}
```

## 3. `if`：把校验和错误放在一起

```go
func ParseAmount(raw string) (int64, error) {
	amount, err := strconv.ParseInt(raw, 10, 64)
	if err != nil {
		return 0, fmt.Errorf("parse amount %q: %w", raw, err)
	}
	if amount <= 0 {
		return 0, ErrInvalidAmount
	}
	return amount, nil
}
```

Go 倾向早返回：先处理失败，成功主路径留在最左侧。初始化语句可以把临时变量限制在分支内：

```go
if amount, err := ParseAmount(raw); err != nil {
	return err
} else {
	fmt.Println(amount)
}
```

不过如果后续仍要使用 `amount`，就应在 `if` 前声明，不要为了缩小作用域制造额外嵌套。

## 4. `switch`：集中表达有限状态

```go
func NextAction(status Status) (string, error) {
	switch status {
	case StatusPending:
		return "pay", nil
	case StatusPaid:
		return "ship", nil
	case StatusCancelled:
		return "stop", nil
	default:
		return "", fmt.Errorf("unknown order status %q", status)
	}
}
```

Go 的 `switch` 默认不会贯穿到下一个 case，不需要手写 `break`。`fallthrough` 很少适合业务状态，因为它不会重新判断下一个 case 条件。

无表达式 switch 适合互斥的范围判断：

```go
switch {
case amountCents <= 0:
	return ErrInvalidAmount
case amountCents > maxOrderAmount:
	return ErrAmountTooLarge
default:
	return nil
}
```

Go 编译器通常不会替你证明枚举分支穷尽；新增状态后，测试必须覆盖决策函数。

## 5. `for`：一种关键字覆盖所有循环

```go
for i := 0; i < 3; i++ {}

for retries < maxRetries {}

for {}

for id, order := range orders {}
```

后端代码最常见的是集合遍历和带取消的长期循环：

```go
for {
	select {
	case <-ctx.Done():
		return ctx.Err()
	case order, ok := <-orders:
		if !ok {
			return nil
		}
		if err := handle(ctx, order); err != nil {
			return err
		}
	}
}
```

## 6. `range` 返回的通常是元素副本

```go
orders := []Order{{AmountCents: 100}}

for _, order := range orders {
	order.AmountCents = 200
}

fmt.Println(orders[0].AmountCents) // 100
```

`order` 是元素值的复制。要修改 slice 中的结构体元素，使用索引：

```go
for i := range orders {
	orders[i].AmountCents = 200
}
```

如果 slice 保存的是指针，复制的是地址，仍然会访问同一个对象：

```go
for _, order := range []*Order{orderPtr} {
	order.AmountCents = 200
}
```

不要假设 map 遍历顺序稳定；需要稳定响应或测试快照时，先收集并排序 key。

## 7. `break`、`continue`、标签和 `return`

- `return` 结束函数，最适合错误早返回。
- `continue` 跳过本轮循环。
- `break` 结束当前 `for`、`switch` 或 `select`。
- 标签可以跳出外层循环，但业务代码应优先拆小函数。
- `goto` 存在，但普通业务流程几乎不需要。

控制转移不是为了减少代码行数，而是让失败路径、循环边界和退出条件一眼可见。

## 8. 运行时实际做什么

```text
if/switch       → 计算表达式并选择一条控制路径
for             → 反复判断条件和执行循环体
range slice     → 读取长度并逐项复制元素值
range map       → 通过运行时迭代 map，顺序不构成契约
select          → 从当前可进行的通信分支中选择
```

一行语法背后可能包含 hash 查询、元素复制、channel 阻塞或调度；性能和并发判断不能只看代码行数。

## 9. 与其他语言对照

| 习惯 | Go 中的差异 |
| --- | --- |
| Java/C++ `while` | 统一使用 `for condition` |
| Java/C++ switch | 默认不贯穿，不需要 `break` |
| JavaScript/Python 真值判断 | 条件必须是 bool，不把字符串、数字自动当真假 |
| JavaScript 三元表达式 | Go 没有，使用 `if` |
| Python 遍历对象引用 | Go `range` 变量取得元素值的复制 |
| Java enum 穷尽检查 | Go 具名常量通常需要 default 和测试兜底 |

## 10. 动手验证

1. 给订单增加 `refunded` 状态，观察遗漏 switch 分支时测试是否能发现。
2. 分别遍历 `[]Order` 和 `[]*Order` 修改金额，解释结果差异。
3. 遍历同一个 map 多次，验证顺序不能依赖。
4. 写一个监听 context 的消费循环，并测试取消后能及时退出。

## 11. 掌握标准

- 能使用短路、多值结果、`value, ok` 和早返回表达失败。
- 能用 switch 集中管理有限状态并通过测试防止遗漏。
- 能说明 range 复制了什么，以及如何修改原始元素。
- 长期循环具有取消、channel 关闭和错误退出路径。
- 能从语法继续推导 hash 查询、复制、阻塞等运行时行为。
