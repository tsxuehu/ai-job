# Go：从一个可运行程序认识基础语法

目标：从一个可运行的订单程序出发，掌握 module、package、import、声明、函数和工具链，并理解源码如何变成进程。

## 1. 先运行订单程序

新建空目录并执行：

```bash
go mod init example.com/orderdemo
```

创建 `main.go`：

```go
package main

import "fmt"

type Order struct {
	ID          string
	AmountCents int64
}

func main() {
	order := Order{
		ID:          "order-1",
		AmountCents: 100,
	}

	fmt.Printf("order=%s amount=%d\n", order.ID, order.AmountCents)
}
```

运行：

```bash
go run .
```

输出：

```text
order=order-1 amount=100
```

这段程序已经包含 Go 的基本骨架：文件属于 package，import 声明依赖，type 定义数据，func 定义行为，main 是进程入口。

## 2. package、文件和程序入口

```go
package main
```

同一目录中参与同一次普通构建的 `.go` 文件通常属于同一个 package。package 是 Go 的编译、导入和可见性边界，不是 Java class，也不是 Node.js 单文件模块。

可执行程序需要：

```go
package main

func main() {}
```

普通业务 package 不写 `main`，而是导出类型和函数供其他 package 调用。

## 3. import 表达编译期依赖

```go
import (
	"context"
	"fmt"
	"net/http"
)
```

import 使用 package 路径，不使用文件相对路径。未使用 import 会编译失败；依赖循环也会编译失败。这迫使 package 依赖方向保持清晰。

不要用空白导入隐藏普通依赖：

```go
import _ "database/driver"
```

空白导入只适合确实依赖 package 初始化副作用的少量场景，例如注册数据库驱动。

## 4. 完整案例：创建并导入自己的 package

先记住四个不同的名字：

| 名称 | 写在哪里 | 示例 | 作用 |
| --- | --- | --- | --- |
| module 路径 | `go.mod` | `example.com/orderdemo` | 标识一组共同做版本管理的 package |
| package 目录 | 文件系统 | `internal/order` | 决定 import 路径的后半部分 |
| package 名 | `.go` 文件首行 | `package order` | 调用代码时默认使用的限定名 |
| import 路径 | `import` | `example.com/orderdemo/internal/order` | 唯一定位要依赖的 package |

它们的关系是：

```text
module 路径 + package 相对目录 = import 路径

example.com/orderdemo + internal/order
= example.com/orderdemo/internal/order
```

### 4.1 创建目录和 module

```text
orderdemo/
├── go.mod
├── cmd/
│   └── api/
│       └── main.go
└── internal/
    └── order/
        └── order.go
```

在 `orderdemo` 根目录执行：

```bash
go mod init example.com/orderdemo
```

得到：

```go
module example.com/orderdemo

go 1.27
```

`module` 后面的内容是模块路径。它不一定是真实网站，但准备公开的 module 通常使用代码仓库路径，避免与其他 module 冲突。

### 4.2 编写业务 package

`internal/order/order.go`：

```go
package order

type Order struct {
	ID string
}

func New(id string) Order {
	return Order{ID: id}
}
```

这个目录编译成一个 package。`Order` 和 `New` 首字母大写，所以其他 package 可以使用；`order` 是默认调用名。

### 4.3 在 main package 中导入

`cmd/api/main.go`：

```go
package main

import (
	"fmt"

	"example.com/orderdemo/internal/order"
)

func main() {
	o := order.New("order-1")
	fmt.Println(o.ID)
}
```

运行：

```bash
go run ./cmd/api
```

这里要看清两个名字：

```go
import "example.com/orderdemo/internal/order" // 使用完整 import 路径定位

order.New("order-1") // 使用 package 声明的名字调用
```

Go 导入的是 package，不是某个 `.go` 文件，也不能写 `../../internal/order` 这样的相对文件路径。

### 4.4 package 别名只改变当前文件中的调用名

发生名称冲突时可以起别名：

```go
import orderdomain "example.com/orderdemo/internal/order"

func main() {
	o := orderdomain.New("order-1")
	_ = o
}
```

`orderdomain` 只在当前文件有效，没有修改 package 名或 import 路径。普通情况下使用原包名即可；不要为了“看起来分层”给所有 import 起别名。

### 4.5 使用外部 module 中的 package

添加外部依赖：

```bash
go get github.com/google/uuid@latest
```

工具链会把依赖 module 记录进 `go.mod`，并把内容校验信息写入 `go.sum`。代码仍然导入这个 module 中的具体 package：

```go
import "github.com/google/uuid"

func newOrderID() string {
	return uuid.NewString()
}
```

因此，“导入 module”不是准确说法：

```text
go get / go.mod 管理 module 依赖和版本
import 在源码中导入 module 里的 package
```

一个 module 可以包含很多 package，代码只 import 实际使用的那些 package。

## 5. 声明：`var`、`:=`、`const` 和 `type`

```go
var retries int                 // 声明，使用零值 0
var host = "localhost"          // 编译器推断 string
timeout := 500 * time.Millisecond // 只能在函数内部
const maxRetries = 3
type OrderID string
```

选择规则：

| 写法 | 适用位置 | 重点 |
| --- | --- | --- |
| `var name T` | package 或函数 | 需要零值或显式类型 |
| `var name = value` | package 或函数 | 声明时初始化 |
| `name := value` | 仅函数内部 | 简短局部声明 |
| `const` | package 或函数 | 编译期常量，不能是运行时结果 |
| `type` | package 或函数 | 定义具名类型或别名 |

`:=` 不是赋值符号的简写，它至少要声明一个当前作用域中的新变量。错误处理中的变量遮蔽会在后续章节专门解释。

## 6. 代码块、分号和格式

Go 使用花括号形成代码块，但通常不手写分号。词法规则会自动插入分号，因此左花括号必须跟在声明或控制语句同一行：

```go
if amountCents > 0 {
	fmt.Println("valid")
}
```

不要争论空格和换行风格，直接运行：

```bash
gofmt -w .
```

`gofmt` 是语言生态的一部分，它让团队把评审注意力放在语义而不是排版上。

## 7. 名称和导出

Go 使用首字母大小写表达 package 可见性：

```go
type Order struct {       // 其他 package 可引用 Order
	ID string             // 其他 package 可访问 ID
	status string         // 只能在当前 package 访问
}
```

导出 API 的注释以名称开头，说明契约而不是重复类型：

```go
// NewOrder validates input and creates a pending order.
func NewOrder(id string, amountCents int64) (*Order, error) {
	// ...
}
```

## 8. 从源码到运行进程

```text
.go 源文件
→ 编译 package
→ 链接依赖和 Go runtime
→ 生成本地可执行文件
→ 操作系统启动进程
→ runtime 初始化调度器、GC 等能力
→ 调用 main.main
```

`go run .` 会临时完成构建并执行；生产构建通常使用：

```bash
go build -o order-api ./cmd/api
```

语言语法只规定代码含义，编译、链接、调度和内存管理属于工具链与运行时行为。

## 9. 与你熟悉的语言对照

| Go | Java | Node.js/TypeScript | Python | C++ |
| --- | --- | --- | --- | --- |
| package | package/module | package + ESM | module/package | namespace + target |
| `main.main` | `static main` | 启动模块 | `__main__` | `main` |
| 首字母大写导出 | `public` | `export` | 约定/`__all__` | 访问控制/头文件 |
| `gofmt` 统一格式 | formatter 另配 | formatter 另配 | formatter 另配 | formatter 另配 |
| 禁止未使用 import | 通常警告或工具检查 | 工具检查 | 工具检查 | 通常警告 |

## 10. 动手验证

1. 运行第 4 节的完整案例，再添加 `internal/payment` package 并从 `cmd/api` 导入。
2. 把 `ID` 改成小写，观察另一个 package 的编译错误。
3. 把目录保持为 `internal/order`，将声明改为 `package ordermodel`，观察 import 路径和调用名分别是否变化。
4. 使用 import 别名解决两个同名 package 的冲突。
5. 加入未使用变量和 import，记录编译器信息。
6. 分别运行 `go run ./cmd/api`、`go build ./...`、`go test ./...` 和 `go vet ./...`。

## 11. 掌握标准

- 能从零创建 module 并运行最小程序。
- 能区分 module 路径、package 目录、package 名和 import 路径。
- 能根据 `go.mod` 和目录写出本地 package 的完整 import 路径。
- 知道 `go get` 管理 module 依赖，源码 `import` 使用其中的 package。
- 能解释 package、import、main、声明、别名和导出规则。
- 知道 `:=` 是声明，`=` 是赋值。
- 能说明 Go 源码如何经过编译、链接和 runtime 初始化变成进程。
- 从第一天开始使用 `gofmt`、`go test` 和 `go vet`。
