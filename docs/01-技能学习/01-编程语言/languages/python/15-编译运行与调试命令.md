# Python：运行、检查与调试命令

Python 项目通常由解释器直接运行源码。解释器会按需生成字节码缓存，但这不等于生成独立机器码程序；工程重点是固定解释器和依赖环境，使用 module 入口运行，并把测试、类型检查和诊断命令标准化。

## 1. 检查解释器和环境

```bash
python --version
python -c 'import sys; print(sys.executable); print(sys.version)'
python -m pip --version
```

使用 `python -m pip` 可以确认 pip 属于当前解释器，避免 `pip` 和 `python` 指向不同环境。

查看 import 路径：

```bash
python -c 'import sys; print(*sys.path, sep="\n")'
```

## 2. 创建和使用虚拟环境

```bash
python -m venv .venv
source .venv/bin/activate          # macOS/Linux
python -m pip install --upgrade pip
python -m pip install -e '.[dev]'
```

Windows PowerShell 激活方式通常是：

```powershell
.venv\Scripts\Activate.ps1
```

退出环境：

```bash
deactivate
```

`.venv` 不提交仓库。依赖、Python 版本和构建配置应记录在 `pyproject.toml`、锁文件或团队认可的环境管理方案中。

## 3. 运行脚本和 module

直接运行脚本：

```bash
python scripts/import_orders.py
```

运行 package 中的 module：

```bash
python -m order_service
python -m order_service.worker
```

企业项目优先使用 `python -m package.module` 或安装后的 console script。它能按 package 规则处理 import，减少“从哪个工作目录启动”造成的差异。

执行一小段代码：

```bash
python -c 'from order_service import __version__; print(__version__)'
```

交互模式：

```bash
python
```

## 4. 语法检查和字节码编译

检查单个文件语法并生成 `.pyc`：

```bash
python -m py_compile src/order_service/service.py
```

递归编译：

```bash
python -m compileall -q src
```

这能提前发现语法错误，但不能证明 import、类型或业务行为正确。`.pyc` 是解释器字节码缓存，不是脱离 Python 运行时的独立可执行文件。

## 5. 运行测试

标准库 unittest：

```bash
python -m unittest
python -m unittest discover -s tests
python -m unittest tests.test_order.OrderTest.test_checkout
```

项目使用 pytest 时：

```bash
python -m pytest
python -m pytest -q
python -m pytest tests/test_order.py
python -m pytest tests/test_order.py::test_checkout
python -m pytest -k 'checkout and not slow'
```

覆盖率通常由项目安装的 pytest-cov/coverage 工具提供：

```bash
python -m pytest --cov=order_service --cov-report=term-missing
```

优先使用 `python -m pytest`，确保测试运行器来自当前虚拟环境。

## 6. 格式、lint 和类型检查

具体工具由项目决定，常见命令是：

```bash
ruff format --check .
ruff check .
mypy src
pyright
```

自动修复前先看差异：

```bash
ruff format .
ruff check --fix .
```

这些不是 Python 标准库命令，必须在开发依赖中固定版本。格式检查、lint、类型检查、运行时 schema 和测试职责不同，不能相互替代。

## 7. 使用 pdb 和 breakpoint 调试

在代码中加入：

```python
breakpoint()
```

运行程序后会进入调试器。也可以从命令行启动：

```bash
python -m pdb scripts/import_orders.py
```

常用 pdb 命令：

```text
b 42                 在当前文件第 42 行设置断点
b service.py:42      在指定文件设置断点
r                     运行到当前函数返回
n                     下一行，不进入函数
s                     进入函数
p order               打印表达式
pp order              格式化打印
l                     查看附近源码
w                     查看调用栈
u / d                 切换上层/下层栈帧
c                     继续
q                     退出
```

生产代码中不应遗留会暂停进程的 `breakpoint()`。需要临时禁用时可以：

```bash
PYTHONBREAKPOINT=0 python -m order_service
```

## 8. 开发模式和异常诊断

启用开发模式：

```bash
python -X dev -m order_service
```

启用 faulthandler：

```bash
python -X faulthandler -m order_service
```

调试 asyncio：

```bash
PYTHONASYNCIODEBUG=1 python -X dev -m order_service
```

这些模式会增加检查或日志，不应未经评估直接用于高负载生产环境。

## 9. CPU、内存和微基准

CPU profile：

```bash
python -m cProfile -o cpu.prof -m order_service
python -m pstats cpu.prof
```

在 pstats 中常用：

```text
sort cumulative
stats 30
callers
callees
```

观察内存分配栈：

```bash
python -X tracemalloc=25 -m order_service
```

微基准：

```bash
python -m timeit -s 'values=list(range(1000))' 'sum(values)'
```

`timeit` 只适合局部表达式；接口 P99、数据库和异步系统必须使用真实服务负载和观测数据。

## 10. 构建和安装产物

构建 wheel/sdist 通常需要项目开发依赖中的 `build`：

```bash
python -m build
```

检查产物：

```bash
python -m zipfile -l dist/order_service-1.0.0-py3-none-any.whl
```

在干净环境验证安装：

```bash
python -m venv /tmp/order-verify-venv
/tmp/order-verify-venv/bin/python -m pip install dist/order_service-1.0.0-py3-none-any.whl
/tmp/order-verify-venv/bin/python -m order_service
```

应用部署也可以使用容器或锁定环境，但必须验证最终产物，而不只是源码目录中的 editable install。

## 11. 推荐的日常命令顺序

```bash
source .venv/bin/activate
ruff format --check .
ruff check .
mypy src
python -m pytest
python -m build
```

项目没有采用 ruff、mypy 或 pytest 时，使用 `pyproject.toml` 中实际约定的工具，不要同时引入多套职责重叠的命令。

## 12. 掌握标准

- 能确认正在使用的 Python 解释器、pip 和虚拟环境。
- 能区分脚本运行、`python -m`、字节码缓存和 distribution 构建。
- 能运行 unittest/pytest、指定测试、覆盖率、lint 和类型检查。
- 能使用 `breakpoint()`/pdb 查看变量、栈帧和调用链。
- 能使用开发模式、faulthandler、asyncio debug、cProfile 和 tracemalloc。
- 能构建 wheel，并在干净环境验证最终产物。
