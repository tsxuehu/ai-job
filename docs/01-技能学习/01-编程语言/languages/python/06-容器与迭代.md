# Python：容器与迭代

Python 容器高度通用，选择时要考虑顺序、可变性、哈希、复杂度和是否会一次性占用内存。

## 1. 常用容器

| 类型 | 适合场景 | 关键点 |
| --- | --- | --- |
| `list` | 默认有序动态序列 | 尾部 append 快，中间插入移动元素 |
| `tuple` | 固定结构、不可变序列 | 元素本身仍可能可变 |
| `dict` | 保持插入顺序的键值映射 | key 必须可哈希且相等/哈希稳定 |
| `set` / `frozenset` | 去重和成员判断 | 无业务排序语义 |
| `deque` | 队列和双端操作 | 两端增删高效 |
| `heapq` | 优先队列 | 在 list 上维护最小堆 |

对外返回内部 list/dict 时明确共享或复制。浅复制只复制外层容器，嵌套对象仍共享。

## 2. iterable、iterator 与 generator

- iterable 可以产生 iterator；iterator 记录一次遍历状态。
- `iter()` 获取 iterator，`next()` 推进并可能抛 StopIteration。
- generator 惰性产生值，适合流式处理和组合管道。
- 生成器持有函数帧和捕获资源，未耗尽时要明确关闭策略。

```python
def read_valid(lines: Iterable[str]) -> Iterator[Record]:
    for line in lines:
        if record := parse(line):
            yield record
```

## 3. 排序与复杂度

`sorted` 返回新 list，`list.sort` 原地修改；排序稳定。成员判断在 list 通常线性，在 set/dict 平均常数。性能判断结合数据规模、对象哈希成本和内存，而不是只背复杂度。

## 4. 用生成器处理订单流

```python
def pending_orders(rows: Iterable[Row]) -> Iterator[Order]:
    for row in rows:
        order = to_order(row)
        if order.status is Status.PENDING:
            yield order
```

调用函数只创建 generator；每次 `next` 才继续执行到下一个 yield。它能以较小内存流式处理，但会把异常和资源使用推迟到消费阶段。调用方必须知道迭代是一次性的、可能抛错且可能持有上游资源。

## 5. dict key 依赖 hash 与相等性

可作为 key 的对象必须 hash 稳定，并满足相等对象具有相同 hash。冻结 dataclass/不可变值适合业务 ID；可变实体通常不适合作 key。dict 保持插入顺序，但“排序输出”仍要显式排序。

## 6. 与其他语言对照

| 语言经验 | Python 中的差异 |
| --- | --- |
| Java Stream | generator/iterator 是语言协议，可逐步执行并保留 frame |
| C++ ranges | 都可惰性借用源数据；Python 生成器还会保存执行状态和异常位置 |
| Go channel | generator 通常是同线程拉取模型，不等于并发通信 |
| JS AsyncIterable | 普通 Python Iterator 同步；异步流使用 AsyncIterator/async for |

## 7. 动手验证

2. 提前停止消费持有文件的生成器，验证清理；

4. 用 deque 实现队列，避免 list 头部删除；
5. 对不同数据规模测量 list/set 成员判断。

## 8. 掌握标准

- 能按顺序、查找、队列、去重和可变性选择容器。
- 能区分 iterable、iterator、generator 和一次性消费。
- 能避免内部集合泄露、错误浅复制和无意一次性加载大数据。
