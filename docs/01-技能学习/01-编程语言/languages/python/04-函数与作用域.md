# Python：函数与作用域

Python 调用把对象绑定给形参；可变对象可能被函数修改，重新绑定形参不会改变调用方名称。

## 1. 参数设计

```python
def request(
    url: str,
    *,
    timeout: float,
    retries: int = 0,
) -> Response:
    ...
```

- `/` 前是仅位置参数，`*` 后是仅关键字参数。
- `*args` 收集 tuple，`**kwargs` 收集 dict；公共 API 不用它们隐藏无约束输入。
- 默认参数在函数定义时求值一次，可变默认值使用 `None` 后在函数内创建。
- 不在函数中通过可变全局变量隐式输出结果。

## 2. LEGB 与闭包

名称按 Local、Enclosing、Global、Builtins 查找。赋值默认创建局部名称，`nonlocal` 修改外围函数绑定，`global` 修改模块绑定；二者都应少用。

闭包捕获名称绑定，循环中创建 lambda 可能在调用时都读取最终值。使用默认参数冻结本轮值，或提取工厂函数。

## 3. 函数、装饰器和 callable

函数是一等对象。装饰器接收并返回 callable，要用 `functools.wraps` 保留元数据；含参数装饰器是多层函数。装饰器不应隐藏事务、重试和错误等关键语义。

生成器函数含 `yield`，调用时返回迭代器而不立即执行函数体。`yield from` 委托子迭代器；异步生成器用于异步流。

## 4. 用结算函数看形参绑定

```python
def checkout(order: Order, gateway: PaymentGateway) -> None:
    receipt = gateway.pay(order.id, order.amount_cents)
    order.mark_paid(receipt.id)
```

调用时，实参对象分别绑定给局部名称 `order` 和 `gateway`。函数不复制对象；能否修改由对象协议决定。类型标注帮助检查调用，但运行时不会自动确认 gateway 真正满足 Protocol。

## 5. 默认参数和闭包都涉及定义时机

```python
def append_order(order: Order, orders: list[Order] = []):  # 错误
    orders.append(order)
    return orders
```

默认 list 在函数定义时只创建一次，后续调用共享。改成 `None` 哨兵或显式由调用方传容器。闭包晚绑定也来自“调用时读取名称”，而不是复制创建时的值。

## 6. 装饰器和生成器不能隐藏生命周期

装饰器若增加重试、事务或日志，要保留签名/元数据并明确异常语义。生成器可能在 `yield` 处长期暂停并持有文件、数据库游标和局部对象；若调用方提前停止，使用 context manager 或显式 `close` 保证清理。

## 7. 与其他语言对照

| 语言经验 | Python 中的差异 |
| --- | --- |
| Java/Go | Python 支持仅位置/仅关键字、默认参数和动态 `*args/**kwargs` |
| C++ | 没有基于静态类型的函数重载选择；常用单分派、默认参数或 singledispatch |
| JavaScript | 闭包相似，但 Python 的 LEGB、`nonlocal` 和默认参数时机不同 |

## 8. 动手验证

1. 制造可变默认参数状态泄漏，再用 None 修复；
2. 在循环中创建 lambda，比较晚绑定和默认参数冻结；
3. 给 checkout 重新绑定 order，证明调用方名称不变；
4. 编写生成器持有文件，测试提前停止后的关闭；
5. 给装饰器加入 `functools.wraps` 并检查签名和 traceback。

## 9. 掌握标准

- 能正确设计位置/关键字参数并避免可变默认值。
- 能解释形参绑定、LEGB、闭包晚绑定与 nonlocal/global。
- 能编写保留元数据的装饰器和资源安全的生成器。
