# Python：自定义类型、面向对象与抽象

Python 的 class 是运行时对象，支持继承、多态和动态修改；类型提示又提供 Protocol、泛型等静态抽象，两层需要同时理解。

## 1. 面向对象概念映射

| 概念 | Python 如何实现 |
| --- | --- |
| 对象 | 几乎所有运行时值都是对象，行为通过属性查找和协议调用 |
| 类 | class 本身也是运行时对象，可创建实例并参与元编程 |
| 封装 | 模块/API 约定、前导下划线、property；不是强权限边界 |
| 继承 | 支持多继承，MRO 决定查找顺序，`super()` 沿 MRO 协作 |
| 运行时多态 | 鸭子类型、方法覆盖、ABC 和运行时协议判断 |
| 静态多态检查 | Protocol、泛型和类型检查器；默认不改变运行时 |
| 组合 | 对象字段、委托、函数和装饰器，通常优先于深继承 |

Python 的面向对象模型高度动态。灵活性越强，越需要通过小型公共 API、类型标注、运行时校验和测试约束边界。

## 2. dataclass、class 与 Enum

- dataclass 适合字段明确的数据对象，可生成初始化、比较和 repr。
- 普通 class 适合维护身份、资源和不变量的对象。
- Enum 表达有限常量，避免字符串散落。
- `__slots__` 可限制实例属性并影响内存，但不是安全封装机制。

```python
@dataclass(frozen=True, slots=True)
class TaskId:
    value: int

    def __post_init__(self) -> None:
        if self.value <= 0:
            raise ValueError("value must be positive")
```

前导下划线表达内部成员，双下划线会名称改写但不是权限控制。封装依赖清晰 API、property 和不变量，不是 getter/setter 模板。

## 3. 继承、组合与 MRO

Python 支持多继承，方法解析顺序遵循 MRO；`super()` 沿 MRO 协作调用，不只是“父类方法”。Mixin 应小而无状态。业务复用优先组合，避免复杂菱形继承。

## 4. Protocol、ABC 与泛型

```python
class Store(Protocol):
    def get(self, task_id: TaskId) -> Task | None: ...
```

Protocol 提供结构化静态多态，对象不必显式继承；ABC 提供运行时名义继承与抽象方法检查。泛型描述类型关系，默认不会产生运行时校验。

Python 多态也来自鸭子类型：只要对象提供调用方需要的行为即可。边界层可用 Protocol 给动态能力增加检查。

## 5. 用支付案例看结构化多态

```python
class PaymentGateway(Protocol):
    def pay(self, order_id: str, amount_cents: int) -> Receipt: ...


class CheckoutService:
    def __init__(self, gateway: PaymentGateway) -> None:
        self._gateway = gateway

    def checkout(self, order: Order) -> None:
        receipt = self._gateway.pay(order.id, order.amount_cents)
        order.mark_paid(receipt.id)
```

FakeGateway 不必继承 PaymentGateway，只要静态类型检查器看到相同方法即可。运行时调用仍是普通属性查找和方法绑定；Protocol 默认不会验证外部对象。

## 6. Python 多态来自数据模型协议

`len(x)` 调用长度协议，`for` 使用迭代协议，`with` 使用上下文管理协议，运算符调用特殊方法。Pythonic 抽象通常是实现一个小协议，使对象进入现有语言/标准库生态，而不是创建深继承树。

```python
class OrderBatch:
    def __iter__(self) -> Iterator[Order]:
        return iter(self._orders)
```

## 7. 组合、ABC 和继承如何选择

- 只需静态结构合同：Protocol；
- 必须运行时阻止未实现方法的实例化：ABC；
- 只是复用或包装行为：组合/委托/装饰器；
- 需要协作多继承：设计无状态 mixin，并保证所有类按 MRO 使用 `super()`。

## 8. 与其他语言对照

| 语言经验 | Python 中的差异 |
| --- | --- |
| Java | Protocol 可结构化满足，不必显式 implements；封装更多依赖约定 |
| C++ | 特殊方法协议有点像运行时 Concept，但不进行模板实例化 |
| Go | 都偏好小行为合同；Python Protocol 主要服务静态检查，运行时仍是动态属性访问 |
