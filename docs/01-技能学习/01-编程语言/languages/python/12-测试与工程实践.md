# Python：测试、调试与性能实践

目标：用类型检查、分层测试和运行时证据验证 Python 代码的行为、异步生命周期与性能。依赖和交付参见 [13-工程化](13-工程化.md)。

## 1. 领域规则测试

```python
def test_rejects_non_positive_amount() -> None:
    with pytest.raises(InvalidAmountError):
        Order.create("o-1", 0)
```

类型检查不能替代测试，测试也不能替代边界 schema。核心规则使用普通快速测试，不启动 Web 框架和数据库。

## 2. 异步取消和资源清理

```python
@pytest.mark.asyncio
async def test_worker_stops_after_cancel() -> None:
    task = asyncio.create_task(run_worker())
    task.cancel()

    with pytest.raises(asyncio.CancelledError):
        await task
```

异步测试结束后检查未完成 Task、连接、线程和进程。不要捕获 `CancelledError` 后静默继续；清理完成后通常继续传播。

## 3. 真实边界测试

- 使用真实数据库语义验证 migration、事务、锁和类型映射。
- HTTP/模型服务使用协议级 fake server，不 mock 客户端内部方法。
- 属性测试/fuzz 适合 parser、序列化和不可信输入。
- 同步 SDK 放入 async 链路时，测试 event-loop 阻塞与线程隔离。

## 4. 固定质量命令

```bash
python -m ruff check .
python -m mypy src
python -m pytest
python -m pytest tests/integration
```

工具可以替换，但 formatter/lint、类型检查、单元测试、集成测试和 wheel 构建应是独立门禁。

## 5. 性能和内存定位

```bash
python -m cProfile -o profile.out -m company_app
python -X tracemalloc -m company_app
```

cProfile/采样 profiler 找 CPU 路径，tracemalloc 看 Python 分配，RSS 和系统工具看 native 内存，asyncio 调试和 event-loop 指标看阻塞。优化前固定 Python 构建、数据、并发和下游。

## 6. 按动态边界选择证据

| 风险 | 首选证据 |
| --- | --- |
| 订单规则 | pytest 参数化单元测试 |
| 静态类型关系 | mypy/pyright 等类型检查 |
| HTTP/JSON/配置 | 运行时 schema + 边界测试 |
| SQL/事务/锁 | 真实数据库集成测试 |
| 任意输入 | Hypothesis/property/fuzz |
| async 取消/泄漏 | TaskGroup 生命周期测试 + loop debug |
| CPU/Python 分配 | profiler + tracemalloc |
| native/RSS | 系统 profiler 与进程指标 |

动态语言不能只靠测试穷举所有类型，类型检查也看不到真实外部数据；两者与 schema 共同组成边界。

## 7. fixture 负责资源，不负责隐藏系统

fixture 适合创建/清理数据库、client 和 app，但范围必须明确。session fixture 的可变状态可能让测试互相污染；autouse fixture 过多会让依赖不可见。核心领域直接构造对象通常最清楚。

## 8. 与其他语言对照

| 语言经验 | Python 测试重点 |
| --- | --- |
| Java/Go/TS 静态类型 | Python 更依赖类型检查 + 运行时 schema + 属性测试的组合 |
| C++ sanitizer | Python 自身少一类内存 UB，但 native 扩展仍可能需要 sanitizer/系统工具 |
| Node async | 都要检查未管理任务和事件循环阻塞，框架插件不同 |

## 9. 动手验证

1. 给 Order 写参数化和 Hypothesis 不变量测试；
2. 用 fake gateway 测业务，用 fake HTTP server 测协议；
3. 真实数据库验证 migration/事务/锁；
4. TaskGroup 中注入取消和多异常，检查所有资源；
5. 用 profiler/tracemalloc 对同一负载形成优化闭环。

## 10. 掌握标准

- [ ] 单元、异步、adapter、集成和契约测试职责分开。
- [ ] 类型检查、schema 校验和运行时测试互不替代。
- [ ] 取消、超时、Task/连接清理有测试。
- [ ] 能区分 Python 分配、native 内存和 IO 等待。

权威参考：[pytest documentation](https://docs.pytest.org/)、[Hypothesis](https://hypothesis.readthedocs.io/)、[unittest](https://docs.python.org/3/library/unittest.html)。
