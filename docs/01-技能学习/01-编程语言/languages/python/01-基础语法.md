# Python：基础语法

Python 用缩进表达代码块，是动态类型语言。类型标注改善静态检查与协作，但默认不会校验运行时值。

## 1. 最小程序

```python
def main() -> None:
    port = 8080
    print(f"listen on {port}")


if __name__ == "__main__":
    main()
```

- 缩进是语法，项目统一 4 个空格并交给 formatter。
- 名称不需要预先声明类型，赋值把名称绑定到对象。
- 冒号开启代码块，空行和命名遵循 PEP 8 约定。
- `__name__` 判断让模块既可导入也可直接执行。

## 2. 常见语法设施

- 注释使用 `#`，docstring 放在模块、类或函数开头说明公共契约。
- f-string 用于清晰插值；日志使用延迟格式化避免无用计算。
- 解包和星号语法可处理序列、映射、参数与导入，过度使用会隐藏数据形状。
- `pass` 表示空块，`...` 常在存根/Protocol 中表示未实现体。
- Python 没有真正的编译期 private；前导下划线表达内部 API 约定。

## 3. 执行和检查

Python 源码通常编译为字节码后由解释器执行；语法通过不等于类型和业务正确。学习项目从开始就使用 formatter、lint、类型检查和测试，不依赖运行到某条路径才发现拼写或类型问题。

## 4. 从模块源码到执行

```text
order.py
→ 解析为语法树
→ 编译为 code object / 字节码
→ Python 虚拟机执行
→ import 时创建并缓存模块对象
```

Python 会编译字节码，但这不等于提前完成 Java/C++ 式静态类型检查。未执行路径中的名称错误可能直到运行才出现；类型检查器、lint 和测试负责提前扩大覆盖面。

```bash
python -m order_service
python -m compileall src
python -m dis order_service.order
```

应用入口优先使用 `python -m package.module` 或安装后的 console script，避免依赖当前目录碰巧进入 `sys.path`。

## 5. 与其他语言对照

| 语言经验 | Python 中的差异 |
| --- | --- |
| Java/C++ | 源码不靠静态类型编译后才能运行；名称和属性解析大量发生在运行时 |
| Node.js | 都有动态模块执行，但 import 规则、缓存和包解析模型不同 |
| Go | Go package 在编译期形成依赖；Python 模块本身是运行时对象 |

## 6. 动手验证

1. 用 `python -m dis` 查看一个订单函数的字节码；
2. 把未定义名称放在未执行分支，比较解释器、lint 和类型检查结果；
3. 直接运行文件和 `python -m` 运行模块，比较 import 路径；
4. 在模块顶层打印副作用，观察首次 import 和缓存后的行为；
5. 建立 `src` package 和 console script，避免修改 `sys.path`。

## 7. 掌握标准

- 能解释缩进、名称绑定、模块入口和 docstring。
- 能区分动态运行时与类型标注的静态检查作用。
- 能创建模块、运行程序并根据 traceback 定位语法和运行时错误。
