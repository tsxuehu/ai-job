# Python：并发与异步

先按任务性质选择模型：大量等待使用 asyncio 或线程，CPU 密集使用进程、native 扩展或外部计算服务。

## 1. threading

线程共享进程内对象，适合阻塞 IO 和需要线程亲和的库。锁保护共享不变量，queue 传递工作。以 CPython GIL 为由忽略同步是错误的：复合操作、跨实现行为和业务状态仍需显式协调。

## 2. multiprocessing

进程拥有独立内存，可利用多核执行 Python CPU 计算；代价是启动、序列化、数据复制和进程间通信。任务粒度要足够大，池需要关闭、等待、超时和子进程失败策略。

## 3. asyncio

```python
async def fetch(client: Client, url: str) -> Data:
    async with asyncio.timeout(2):
        return await client.get(url)
```

- coroutine 只有被 await 或调度为 Task 才推进。
- 事件循环线程中的同步阻塞会停止全部协作任务。
- 使用 TaskGroup 管理子任务生命周期和组合失败。
- 取消通过 `CancelledError` 协作传播，清理后通常要继续传播。
- semaphore/有界队列限制并发与背压，超时需要覆盖整条链路。

## 4. 上下文与生命周期

contextvars 传播请求上下文，不使用线程局部代替异步任务上下文。每个任务有拥有者、结果观察和取消路径；阻塞 IO 使用线程隔离，CPU 工作使用进程/外部服务。

## 5. 用 TaskGroup 管理订单任务

```python
async def process_batch(orders: Iterable[Order]) -> None:
    semaphore = asyncio.Semaphore(20)

    async def run_one(order: Order) -> None:
        async with semaphore:
            await process_order(order)

    async with asyncio.TaskGroup() as group:
        for order in orders:
            group.create_task(run_one(order))
```

TaskGroup 拥有子任务：离开上下文前等待全部结束；一个任务失败会取消其余任务，并可能以 ExceptionGroup 报告。semaphore 限制同时进入下游的数量，但若 orders 本身无限，仍需有界生产/队列，不能先创建无限 Task。

## 6. 取消必须沿调用链传播

捕获 CancelledError 只用于清理，之后通常重新 raise。`asyncio.shield`、后台 Task 和 to_thread 会改变取消边界，必须有具体理由。timeout 包围总体业务链，而不是每层各自重置完整超时预算。

## 7. GIL 与线程安全是两个问题

普通 CPython 的 GIL 限制同时执行 Python 字节码，但一个业务操作可能跨多个字节码/await，native 扩展可能释放 GIL，free-threaded 构建行为也不同。共享可变状态仍使用锁、队列、不可变消息或单 owner。

## 8. 与其他语言对照

| 语言经验 | Python 中的差异 |
| --- | --- |
| Node.js Promise | TaskGroup 提供结构化 owner 和组合取消；Promise 默认没有父子生命周期 |
| Go goroutine | asyncio Task 依赖事件循环且需 await 才协作推进，CPU 循环会阻塞 |
| Java virtual thread | Python coroutine 不是线程，阻塞库必须适配，CPU 并行通常靠进程/native |

## 9. 动手验证

1. 创建 coroutine 但不 await，观察警告与未执行行为；
2. 在 TaskGroup 让两个任务失败，检查 ExceptionGroup；
3. 吞掉 CancelledError，验证停机为何卡住；
4. 比较 threading/multiprocessing/asyncio 的 IO 与 CPU 负载；
5. 用有界 queue 实现生产者/消费者和优雅关闭。

## 10. 掌握标准

- 能根据 IO/CPU、共享/隔离选择线程、进程和 asyncio。
- 能管理 TaskGroup、超时、取消、背压和阻塞隔离。
- 能解释 GIL 的影响与它不能保证的业务并发正确性。
