# Java：工程化

Java 企业项目需要同时处理业务 package、Maven/Gradle 构建模块、Spring composition root、JPA 边界和 JVM 生产治理。公共原则参见 [企业级后端项目工程结构](../../../../03-实战项目/企业级项目工程结构.md)。

## 1. 两种推荐起点

### 1.1 单构建模块，package by feature

适合边界尚在演进的中小项目：

```text
src/main/java/com/company/app/
├── order/
│   ├── domain/
│   ├── application/
│   ├── adapter/in/web/
│   ├── adapter/out/persistence/
│   └── config/
├── inventory/
└── bootstrap/
```

### 1.2 多构建模块的模块化单体

适合边界稳定、需要编译级依赖约束的项目：

```text
repository/
├── settings.gradle / pom.xml
├── modules/
│   ├── order-domain/
│   ├── order-application/
│   ├── order-adapter-web/
│   ├── order-adapter-persistence/
│   └── inventory-.../
├── platform/
│   ├── observability/
│   └── database/
├── apps/
│   ├── boot-api/
│   └── boot-worker/
├── contracts/
├── migrations/
├── tests-integration/
├── deploy/
├── ops/
└── docs/
```

不要一开始就为每个 package 建构建模块。构建模块用于强化稳定依赖、独立测试或复用，不用于展示目录数量。

## 2. 依赖方向

```text
order-domain
      ▲
order-application ◄── persistence-adapter
      ▲              messaging-adapter
      │
web-adapter
      ▲
boot-api（Spring 组装所有 Bean）
```

- domain 是普通 Java，不依赖 Spring、JPA、Jackson 和 HTTP。
- application 定义用例、事务意图与 Repository/Clock/Publisher 等端口。
- adapter 负责 Spring MVC、JPA、消息和外部 SDK 细节。
- boot module 创建 Spring Boot Application 和配置，是主要 composition root。
- Maven/Gradle 依赖图与架构方向一致，CI/架构测试阻止反向依赖。

## 3. Spring 边界

- `@SpringBootApplication`、component scan 范围保持可控，不能扫描整个公司根包。
- 核心对象优先显式构造；Spring 配置将端口绑定到 adapter。
- 事务边界通常放 application 用例，明确代理调用、异常回滚和异步线程切换。
- domain 不通过静态 ApplicationContext、Service Locator 或 `@Autowired` 获取依赖。
- 模块事件区分同进程领域事件与跨边界集成事件。

## 4. JPA 与数据边界

- JPA entity 属于 persistence adapter，不直接作为 HTTP DTO 和领域对象。
- Repository 返回领域类型或 application 所需结果，不能泄露 EntityManager/Session。
- 数据库表明确业务模块所有者；其他模块不直接复用 entity/repository。
- migration 与应用版本共同发布，使用向前兼容的 expand/contract 过程。
- 集成测试使用真实数据库语义验证事务、锁、索引、N+1 和映射。

## 5. 构建与依赖治理

- Java `package` 组织源码和访问范围；Maven/Gradle module 是构建与依赖边界；
  JPMS module 进一步约束运行时的 `requires` 和 `exports`。三者不是一回事。
- Maven/Gradle 只选一个主要工作流，提交 wrapper 并固定 JDK/插件。
- 使用版本平台/BOM 统一依赖，检查收敛和传递依赖。
- annotation processor、代码生成和生成目录进入可复现构建。
- JPMS 可进一步限制 exports/requires，但先验证 Spring、反射和依赖兼容。
- 公共 `common` module 必须拆成小型稳定能力，不能成为循环依赖中转站。

## 6. 测试组织

- domain/application：普通快速单元测试，不启动 Spring context。
- adapter slice：Web、JSON、JPA、消息等局部框架测试。
- 集成测试：真实数据库、迁移、事务和外部协议。
- 架构测试：限制 package/module 依赖与命名规则。
- boot smoke：验证 Bean 能组装、配置能校验、应用能启动。
- 性能/JVM：JFR、线程/堆/GC 分析与固定负载报告。

## 7. 常见错误

- 全局 controller/service/repository/entity 分层，业务边界消失。
- domain 充满 Spring/JPA/Jackson 注解，无法独立验证。
- 所有模块依赖 common，或通过共享 entity 耦合数据。
- 启动完整 Spring context 才能测试一个值对象。
- 以为 `@Transactional` 自调用、异步调用和 private 方法都会自动生效。

## 8. 项目从小到大如何演进

```text
阶段 1：单构建模块，order package 内聚
阶段 2：按 feature 分 domain/application/adapter
阶段 3：稳定边界升级为 Maven/Gradle module
阶段 4：确有独立发布/扩缩容需求时拆服务
```

不要从 controller/service/repository 全局技术目录开始，也不要一开始把每个 package 变成构建模块。边界应该来自业务变化、依赖方向、测试和发布需求。

## 9. 一个请求如何穿过工程边界

```text
boot-api：创建 DataSource、gateway、repository、service、controller
→ web adapter：HTTP/DTO/校验
→ application：用例、事务意图、端口
→ domain：Order 与规则
→ persistence/payment adapter：JPA/JDBC/HTTP 实现
```

Spring 负责在 composition root 组装，不应成为 domain 的服务定位器。Repository 接口靠近使用方，JPA entity 和 SDK error 留在 adapter。

## 10. 配置、迁移、可观测性和发布

- 启动时一次绑定并校验有类型配置；业务代码不散落读取环境变量；
- migration 使用 expand/contract 支持滚动升级；
- trace/log/metric 在请求边界建立，在 adapter 记录外部依赖；
- 构建一次不可变 jar/image，逐环境推广；
- 固定 JDK、wrapper、plugin、BOM 和 annotation processor；
- readiness 下线后停止接收，关闭 executor，等待任务，再关闭连接/遥测。

## 11. package、构建 module 与 JPMS

| 概念 | 作用 |
| --- | --- |
| Java package | 名称与源码访问级别 |
| Maven/Gradle module | 构建、依赖、测试和产物边界 |
| JPMS module | JVM 级 requires/exports/opens |
| repository | 版本控制容器，可含多个构建 module |

Spring 反射可能需要 `opens`，不能把 JPMS `exports` 与 Maven dependency 混为一谈。

## 12. 与其他语言工程边界对照

| 生态 | Java 特别关注 |
| --- | --- |
| C++ | Java 不处理头文件/ABI 同类问题，但要处理 classpath、classloader、代理和反射 |
| Go | Java 构建模块与 package 分层更常见，框架组装更重 |
| Node/Python | Java 依赖图在编译期更强，运行时仍可能被反射/代理扩展 |

## 13. 动手验证

1. 将全局技术分层重构为 order feature package；
2. 用 ArchUnit/构建依赖阻止 domain 导入 Spring/JPA；
3. 比较单模块和拆构建模块后的实际收益；
4. 演练代理自调用、事务跨线程和滚动 migration；
5. 模拟 SIGTERM 验证 readiness、executor、连接和 JFR/日志关闭顺序。

## 14. 掌握标准

- [ ] package/build module 按业务能力划分，依赖图有向无环。
- [ ] domain/application 能脱离 Spring/JPA 快速测试。
- [ ] boot module 负责组装，adapter 不向核心泄露框架类型。
- [ ] entity、DTO、领域类型和事件 schema 边界清楚。
- [ ] 构建、迁移、架构测试和生产产物可复现。
- [ ] 线程池、连接池、虚拟线程和优雅停机在应用入口统一治理。
