# Java：容器与迭代

Java 集合以接口表达能力，以具体实现决定顺序、复杂度、内存布局和并发性质。

## 1. 常用集合

| 接口/实现 | 适合场景 | 关键点 |
| --- | --- | --- |
| `ArrayList` | 默认动态序列 | 随机访问快，中间插入移动元素 |
| `ArrayDeque` | 队列、栈、双端操作 | 通常优于 Stack/LinkedList |
| `HashMap` | 按键查找 | 依赖正确 `equals/hashCode`，无顺序契约 |
| `LinkedHashMap` | 保持插入或访问顺序 | 额外链表开销，可做有限 LRU 基础 |
| `TreeMap` | 有序键和范围查询 | 对数复杂度，需要比较规则 |
| `HashSet` / `TreeSet` | 去重和成员判断 | 与对应 map 语义一致 |
| `ConcurrentHashMap` | 高并发键值访问 | 复合操作使用原子 API |

集合泛型保存引用。不可变集合工厂只禁止结构修改；其中的元素对象仍可能可变。

## 2. Iterator 与 Stream

Iterator 适合逐步遍历和安全删除。Stream 是一次性的惰性计算流水线，终止操作才执行；避免在并行 Stream 中修改共享状态。

```java
var ids = tasks.stream()
    .filter(Task::isReady)
    .map(Task::id)
    .toList();
```

简单循环通常更易调试；Stream 适合清晰的数据转换，不用于隐藏复杂 IO 和异常流程。

## 3. 易错点

- map key 可变且参与 `equals/hashCode`，修改后无法正常查找。
- 使用 `Arrays.asList` 或不可变集合后误以为可增删。
- 遍历时直接修改集合结构。
- 默认启用 parallel stream，占用共享 ForkJoinPool 并放大阻塞。

## 4. 一个订单索引为何依赖相等性

```java
record OrderId(String value) {
    OrderId {
        if (value == null || value.isBlank()) throw new IllegalArgumentException("value");
    }
}

var orders = new HashMap<OrderId, Order>();
orders.put(new OrderId("order-1"), order);
```

record 自动生成与组件一致的 `equals/hashCode`，适合稳定值键。普通可变实体若把可变字段放进 hash，插入后修改会破坏查找。集合选择不仅是 API 选择，还包含元素相等性、顺序和线程安全合同。

## 5. 复合操作和并发

```java
orders.computeIfAbsent(id, this::loadOrder);
```

对于 ConcurrentHashMap，“先 get、没有再 put”不是原子操作；使用 compute/merge 等原子 API，但传入函数仍应短小且避免意外阻塞。不可变快照常比共享可变集合更容易推理。

## 6. 与其他语言对照

| 语言经验 | Java 中的差异 |
| --- | --- |
| C++ 容器存值 | Java 集合通常保存对象引用，不复制元素对象 |
| Python dict/JS Map | Java HashMap 依赖静态 key 类型及 `equals/hashCode` 合同 |
| Go map | 两者普通实现都不支持无同步并发修改；Java 另有并发集合 |

## 7. 动手验证

1. 让可变 key 进入 HashMap 后改变 hash 字段，观察查找；
2. 比较 ArrayList、ArrayDeque 和 LinkedList 的真实遍历/队列性能；
3. 使用 Iterator 安全删除元素；
4. 比较循环和 Stream 对错误、调试和 IO 的表达；
5. 用 ConcurrentHashMap 原子 API 修复一次 check-then-act 竞争。

## 8. 掌握标准

- 能根据顺序、访问、并发和复杂度选择集合实现。
- 能维护正确 `equals/hashCode`，处理 Iterator 修改规则。
- 能判断循环、Stream 和并行处理的适用边界。
