# Java：并发与异步

Java 并发正确性建立在 happens-before 关系上，而不是“这行代码大概率先执行”。

## 1. Java Memory Model

- 锁释放 happens-before 随后的同一锁获取。
- volatile 写 happens-before 随后的读，提供可见性与一定顺序，不让复合操作自动原子化。
- 线程启动、join、并发工具都有规定的同步关系。
- 没有同步的共享读写存在 data race，结果不能用源码顺序推断。

## 2. 线程池和任务生命周期

```java
// Java 21+
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    var future = executor.submit(() -> client.fetch(request));
    return future.get(timeout, TimeUnit.SECONDS);
}
```

平台线程池必须设置线程数、队列容量、拒绝策略、线程命名和关闭流程。无界队列会把过载变成延迟和内存问题。虚拟线程适合大量阻塞式 IO，不能让 CPU 任务突破容量，也要注意 pinning、连接池和下游限制。

Java 17 项目使用显式 ExecutorService，并在 finally 中 shutdown/awaitTermination；不要把上面的 Java 21 API 复制进 Java 17 构建。

## 3. 同步工具

- `synchronized`/Lock 保护一组状态不变量。
- atomic/CAS 适合计数和明确状态机，不替代多字段事务。
- ConcurrentHashMap 的单步操作安全，复合逻辑用 compute 等原子 API。
- semaphore 限制并发，latch/barrier/phaser 协调阶段。

## 4. CompletableFuture

明确每个 stage 使用哪个 Executor、异常如何传播、超时和取消如何处理。默认公共 ForkJoinPool 不适合不可控阻塞任务。取消 Future 不保证底层 IO 一定停止。

## 5. 一个有生命周期的订单 Worker

```text
固定平台线程池 / Java 21+ 每任务虚拟线程
← 有界入口或 semaphore
← 订单生产者

拥有者：应用入口
停止：停止接收 + cancel/interrupt
等待：Future.get / executor termination
错误：每个 Future 或结构化任务边界
```

任务只有“提交成功”远远不够。队列满时怎么处理、interrupt 是否被保留、底层 HTTP/JDBC 是否响应取消、停机等多久，都必须进入合同与测试。

## 6. volatile 不保护业务不变量

```java
if (!orders.containsKey(id)) {
    orders.put(id, order);
}
```

即使 map 引用是 volatile，上面仍是两个操作。使用锁保护完整检查-写入不变量，或使用并发集合原子 API。atomic 变量也只保护其自身状态转换。

## 7. CompletableFuture 的执行器是架构选择

`thenApply` 可能在完成前一 stage 的线程执行，`thenApplyAsync` 默认可能进入公共池。每个阻塞 stage、CPU stage、超时、异常和取消都要明确执行器。链式语法不能自动提供背压或结构化生命周期。

## 8. 与其他语言对照

| 语言经验 | Java 中的差异 |
| --- | --- |
| Go goroutine | Java 虚拟线程接近轻量阻塞任务，但仍由 JMM、interrupt 和资源池约束 |
| Node/Python async | Java 多线程可并行执行共享内存代码，data race 和锁更直接 |
| C++ thread | Java 有 managed runtime、并发集合和 Executor，但线程生命周期仍不能忽略 |

## 9. 动手验证

1. 制造 `count++` 竞争，比较 volatile、AtomicLong 和锁；
2. 使用有界 ThreadPoolExecutor 验证拒绝和队列等待；
3. cancel Future 并检查任务是否响应 interrupt；
4. 让 CompletableFuture stage 跑在不同 executor，记录线程与上下文；
5. Java 21+ 比较平台/虚拟线程，但固定数据库连接数观察瓶颈。

## 10. 掌握标准

- 能用 happens-before 解释 volatile、锁和线程启动/join。
- 能设计有容量、拒绝、超时、取消和关闭的执行器。
- 能判断平台线程、虚拟线程和 CompletableFuture 的适用边界。
