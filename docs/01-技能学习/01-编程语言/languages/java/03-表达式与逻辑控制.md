# Java：表达式与逻辑控制

Java 控制结构传统而明确，现代 switch 表达式和模式匹配进一步提高有限状态处理的完整性。

## 1. 表达式

- `&&`、`||` 短路，`&`、`|` 也可用于布尔但会计算两侧。
- 整数除法截断，移位和混合数值运算要确认提升规则。
- 三元运算符只适合短小的值选择，复杂逻辑使用 if 或方法。
- 对象比较默认用 `equals`，排序语义用 `Comparator` 或 `Comparable`。

## 2. 分支

```java
var result = switch (state) {
    case READY -> start();
    case STOPPED -> Result.ok();
    case FAILED -> Result.failed();
};
```

传统 `switch` 的冒号分支可能贯穿；箭头分支不会。sealed 类型和 enum 配合穷举 switch，可以在新增状态时获得编译提示。

```java
if (!(request instanceof ValidRequest valid)) {
    return reject(request);
}
return handle(valid);
```

## 3. 循环

- 增强 for 适合遍历 `Iterable` 或数组。
- 经典 for 用于索引、步长等确有含义的情况。
- `while`/`do-while` 用于条件驱动循环。
- 遍历集合时删除元素使用 Iterator 的删除方法或集合批量 API，避免并发修改异常。

## 4. 易错点

- 在条件中写复杂副作用，使求值顺序难以审查。
- `switch` 漏写 break 或默认分支吞掉新状态。
- 用 `==` 比较 String 或包装对象。
- 遍历集合时直接改变其结构。

## 5. 用订单状态建立穷举分支

```java
enum Status { PENDING, PAID, CANCELLED }

static String nextAction(Status status) {
    return switch (status) {
        case PENDING -> "pay";
        case PAID -> "ship";
        case CANCELLED -> "stop";
    };
}
```

switch 表达式必须产生值。enum 或 sealed hierarchy 能让编译器帮助检查穷举；不要随意加入 `default`，否则新增合法状态可能被吞进旧逻辑。

## 6. 装箱、提升和比较会改变结果

```java
Integer a = 1000;
Integer b = 1000;
System.out.println(a == b);      // 比较引用，不应依赖结果
System.out.println(a.equals(b)); // 比较值
```

表达式分析顺序：先确认基本类型还是引用类型，再看拆箱/装箱、数值提升、是否可能 null，最后看运算符语义。涉及金额时不要用浮点近似承担精确业务语义。

## 7. 与其他语言对照

| 语言经验 | Java 中的差异 |
| --- | --- |
| JavaScript/Python 真值 | Java 条件必须是 boolean，不对字符串/数字做动态真值判断 |
| C++ switch | 传统冒号形式都可能贯穿；现代箭头 switch 不贯穿并可返回值 |
| Go enum 常量 | Java enum 是类实例，可携带字段和行为 |

## 8. 动手验证

1. 给订单新增状态，比较有无 `default` 的编译反馈；
2. 构造 `Integer` 比较和 null 自动拆箱异常；
3. 用 `Math.addExact` 验证金额溢出；
4. 遍历集合时直接结构修改，再使用 Iterator/批量 API 修复；
5. 为状态决策写参数化边界测试。

## 9. 掌握标准

- 能解释短路、数值提升与对象比较。
- 能选择 if、switch 表达式和循环，并处理完整状态。
- 能用边界和分支测试覆盖空集合、未知状态和数值极值。
