# Java：IO 与网络

> 目标：使用文件、HTTP、JSON 和 JDBC 时，明确编码、流式处理、超时、输入限制、事务和资源关闭。

统一场景：读取订单文件，调用库存 HTTP 服务，再把订单写入数据库。

## 1. 文件、文本和字节

```java
try (BufferedReader reader = Files.newBufferedReader(
    path, StandardCharsets.UTF_8
)) {
    for (String line; (line = reader.readLine()) != null;) {
        // 解析一行订单。
    }
}
```

- 文本读写显式指定 Charset，不依赖平台默认编码；
- 大文件逐行或分块处理，不使用 `readAllBytes` 无上限读取；
- 区分 Reader/Writer 的字符语义和 InputStream/OutputStream 的字节语义；
- 实现 `AutoCloseable` 的资源使用 try-with-resources；
- 临时文件替换要考虑原子性、权限和失败恢复。

## 2. NIO 与流式处理

Channel、ByteBuffer 和异步 API 适合需要精细控制缓冲和网络的场景，但要正确处理：

- ByteBuffer 的 position、limit、flip/clear；
- 一次 read/write 只处理部分数据；
- EOF、零字节进展和消息边界；
- 缓冲池容量和直接内存；
- selector/异步回调的取消与关闭。

普通业务文件优先使用清晰的高层 API，确认存在性能需要后再降低抽象层次。

## 3. HTTP

```java
var request = HttpRequest.newBuilder(uri)
    .timeout(Duration.ofSeconds(2))
    .GET()
    .build();

var response = client.send(
    request, HttpResponse.BodyHandlers.ofInputStream()
);
```

- 复用 HttpClient 和连接；
- 区分连接、单请求和总体业务 deadline；
- 限制响应体，流式处理大响应；
- 检查状态码和 Content-Type；
- 重试只用于幂等且可判定的临时失败；
- 异步 API 仍需传播取消并限制并发。

## 4. JSON 与边界 DTO

HTTP JSON 先进入 DTO，再转换为领域对象：

```text
JSON → CreateOrderRequest → CreateOrderCommand → Order
```

校验必填、未知字段、字符串/数组长度、金额精度和时间格式。Jackson 等反序列化成功只代表语法和部分类型可接受，不代表业务有效。

## 5. JDBC

```java
try (
    Connection connection = dataSource.getConnection();
    PreparedStatement statement = connection.prepareStatement(sql)
) {
    statement.setString(1, orderId);
    statement.executeUpdate();
}
```

- 使用参数化 SQL；
- Connection、Statement、ResultSet 使用 try-with-resources；
- 事务明确 begin/commit/rollback；
- 连接池配置容量、获取超时和泄漏诊断；
- 大结果集流式获取，注意驱动行为；
- ORM 不能消除 N+1、事务、锁和索引问题。

## 6. 常见错误

- 使用平台默认编码；
- 把整个文件/响应读入内存且没有上限；
- 忽略部分读写和 ByteBuffer 状态；
- HTTP 只有连接超时，没有请求 deadline；
- JPA entity 同时作为 HTTP DTO 和领域对象；
- 异常时没有回滚事务或归还连接。
