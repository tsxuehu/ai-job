# Java：变量、数据与类型

Java 有基本类型和引用类型。变量始终存放一个值；引用变量的值是“指向对象的引用”，不是对象本身。

## 1. 基本类型

- 整数：`byte`、`short`、`int`、`long`；`char` 是 UTF-16 code unit。
- 浮点：`float`、`double`；精确金额使用 `BigDecimal` 并明确舍入规则。
- 布尔：`boolean`。
- 基本类型赋值按值复制，不可为 `null`。

自动装箱把基本类型转换成 `Integer` 等包装类型，但会引入对象、null 和缓存比较等语义，热点路径也可能增加分配。

## 2. 变量、引用和实际数据

Java 源码不提供 C++ 那样的普通指针。变量中要么保存基本值，要么保存对象引用；引用可以理解为 JVM 用来找到对象的值。

### 2.1 基本类型变量直接保存值

```java
int first = 100;
int second = first;
second = 200;
```

关系是：

```text
变量 first              变量 second
┌──────────┐            ┌──────────┐
│ int: 100 │            │ int: 200 │
└──────────┘            └──────────┘
```

`second = first` 复制的是数字 100，之后修改 `second` 不影响 `first`。

### 2.2 引用变量保存对象引用

```java
User first = new User("Alice");
User second = first;
```

`new User(...)` 创建 `User` 对象并返回引用。`first` 保存引用，`second = first` 复制这份引用，没有复制对象：

```text
变量 first ──引用──┐
                   ├──▶ User 对象 { name: "Alice" }
变量 second ─引用──┘
```

因此通过任一引用修改对象，另一方都能看到：

```java
second.setName("Bob");

System.out.println(first.getName()); // Bob
```

但给变量重新赋值，只会改变这个变量保存的引用：

```java
second = new User("Carol");
```

关系变为：

```text
first  ──▶ User 对象 { name: "Bob" }
second ──▶ User 对象 { name: "Carol" }
```

这就是“修改对象”和“修改变量指向”之间的区别。

### 2.3 `null` 表示没有对象引用

```java
User user = null;
```

变量 `user` 存在，但里面没有能找到 `User` 对象的引用：

```text
变量 user
┌──────────────┐
│ 引用值：null │ ──▶ 没有 User 对象
└──────────────┘
```

因此下面代码无法找到对象来调用方法：

```java
user.getName(); // NullPointerException
```

### 2.4 数组和集合中保存什么

基本类型数组直接保存基本值；对象数组和大多数集合保存对象引用：

```java
User alice = new User("Alice");
User[] users = {alice};
List<User> list = new ArrayList<>();
list.add(alice);
```

可以简化理解为：

```text
alice 变量 ───────────────┐
users[0] 中的引用 ────────┼──▶ 同一个 User 对象
list 元素中的引用 ────────┘
```

复制 List 变量只复制引用；`new ArrayList<>(list)` 创建新列表，但其中的 `User` 引用仍指向原对象，这叫浅复制。

### 2.5 栈和堆只是常用简化模型

教学时常说“局部变量在栈上、对象在堆上”，这有助于理解生命周期，但不是必须遵守的物理布局。JVM/JIT 可以通过逃逸分析、标量替换等方式消除对象分配。业务代码真正应依赖的是：变量保存基本值或引用、对象是否仍然可达，而不是猜测某个值的实际内存地址。

## 3. String、相等性与数组

`String` 对象不可变，拼接大量文本使用 `StringBuilder`。`equals` 比较对象内容，`==` 比较基本值，或者比较两个引用是否指向同一对象。

数组是固定长度对象。对象数组保存引用并支持协变，可能把部分类型错误推迟到运行时；通用容器优先使用泛型集合。

## 4. null 与 Optional

引用可能为 `null`，解引用会抛 `NullPointerException`。核心模型通过构造校验、非空约定和类型注解减少 null。`Optional<T>` 适合方法返回“可能不存在”，通常不用于实体字段、方法参数和所有集合元素。

## 5. 转换和数值边界

- 小范围到大范围可自动拓宽；可能丢失数据的转换需显式强转。
- 强转不会验证业务范围，整数溢出默认回绕，可使用 `Math.*Exact` 检查。
- 引用向下转型前用模式匹配 `instanceof` 或更好的多态设计。

## 6. 订单对象中实际复制了什么

```java
var first = new Order("order-1", 100);
var second = first;
second.markPaid();

// first 和 second 保存的是同一个对象引用。
```

给方法传 `Order` 时复制的也是引用值，因此方法能通过副本引用修改同一对象，但不能把调用者变量重新指向新对象：

```java
static void replace(Order order) {
    order = new Order("other", 200); // 只改变局部参数
}
```

这不是“对象按引用传递”。Java 所有参数都按值传递，只是引用变量的值恰好指向对象。

## 7. 与其他语言对照

| 语言经验 | Java 中必须修正 |
| --- | --- |
| C++ 值对象 | Java 普通 class 实例通过引用访问，赋值不复制完整对象 |
| Python/Node.js 对象引用 | 使用感觉相似，但 Java 引用具有静态名义类型和受控转换 |
| Go struct | Go struct 赋值通常复制字段；Java class 变量复制引用 |
| TypeScript readonly | Java `final` 只禁止引用重新赋值，也不自动冻结对象 |

## 8. 动手验证

1. 向方法传基本类型、Order、数组和 List，分别修改变量与对象；
2. 比较 String、record 和普通 class 的 `==/equals/hashCode`；
3. 把可变对象作为 HashMap key 后修改参与 hash 的字段，观察查询结果；
4. 比较浅复制 List 与复制其中每个可变元素；
5. 使用 JOL/JFR 只作为实现观察，不把“引用必在栈、对象必在堆”当规范。

- 能识别 null、装箱、溢出、精度和错误强转风险。
