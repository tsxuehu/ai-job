# Java：测试、调试与性能实践

目标：用分层测试证明业务与适配器行为，用 JVM 证据定位并发、内存和性能问题。构建与交付参见 [13-工程化](13-工程化.md)。

## 1. 不启动 Spring 的领域测试

```java
class OrderTest {
    @Test
    void rejectsNonPositiveAmount() {
        assertThrows(InvalidAmountException.class,
            () -> Order.create(new OrderId("o-1"), Money.ZERO));
    }
}
```

值对象、状态机和 application 用例应是普通快速测试。只有验证 Bean 组装、代理、Web/JPA 行为时才启动相应 Spring slice 或完整 context。

## 2. 真实数据库与事务测试

```java
@Test
void duplicateOrderIsMappedToDomainError() {
    repository.save(order("o-1"));

    assertThrows(DuplicateOrderException.class,
        () -> repository.save(order("o-1")));
}
```

这类测试使用与生产一致的数据库语义和 migration，验证唯一约束、事务、锁、时区、类型映射和 N+1。不要用 Mock 复刻 JDBC/JPA 内部行为。

## 3. 并发和异步失败

- Future/CompletableFuture 必须观察异常和超时。
- 测试线程池/虚拟线程的取消、interrupt、容量和关闭。
- 验证事务跨线程后是否仍存在，不靠“看起来加了注解”判断。
- 使用架构测试限制 package/module 反向依赖。

```java
var future = executor.submit(() -> worker.run());
future.cancel(true);
assertTrue(worker.awaitStopped(Duration.ofSeconds(1)));
```

## 4. JVM 排障命令

```bash
./mvnw test
jcmd <pid> Thread.print
jcmd <pid> GC.heap_info
jcmd <pid> JFR.start name=order settings=profile duration=60s filename=order.jfr
```

线程转储看死锁、阻塞和池队列；堆转储看对象保留链；JFR 同时观察 CPU、分配、锁、IO 和 GC。生产抓取前先评估暂停、磁盘和敏感数据风险。

## 5. 性能测试

Java 微基准使用 JMH，避免手写一次 `System.nanoTime` 循环。需要处理预热、JIT、死代码消除和稳定状态；服务测试还要报告 P95/P99、连接池等待和 GC。

## 6. 按风险选择测试层

| 风险 | 首选证据 |
| --- | --- |
| 订单不变量/状态 | 普通 JUnit 参数化单元测试 |
| interface 协作 | 手写 fake/Mockito，只验证可观察行为 |
| Spring MVC/JSON/JPA | 对应 slice + 真实协议/数据库 |
| 事务、锁、migration | 真实数据库集成测试 |
| interrupt/线程池/停机 | 可控同步点和生命周期测试 |
| JIT/分配微优化 | JMH |
| CPU/heap/锁/IO | JFR、profile、dump |

不要为了“像生产”让所有测试启动完整 Spring，也不要为了“快”把数据库行为全部 mock 掉。

## 7. 并发测试不要靠 sleep

使用 latch、barrier、Future 和明确状态同步，让两个操作真正重叠并能在超时内结束。`Thread.sleep` 只能增加概率，不建立 happens-before，也容易形成偶发测试。

## 8. 与其他语言对照

| 语言经验 | Java 测试重点 |
| --- | --- |
| Go | Go 有 race detector；Java 需靠同步设计、stress 工具/JFR 和代码分析共同验证 |
| C++ | Java 无同类 use-after-free，但仍有 data race、资源泄漏和 native/代理问题 |
| Node/Python | Java 还要处理 JIT 预热、类加载、线程池和框架代理边界 |

## 9. 动手验证

1. 给 Order 写参数化状态测试，不启动 Spring；
2. 用 fake gateway 验证错误传播和状态不变；
3. 用真实数据库验证唯一约束、锁和 rollback；
4. 用 latch 构造竞争并验证修复；
5. 从 JFR 找一个热点，再用 JMH/服务压测闭环。

## 10. 掌握标准

- [ ] 领域测试不依赖 Spring context。
- [ ] SQL、migration、事务和序列化由真实组件测试验证。
- [ ] 能用线程转储、堆转储和 JFR 定位不同故障。
- [ ] JMH/服务压测固定 JDK、负载、预热和正确性检查。

权威参考：[JUnit 5 User Guide](https://junit.org/junit5/docs/current/user-guide/)、[JDK Flight Recorder](https://docs.oracle.com/en/java/javase/25/jfapi/)、[JMH](https://github.com/openjdk/jmh)。
