# Java：编译、运行与调试命令

Java 源码先由 `javac` 编译成 class 字节码，再由 JVM 加载和执行。单文件学习可以直接使用 JDK 命令；企业项目应使用仓库自带的 Maven Wrapper 或 Gradle Wrapper，保证构建工具版本一致。

## 1. 检查 JDK 和构建工具

```bash
java -version
javac -version
java -XshowSettings:properties -version
./mvnw -version   # Maven 项目
./gradlew -version # Gradle 项目
```

`java` 和 `javac` 必须来自兼容的 JDK。优先执行仓库里的 `./mvnw` 或 `./gradlew`；全局 `mvn`、`gradle` 版本可能与 CI 不一致。

## 2. 直接编译和运行

假设源码是 `src/com/example/Main.java`：

```bash
mkdir -p out
javac -encoding UTF-8 -d out src/com/example/Main.java
java -cp out com.example.Main
```

关系是：

```text
Main.java
  → javac
  → out/com/example/Main.class
  → java -cp out com.example.Main
  → JVM 加载并执行 main
```

常用编译参数：

| 参数 | 作用 |
| --- | --- |
| `-d out` | class 文件输出目录 |
| `-cp/-classpath` | 编译或运行 classpath |
| `--release 17` | 按指定 Java 版本的语言/API 目标编译 |
| `-encoding UTF-8` | 指定源码编码 |
| `-Xlint:all` | 开启编译警告 |
| `-parameters` | 在 class 中保留方法参数名，部分框架需要 |

生产项目不要手工拼接复杂 classpath，交给 Maven/Gradle 管理。

## 3. 创建和运行 JAR

```bash
jar --create \
  --file order-app.jar \
  --main-class com.example.Main \
  -C out .

java -jar order-app.jar
```

普通 JAR 不会自动包含第三方依赖。可执行 fat/uber JAR 的生成方式由 Maven/Gradle 插件或框架决定，不能只把依赖 JAR 随意解压合并。

检查内容：

```bash
jar --list --file order-app.jar
javap -classpath out -c -p com.example.Main
```

`javap` 用于查看 class 结构和字节码，不是反编译回原始源码。

## 4. Maven 项目

```bash
./mvnw clean compile
./mvnw test
./mvnw package
./mvnw verify
```

只运行指定测试：

```bash
./mvnw -Dtest=OrderServiceTest test
./mvnw -Dtest=OrderServiceTest#shouldRejectDuplicatePayment test
```

查看依赖：

```bash
./mvnw dependency:tree
./mvnw help:effective-pom
```

常见生命周期：

```text
compile → test → package → verify → install → deploy
```

`-DskipTests` 通常跳过测试执行但仍可能编译测试；`-Dmaven.test.skip=true` 连测试编译也跳过。发布前不要用它们掩盖失败。

## 5. Gradle 项目

```bash
./gradlew clean classes
./gradlew test
./gradlew build
```

指定测试：

```bash
./gradlew test --tests 'com.example.OrderServiceTest'
./gradlew test --tests 'com.example.OrderServiceTest.shouldRejectDuplicatePayment'
```

查看任务和依赖：

```bash
./gradlew tasks
./gradlew dependencies
./gradlew dependencyInsight --dependency jackson-databind
```

一个项目选择 Maven 或 Gradle 即可；不要把两套命令混为同一构建流程。

## 6. Spring Boot 的运行方式

Maven 项目：

```bash
./mvnw spring-boot:run
./mvnw clean package
java -jar target/order-service.jar
```

Gradle 项目：

```bash
./gradlew bootRun
./gradlew clean bootJar
java -jar build/libs/order-service.jar
```

开发插件运行和生产 JAR 运行的 classpath、参数、工作目录可能不同。发布前必须实际启动最终产物，而不只是启动 IDE。

## 7. 使用 JDWP 调试

让 JVM 启动后等待调试器连接：

```bash
java \
  -agentlib:jdwp=transport=dt_socket,server=y,suspend=y,address=127.0.0.1:5005 \
  -jar order-service.jar
```

参数含义：

| 参数 | 含义 |
| --- | --- |
| `server=y` | JVM 监听调试器连接 |
| `suspend=y` | main 执行前等待连接 |
| `address=127.0.0.1:5005` | 只监听本机 5005 端口 |

IDE 连接 `127.0.0.1:5005` 后，可以设置断点、查看变量、线程和调用栈。调试端口能控制 JVM，不能直接暴露公网。

已经运行的 JVM 通常不能凭空开启完整 JDWP；生产排障优先使用 JFR、`jcmd`、线程 dump 和可观测数据。

## 8. 线程、堆和 JVM 诊断

查找 Java 进程：

```bash
jps -lv
```

使用 `jcmd`：

```bash
jcmd <pid> VM.command_line
jcmd <pid> VM.system_properties
jcmd <pid> Thread.print
jcmd <pid> GC.heap_info
jcmd <pid> GC.class_histogram
```

传统命令：

```bash
jstack <pid>
jmap -histo:live <pid>
```

生成 heap dump 会暂停进程并产生大文件，必须确认磁盘和生产影响：

```bash
jcmd <pid> GC.heap_dump /safe/path/heap.hprof
```

## 9. JFR 和性能分析

对运行中的 JVM 采集 60 秒：

```bash
jcmd <pid> JFR.start \
  name=order-profile \
  settings=profile \
  duration=60s \
  filename=/safe/path/order.jfr
```

查看记录：

```bash
jfr summary /safe/path/order.jfr
jfr print --events CPULoad,GarbageCollection /safe/path/order.jfr
```

微基准应使用 JMH，通过 Maven/Gradle 项目执行，不能用一次 `System.nanoTime()` 循环代替，因为 JVM 预热、JIT、常量折叠和死代码消除会扭曲结果。

## 10. 测试、格式和质量门禁

Maven 示例：

```bash
./mvnw test
./mvnw verify
```

Gradle 示例：

```bash
./gradlew test
./gradlew check
```

格式、Checkstyle、SpotBugs、错误检查和覆盖率命令取决于仓库插件，应封装为 Wrapper task，而不是要求开发者记住插件内部参数。

直接运行使用 Java `assert` 的学习示例时，需要开启断言：

```bash
java -ea -cp out com.example.Main
```

## 11. 推荐的日常命令顺序

Maven：

```bash
./mvnw clean verify
java -jar target/order-service.jar
```

Gradle：

```bash
./gradlew clean check build
java -jar build/libs/order-service.jar
```

出现线上问题时先保留时间线和指标，再按现象选择 thread dump、JFR、heap histogram 或 heap dump；不要一开始就使用影响最大的工具。

## 12. 掌握标准

- 能解释 Java 源码、class、classpath、JAR 和 JVM 的关系。
- 能直接使用 `javac/java/jar/javap` 完成最小程序构建。
- 能使用 Maven 或 Gradle Wrapper 编译、测试、打包和查看依赖。
- 能通过 JDWP 连接调试器，并保护调试端口。
- 能使用 `jcmd`、thread dump、JFR 和 heap 工具定位问题。
- 能区分单元测试、构建质量门禁、JMH 和服务压测。
