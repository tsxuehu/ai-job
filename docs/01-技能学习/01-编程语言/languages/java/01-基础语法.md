# Java：基础语法

Java 源码先编译为字节码，再由 JVM 加载和执行。学习语法时要同时区分源码结构、类型检查与 JVM 运行时行为。

## 1. 最小程序

```java
package example;

public final class Application {
    public static void main(String[] args) {
        int port = 8080;
        System.out.println("listen on " + port);
    }
}
```

- `package` 建立命名空间；目录结构通常与包名一致。
- class 是常见代码容器，`main` 是普通应用入口。
- 语句以分号结束，作用域由花括号决定。
- `import` 简化类型名称，不会在运行时“加载全部代码”。

## 2. 声明与可见性

Java 变量必须有可推断或显式类型并在使用前初始化。成员拥有默认值，局部变量没有可依赖的默认初始化。访问级别包括 `private`、包级、`protected` 和 `public`，默认从最小可见性开始。

```java
var timeout = Duration.ofMillis(500); // 仅局部变量可使用 var
final int maxRetries = 3;
```

`var` 仍是静态类型，只省略局部类型书写；`final` 禁止重新赋值，不代表引用对象内部不可变。

## 3. 常见语法设施

- 注解为编译器、框架或工具提供元数据，本身不等于自动产生业务语义。
- `enum` 表达有限常量，`record` 适合紧凑数据载体。
- `switch` 可作为语句或表达式；现代语法优先箭头分支避免贯穿。
- 文档注释使用 Javadoc，公共 API 说明契约、异常和线程安全性。

## 4. 从源码到 JVM 执行

```text
Application.java
→ javac：语法/类型检查并生成 .class 字节码
→ JVM 启动
→ class loader 加载、链接和初始化类
→ 解释器执行代码
→ JIT 根据运行数据编译热点方法
```

源码编译成功不保证运行一定成功：类路径缺失会出现类加载/链接错误，静态初始化可能失败，业务代码还可能抛异常。遇到问题先判断发生在编译、类加载、初始化还是方法执行阶段。

```bash
javac -d out src/example/Application.java
java -cp out example.Application
```

## 5. 与其他语言对照

| 语言经验 | Java 中的差异 |
| --- | --- |
| C++ | Java 通常生成 JVM 字节码，运行时还有类加载、JIT 和 GC |
| Python/Node.js | Java 在 javac 阶段完成名义类型检查，运行时仍保留类元数据 |
| Go | Go 通常直接链接本地可执行文件；Java 以 classpath/module path 组织运行依赖 |

## 6. 动手验证

1. 使用 `javap -c` 查看订单构造和方法调用的字节码；
2. 修改 package 但不调整启动类名，观察错误阶段；
3. 编译时有依赖、运行时删除依赖，观察类加载错误；
4. 创建静态初始化失败的类，区分首次异常与后续使用结果；
5. 分别制造编译错误、`NoClassDefFoundError` 和业务异常。

## 7. 掌握标准

- 能解释 package、class、main、import 和访问级别。
- 能区分局部变量、成员变量、`var` 与 `final`。
- 能从编译错误、类加载错误和运行时异常判断问题阶段。
