# Java：方法与作用域

Java 的函数通常以方法形式存在。参数永远按值传递：传入对象时复制的是引用值，因此方法可以修改对象，但不能把调用方变量重新指向另一个对象。

## 1. 方法签名

```java
public Optional<Task> find(TaskId id) { ... }
public void update(Config config) { ... }
public static Service create(Config config) { ... }
```

- 签名表达名称、参数、返回类型、泛型和可能抛出的 checked exception。
- 方法可以重载，但不能只靠返回类型区分。
- 可变参数在方法内表现为数组，公共 API 谨慎使用。
- 静态方法不依赖实例状态，适合纯计算和明确工厂；不要用静态状态充当依赖注入。

## 2. 作用域与生命周期

局部名称由花括号限定；对象是否存活由可达性决定，不随某个局部引用离开作用域立即销毁。实例字段属于对象，静态字段属于类加载器范围。隐藏的静态可变状态会影响测试、并发和卸载。

## 3. lambda 与方法引用

lambda 实现函数式接口，可捕获 final 或 effectively final 的局部变量。捕获的是值；若值是引用，对象仍可能被修改。lambda 中的 `this` 指向外围实例，不像匿名类那样创建新的 this。

```java
Predicate<Task> ready = task -> task.priority() >= limit;
tasks.stream().filter(ready).forEach(this::process);
```

## 4. 易错点

- 误以为传对象是按引用传递，期待方法替换调用方变量。
- 重载与自动装箱、null 组合导致调用歧义。
- lambda 捕获可变对象并跨线程使用，却没有同步。
- 通过静态字段共享请求状态。

## 5. 用结算方法理解按值传递

```java
static void checkout(Order order, PaymentGateway gateway) {
    var receipt = gateway.pay(order.id(), order.amountCents());
    order.markPaid(receipt.id());
}
```

方法得到两个引用值的副本。它能调用同一 Order 和 gateway 对象，却无法把调用者的变量替换成另一个对象。对象修改是否安全，取决于对象是否可变、是否被其他线程共享和方法合同。

## 6. 重载在编译期，多态分派在运行时

```java
pay(Order order);          // overload A
pay(RecurringOrder order); // overload B
```

重载根据变量的编译期类型选择签名；选定方法后，实例方法覆盖才根据接收者动态类型分派。不要把 overload 和 override 混成同一种多态。

返回集合时应明确可变性和所有权。不要仅为“避免复制”暴露内部可变 List；可返回不可变快照、专用视图或行为方法。

## 7. 与其他语言对照

| 语言经验 | Java 中的差异 |
| --- | --- |
| C++ 引用参数 | Java 没有 `T&` 形参；对象引用本身仍按值复制 |
| Go | Java 支持重载；Go 通过不同函数名或配置对象表达 |
| Python/TypeScript | Java 重载有一个实际实现选择，泛型/装箱/null 可能造成歧义 |

## 8. 动手验证

1. 在方法内重新赋值 Order 参数，证明调用方变量不变；
2. 分别调用 overload/override 示例，记录编译期和运行时选择；
3. 让 lambda 捕获可变 List 并跨线程使用，再改为不可变快照；
4. 比较返回内部集合与 `List.copyOf` 的边界；
5. 删除隐藏静态状态，通过构造参数注入依赖。

## 9. 掌握标准

- 能准确解释 Java 的参数按值传递。
- 能合理使用重载、静态方法、lambda 与函数式接口。
- 能区分名称作用域、对象可达生命周期和类加载器生命周期。
