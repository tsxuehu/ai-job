# C++：测试、调试与性能实践

本章回答“怎样证明代码正确、怎样定位崩溃、怎样用数据优化”。仓库结构、依赖、CI/CD 和部署放在 [13-工程化](13-工程化.md)。

## 1. 单元测试要验证行为

下面使用 Catch2 表达订单规则；GoogleTest 写法不同，测试边界相同。

```cpp
TEST_CASE("order rejects non-positive amount") {
    const auto result = Order::create(OrderId{1}, Money{0});

    REQUIRE_FALSE(result.has_value());
    REQUIRE(result.error() == OrderError::invalid_amount);
}
```

断言稳定错误类型和可观察结果，不断言私有字段、完整日志文本或函数被调用了几次。值对象、状态机和算法测试不应启动数据库和网络。

## 2. 必测的 C++ 风险

- 复制、移动和析构后对象仍满足契约。
- 异常、早返回和取消路径没有资源泄漏。
- parser/协议面对空输入、超长输入和随机字节不会越界。
- 多线程测试反复运行，覆盖启动、停止、超时和竞争。
- 数据库和网络 adapter 使用真实协议验证部分读写与错误映射。

```cpp
TEST_CASE("worker stops before dependency is destroyed") {
    FakeQueue queue;
    Worker worker{queue};
    worker.start();
    worker.request_stop();
    REQUIRE(worker.wait_for(100ms));
}
```

## 3. 编译器和 sanitizer 是测试的一部分

```bash
cmake --preset debug
cmake --build --preset debug
ctest --preset debug --output-on-failure

cmake --preset asan
cmake --build --preset asan
ctest --preset asan --output-on-failure
```

ASan 查越界和 use-after-free，UBSan 查部分未定义行为，TSan 查实际执行路径上的数据竞争。不同 sanitizer 通常分开运行；没有报告不等于程序已被证明正确。

## 4. 调试顺序

1. 保存输入、commit、编译器、构建参数和依赖版本。
2. 使用 GDB/LLDB 读取崩溃栈、线程和 core dump。
3. 用 sanitizer 缩小内存、UB 或竞争问题。
4. 加最小回归测试，再修改实现。

Release 产物保留可匹配的调试符号；不要只在 Debug 构建复现性能问题。

## 5. 性能验证

```cpp
TEST_CASE("benchmark parsing") {
    const std::string payload = sample_order_json();
    BENCHMARK("parse order") { return parse_order(payload); };
}
```

基准使用优化构建，固定输入和机器，报告吞吐、P95/P99、分配、锁和系统调用。先用 profiler 找热点，再改算法、数据布局、复制或分配。

## 6. 验收

- [ ] 关键规则有正常、边界和错误测试。
- [ ] ASan、UBSan、TSan 和严格警告进入独立 CI 任务。
- [ ] 能从 core dump、调用栈和 sanitizer 报告定位问题。
- [ ] 性能结论来自优化构建和可复现负载。
