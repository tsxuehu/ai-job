# C++：编译、运行与调试命令

C++ 源文件要经过预处理、编译和链接才能成为可执行程序。单文件练习可以直接调用编译器，企业项目应通过 CMake target 统一编译选项、依赖、测试和安装规则。

## 1. 检查工具环境

```bash
c++ --version
cmake --version
ninja --version
lldb --version   # macOS 常用
gdb --version    # Linux 常用
```

`c++` 通常指向 Clang 或 GCC。团队必须固定编译器、标准库、C++ 标准和关键选项，不能只写“本机能编译”。本机没有 CMake/Ninja 时，直接编译仍可用于学习，但 CMake 工程命令不能执行。

## 2. 单文件编译与运行

```bash
c++ -std=c++20 \
  -Wall -Wextra -Wpedantic -Wconversion \
  -g \
  order_example.cpp \
  -o order_example

./order_example
```

常用参数：

| 参数 | 作用 |
| --- | --- |
| `-std=c++20` | 使用 C++20 |
| `-Wall -Wextra -Wpedantic` | 开启常用警告 |
| `-Wconversion` | 提示可能丢失信息的转换 |
| `-Werror` | 把警告当错误，是否启用由项目决定 |
| `-g` | 生成调试信息 |
| `-O0/-O2/-O3` | 设置优化级别 |
| `-o app` | 指定输出文件 |

调试构建通常使用 `-O0 -g`；性能测试和生产构建使用项目认可的优化级别。不要用 Debug 性能代表 Release，也不要在没有 profile 的情况下盲目使用 `-O3`。

## 3. 分开编译和链接

```bash
c++ -std=c++20 -Iinclude -c src/order.cpp -o order.o
c++ -std=c++20 -Iinclude -c src/main.cpp -o main.o
c++ order.o main.o -o order_api
```

`-c` 只生成目标文件，不链接。最终链接阶段必须提供程序使用的所有目标文件和库：

```text
order.cpp → order.o ──┐
main.cpp  → main.o  ──┼──▶ linker → order_api
third-party library ──┘
```

真实项目不应手写越来越长的编译命令，应把 target、include、编译选项和链接依赖写进 CMake。

## 4. 使用 CMake 构建

单配置生成器的 Debug 构建：

```bash
cmake -S . -B build/debug \
  -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_EXPORT_COMPILE_COMMANDS=ON

cmake --build build/debug --parallel
```

Release 构建：

```bash
cmake -S . -B build/release -DCMAKE_BUILD_TYPE=Release
cmake --build build/release --parallel
```

如果项目提供 `CMakePresets.json`，优先使用仓库固定的 preset：

```bash
cmake --list-presets
cmake --preset debug
cmake --build --preset debug
```

Visual Studio、Xcode 等多配置生成器通常在构建时选择配置：

```bash
cmake --build build --config Debug --parallel
```

不要在同一个构建目录中反复切换不兼容的生成器、编译器或构建类型。

## 5. 运行测试

```bash
ctest --test-dir build/debug --output-on-failure
```

常用方式：

```bash
ctest --test-dir build/debug -N
ctest --test-dir build/debug -R Order --output-on-failure
ctest --test-dir build/debug --repeat until-fail:20 --output-on-failure
```

也可以直接运行测试二进制，以便传入测试框架参数：

```bash
./build/debug/tests/order_test
```

## 6. 使用 LLDB 调试

macOS 常用 LLDB：

```bash
lldb -- ./build/debug/order_api --config config/dev.yaml
```

进入 LLDB 后：

```text
breakpoint set --name main       # 函数断点
breakpoint set --file order.cpp --line 42
run                              # 启动
next                             # 单步，不进入函数
step                             # 单步，进入函数
frame variable                   # 查看当前栈帧变量
print order.amount_cents()       # 求值表达式
bt                               # 当前线程调用栈
thread backtrace all             # 所有线程调用栈
continue                         # 继续运行
quit
```

程序已经运行时可以附加：

```bash
lldb -p <pid>
```

Linux 的 GDB 对应命令通常是：

```bash
gdb --args ./build/debug/order_api --config config/dev.yaml
```

```text
break main
run
next
step
print order
backtrace
thread apply all backtrace
continue
quit
```

## 7. 使用 Sanitizer 找内存和并发错误

ASan + UBSan：

```bash
c++ -std=c++20 -O1 -g \
  -fsanitize=address,undefined \
  -fno-omit-frame-pointer \
  order_example.cpp -o order_asan

./order_asan
```

TSan 单独构建：

```bash
c++ -std=c++20 -O1 -g \
  -fsanitize=thread \
  -fno-omit-frame-pointer \
  worker.cpp -o worker_tsan

./worker_tsan
```

AddressSanitizer 和 ThreadSanitizer 通常不能放在同一个构建中。Sanitizer 需要同时出现在编译和链接选项中；企业项目应通过 CMake option/preset 建立独立构建目录。

## 8. 格式化和静态检查

```bash
clang-format --dry-run --Werror src/order.cpp include/order.hpp
clang-format -i src/order.cpp include/order.hpp
clang-tidy -p build/debug src/order.cpp
```

`clang-tidy` 需要正确的编译参数，通常读取 CMake 生成的 `compile_commands.json`。格式化、编译警告、静态检查和 sanitizer 解决的是不同问题，不能互相替代。

## 9. 性能分析

先生成带优化和符号的构建：

```bash
c++ -std=c++20 -O2 -g order_bench.cpp -o order_bench
time ./order_bench
```

Linux 常用：

```bash
perf record -g ./order_bench
perf report
```

macOS 常用 Instruments 的 Time Profiler、Allocations 和 System Trace。优化前固定输入、构建和环境，先确认热点，再修改代码并重复验证。

## 10. 安装、产物和动态库检查

```bash
cmake --install build/release --prefix dist
file build/release/order_api
```

查看动态库依赖：

```bash
otool -L build/release/order_api # macOS
ldd build/release/order_api      # Linux
```

发布产物要记录编译器、标准库、架构、构建类型、Git 提交和依赖版本。C++ 二进制能否在另一台机器运行，还受 ABI 和动态库版本影响。

## 11. 推荐的日常命令顺序

```bash
cmake --preset debug
cmake --build --preset debug --parallel
ctest --preset debug --output-on-failure
clang-format --dry-run --Werror src/order.cpp include/order.hpp
clang-tidy -p build/debug src/order.cpp
```

提交前再运行项目定义的 ASan/UBSan 构建；修改并发代码时运行 TSan；性能修改使用 Release/profile 构建验证。

## 12. 掌握标准

- 能解释预处理、编译、链接和运行分别发生什么。
- 能用直接编译器命令运行单文件，也能使用 CMake target 构建项目。
- 能区分 Debug、Release、sanitizer 和 profile 构建。
- 能使用 LLDB/GDB 设置断点、查看变量、线程和调用栈。
- 能运行 CTest、clang-format、clang-tidy 和 sanitizer。
- 能检查产物架构、动态库、ABI 和可复现构建信息。
