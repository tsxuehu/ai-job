# C++：变量、数据与类型

C++ 的类型不仅描述数据形状，还经常表达对象是否拥有资源、能否修改以及生命周期关系。

## 1. 基础类型与业务类型

- 布尔：`bool`。
- 整数：`char`、`short`、`int`、`long` 等；协议和存储格式使用 `<cstdint>` 的固定宽度类型。
- 浮点：`float`、`double`；精确金额使用整数最小单位或十进制库。
- 文本：`std::string` 拥有数据，`std::string_view` 只是只读视图。
- 可选值：`std::optional<T>`；不要用 `-1` 或空字符串暗示“没有值”。

```cpp
struct UserId { std::uint64_t value; };
struct OrderId { std::uint64_t value; };

const UserId user_id{42};
std::optional<std::string> nickname;
```

即使底层都是整数，独立业务类型也能阻止把用户编号误传为订单编号。

## 2. 变量、指针和实际数据

C++ 中“变量”和“对象”经常是同一块存储。指针则是另一个值，它保存对象的地址。

### 2.1 值变量直接包含对象

```cpp
struct Order {
    std::string id;
    std::int64_t amount_cents;
};

Order first{"order-1", 100};
```

可以简化理解为：

```text
变量 first，也是一个 Order 对象
┌─────────────────────────┐
│ id: "order-1"           │
│ amount_cents: 100       │
└─────────────────────────┘
```

值赋值通常复制对象：

```cpp
Order second = first;
second.amount_cents = 200;

// first.amount_cents 仍是 100
// second.amount_cents 是 200
```

此时是两个独立的 `Order`。`std::string` 负责复制自己拥有的文本资源，不需要业务代码手动复制字符缓冲区。

### 2.2 指针保存对象地址

```cpp
Order* p = &first;
```

关系是：

```text
变量 p                            对象 first
┌──────────────────┐             ┌─────────────────────────┐
│ first 的地址 ─────────────────▶ │ id: "order-1"           │
└──────────────────┘             │ amount_cents: 100       │
                                 └─────────────────────────┘
```

通过 `*p` 取得所指对象，通过 `p->field` 访问字段：

```cpp
p->amount_cents = 300;

// 等价写法：(*p).amount_cents = 300;
// first.amount_cents 现在也是 300
```

复制指针只复制地址，不复制对象：

```cpp
Order* p2 = p;
p2->amount_cents = 400;

// p、p2 都指向 first
```

裸指针通常只表示“我能访问这个对象”，不说明谁负责销毁它。对象先销毁而指针仍被使用，就会产生悬垂指针和未定义行为。

### 2.3 引用是对象的别名

```cpp
Order& alias = first;
alias.amount_cents = 500;
```

语言语义上，`alias` 是 `first` 的另一个名字：

```text
first ──┐
        ├──▶ 同一个 Order 对象
alias ──┘
```

普通引用初始化后不能改为引用另一个对象，也不应该为空。引用不会复制对象，也不会延长普通对象的生命周期。

### 2.4 动态对象和所有权

```cpp
auto owner = std::make_unique<Order>(Order{"order-1", 100});
Order* observer = owner.get();
```

关系是：

```text
unique_ptr owner ──拥有──▶ 动态 Order 对象
                              ▲
裸指针 observer ──观察────────┘
```

`owner` 离开作用域时销毁对象；`observer` 不负责销毁，也不能在对象销毁后继续使用。现代 C++ 优先使用值、`std::unique_ptr` 和 `std::shared_ptr` 表达所有权，避免手写 `new`/`delete`。

### 2.5 容器变量和底层存储

`std::vector<Order>` 变量通常保存底层数组地址、元素数量和容量，元素数据位于它管理的连续存储中：

```text
vector 变量                       连续元素存储
┌──────────────────┐             ┌────────┬────────┬────────┐
│ 数据地址 ─────────────────────▶ │ Order  │ Order  │ Order  │
│ size            │             └────────┴────────┴────────┘
│ capacity        │
└──────────────────┘
```

vector 扩容后底层地址可能变化，旧的指针、引用和迭代器可能失效。复制 vector 会复制元素；移动 vector 通常把底层存储的所有权转交给新对象。

## 3. 值、引用与指针速查

| 形式 | 主要语义 | 常见用途 |
| --- | --- | --- |
| `T` | 独立值，可能复制或移动 | 小对象、值语义、所有权转移 |
| `T&` | 非空、非拥有、可修改 | 修改调用者对象 |
| `const T&` | 非空、非拥有、只读 | 避免复制大对象 |
| `T*` | 地址可为空，通常不拥有 | 可选观察、底层接口 |
| 智能指针 | 动态对象的所有权 | 独占或共享生命周期 |

引用、裸指针、`string_view` 和 `span` 都不会延长底层对象生命周期。

## 4. const、推断和转换

- `const` 约束通过当前访问路径能否修改对象；区分“指向常量的指针”和“常量指针”。
- `auto` 会按规则丢掉顶层引用或 `const`，需要保留时使用 `auto&`、`const auto&`。
- 避免不受控的隐式窄化、有符号与无符号混算。
- 用 `static_cast` 等显式转换表达意图；类型转换不会自动验证业务范围。

## 5. 复制与移动

值对象被复制后彼此独立；移动把资源转交给新对象。被移动对象仍可析构和重新赋值，但不要继续依赖它原来的业务值。资源类优先遵循 Rule of Zero，让标准类型自动生成正确的复制、移动和析构行为。

## 6. 易错点

- 返回指向局部变量的引用、指针或视图。
- 把无符号整数减到零以下，得到很大的正数。
- 把浮点相等比较用于金额或累计计算。
- 误以为 `std::move` 会移动；它只是把表达式转换为可移动形式。

## 7. 与其他语言对照

| 语言经验 | C++ 中必须修正 |
| --- | --- |
| Java/Python/Node.js 对象引用 | `Order second = first` 通常复制完整值，不只是复制引用 |
| Go 指针 | C++ 裸指针可参与更多底层操作，但所有权和有效期不会自动检查 |
| Java GC | C++ 值对象按作用域析构，动态对象由所有权类型决定销毁 |
| TypeScript readonly | C++ `const` 参与类型系统，但仍要区分对象、指针和访问路径的 const |

## 8. 动手验证

1. 复制和移动 `Order`、`vector<Order>`、`unique_ptr<Order>`，记录哪些写法可编译；
2. 返回局部 `string` 的 `string_view`，用 ASan 观察悬垂访问；
3. 让 `vector` 扩容前后打印 `data()`，验证旧引用为什么失效；
4. 分别声明 `const Order*`、`Order* const`、`const Order* const` 并尝试修改；
5. 给资源类删除手写析构/复制代码，改用标准成员实现 Rule of Zero。
