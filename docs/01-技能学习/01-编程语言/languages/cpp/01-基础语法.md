# C++：基础语法

目标：掌握阅读和编写 C++ 程序所需的最小语法框架，并能把一份源码与预处理、编译、链接后的程序对应起来。

## 1. 程序结构

```cpp
#include <iostream>

int main() {
    const int port{8080};
    std::cout << "listen on " << port << '\n';
    return 0;
}
```

- `#include` 在预处理阶段引入声明；不要把它理解成运行时导入模块。
- 语句通常以分号结束，代码块使用花括号。
- `main` 是普通可执行程序的入口，返回 `0` 表示成功。
- 名称放进 `namespace`，避免大型项目中的命名冲突。

## 2. 声明、定义和初始化

```cpp
int retries{3};                 // 声明、定义并初始化
extern int global_limit;        // 只有声明，定义在其他翻译单元
auto timeout = std::chrono::milliseconds{500};
```

优先使用花括号初始化，它能阻止部分窄化转换。局部变量应靠近使用位置并立即初始化；`auto` 适合右侧类型明显的表达式，不应隐藏关键的精度、单位和所有权。

## 3. 需要认识的语法设施

- `//` 和 `/* */` 是注释；注释解释约束和原因，不复述代码。
- `using` 可以创建类型别名；避免在头文件写 `using namespace ...`。
- `enum class` 提供有作用域的枚举，优于无作用域枚举和魔法数字。
- 属性如 `[[nodiscard]]`、`[[fallthrough]]` 能把意图交给编译器检查。
- 宏只是预处理文本替换，优先使用常量、函数、模板和 `constexpr`。

## 4. 编译基线

学习时至少使用 C++20，并开启高等级警告；警告不是风格提示，而是潜在缺陷线索。需要能区分语法错误、类型错误、链接错误和运行时错误。

## 5. 易错点

- 把声明当成定义，最终得到未定义符号或重复定义。
- 忘记初始化基础类型，随后读取不确定值。
- 宏参数发生重复求值，或宏名称污染其他代码。
- 根据缩进判断作用域，而忽略实际的花括号。

## 6. 订单程序如何变成进程

```text
order.cpp
→ 预处理：展开 include 和条件编译
→ 编译：类型检查并生成目标文件 order.o
→ 链接：解析跨翻译单元符号和库
→ 可执行文件
→ 操作系统装载并进入 main
```

`#include` 只是把声明带进当前翻译单元；实现是否存在，要到链接时才能确认。头文件中的非 `inline` 普通函数被多个翻译单元定义，会违反 One Definition Rule。

```bash
c++ -std=c++20 -Wall -Wextra -Wpedantic order.cpp -o order
```

先看错误发生在哪个阶段：编译器说“不认识类型”和链接器说“找不到定义”，根因完全不同。

## 7. 与其他语言对照

| 语言经验 | C++ 中的差异 |
| --- | --- |
| Java | 不先生成 JVM 字节码；头文件、翻译单元和链接显式存在 |
| Python/Node.js | import 通常是运行时模块机制，`#include` 是预处理文本包含 |
| Go | package 依赖由工具链直接组织；C++ 还要由构建系统定义 target 和链接关系 |

## 8. 动手验证

1. 把函数声明放进 `order.hpp`、定义放进 `order.cpp`、调用放进 `main.cpp`；
2. 漏掉 `order.cpp` 的链接，观察 undefined symbol；
3. 在头文件定义非 inline 函数并被两个 `.cpp` 包含，观察重复定义；
4. 分别制造语法、类型、链接和运行时错误，记录发现阶段；
5. 打开和关闭严格警告，比较编译器能提前发现什么。

## 9. 掌握标准

- 能从入口、声明、表达式和代码块解释一个最小程序。
- 能说明声明与定义、编译期与运行时、宏与函数的区别。
- 能配置严格警告并看懂最常见的编译、链接错误。
