# C++：并发与异步

并发设计先确定任务、共享状态和停止信号的所有者，再选择线程、锁、消息传递或协程。

## 1. 线程与停止

```cpp
std::jthread worker([](std::stop_token token) {
    while (!token.stop_requested()) {
        run_one_task();
    }
});
```

`jthread` 析构时请求停止并等待线程结束，但阻塞 IO、条件变量和业务循环仍需要主动响应停止。线程必须有 join 策略，后台任务不能比依赖对象活得更久。

## 2. 同步工具

| 工具 | 适合场景 |
| --- | --- |
| `mutex` + `lock_guard` | 保护短小共享状态 |
| `scoped_lock` | 按一致方式同时获取多个锁 |
| `condition_variable` | 等待状态变化，始终带谓词 |
| semaphore/latch/barrier | 并发配额或阶段同步 |
| atomic | 简单共享状态、无锁算法基础 |

data race 在 C++ 中是未定义行为。原子变量只能保证该原子操作，不能自动维护多个字段之间的业务不变量；弱内存序必须有明确证明和基准。

## 3. 任务、Future 与协程

- `future/promise` 传递一次性结果，但组合和取消能力有限。
- 线程池必须有有界队列、背压、拒绝和关闭策略。
- 协程只提供保存与恢复状态的语言机制，不自带调度器、事件循环和网络运行时。
- 异步任务要传播截止时间、取消和请求上下文，并隔离阻塞调用。

## 4. 常见故障

- 锁顺序反转造成死锁，在锁内执行阻塞 IO 或用户回调。
- lambda 捕获已经销毁的对象。
- 无界队列让延迟和内存持续增长。
- 停机时先销毁依赖，再等待工作线程结束。

## 5. 有界订单 Worker 必须回答什么

```text
固定 worker 数量
← 有界任务队列（满时阻塞/拒绝）
← 生产者

停止：stop_source/关闭队列
等待：jthread 析构或显式 join
错误：future/result/error sink
依赖：必须活到所有 worker 结束
```

仅仅 `std::async` 或创建 thread 不能建立这些合同。实现前先写下数量、队列容量、背压、取消、错误、等待和关闭顺序。

## 6. C++ 内存模型是正确性边界

两个线程无同步访问同一内存且至少一个写入，就是 data race，行为未定义。mutex unlock/lock、atomic 操作、线程启动/join 等建立规定的 happens-before。`sleep_for` 和“这次能看到”都不是同步证明。

condition variable 要在循环/谓词中等待，因为可能虚假唤醒，且状态必须与同一 mutex 协调：

```cpp
cv.wait(lock, [&] { return stopping || !queue.empty(); });
```

## 7. 协程不是线程池

`co_await` 定义挂起/恢复协议，谁保存 coroutine、在哪个 executor 恢复、如何取消和销毁 frame 由所用库决定。没有理解库的 task 所有权前，不要把 coroutine handle 暴露到业务层。

## 8. 与其他语言对照

| 语言经验 | C++ 中的差异 |
| --- | --- |
| Java thread/virtual thread | C++ 没有统一 managed runtime 替你管理线程和 coroutine scheduler |
| Go goroutine | C++ thread 成本更高，协程不自带调度和网络轮询 |
| Node/Python async | C++ coroutine 是语言机制，事件循环和取消协议来自库 |

## 9. 动手验证

1. 写无界 thread-per-order 与固定 worker pool，比较资源峰值；
2. 制造共享 map data race，用 TSan 定位；
3. 反转两个锁顺序制造死锁，再用统一顺序/scoped_lock 修复；
4. 在异步 lambda 中捕获局部引用，用 ASan 验证悬垂；
5. 模拟 SIGTERM，证明先停生产、再通知、等待、最后销毁依赖。

## 10. 掌握标准

- 能画出线程、队列、共享状态和停止信号关系。
- 能解释 mutex、condition variable、atomic、任务队列和协程的边界。
- 能实现有界任务服务，并用 ThreadSanitizer 检查明显竞争。
