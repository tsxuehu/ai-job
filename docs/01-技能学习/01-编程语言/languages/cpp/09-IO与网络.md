# C++：IO 与网络

> 目标：安全地读取文件、处理字节流、调用网络服务，并正确处理部分读写、超时、输入上限和资源释放。

统一场景：读取订单文件，调用库存 HTTP 服务，再把结果写入数据库。

## 1. 文本、字节与文件

```cpp
std::ifstream input(path, std::ios::binary);
if (!input) {
    throw std::ios_base::failure{"open order file failed"};
}

std::string content{
    std::istreambuf_iterator<char>{input},
    std::istreambuf_iterator<char>{}
};
```

- 文本必须明确字符编码，标准 stream 不会自动解决 Unicode 编码；
- 二进制协议使用字节缓冲，不把对象内存布局直接写入文件；
- 大文件按块处理，不一次性读入全部内存；
- 检查打开、读取、写入、刷新和关闭阶段的失败；
- 文件对象通过 RAII 在离开作用域时关闭。

## 2. 流式读取与部分读写

文件和 socket 的一次 `read/write` 不保证处理完整消息。

```text
协议头：读取固定长度，循环直到够或遇到 EOF
消息体：先校验长度上限，再按长度读取
写出：处理只写入部分字节的情况
```

缓冲可以减少系统调用，但要明确刷新时机。不要用换行符或连接关闭猜测任意二进制消息边界。

## 3. 网络调用

C++ 标准库不提供完整 HTTP client，项目应选择一个主网络库并封装在 adapter 中。

网络调用至少配置：

- DNS、连接、TLS、读取、写入和总体 deadline；
- 取消机制；
- 请求体和响应体大小限制；
- 连接复用与连接池容量；
- 重试次数、退避和幂等条件；
- 半关闭、对端提前断开和部分响应处理。

业务核心只依赖稳定接口，不暴露网络库的 request、buffer 或 error 类型。

## 4. 序列化与外部输入

JSON、Protobuf 等输入都不可信：

- 校验必填字段、范围、数组长度和嵌套深度；
- 金额不要使用无法满足精度要求的浮点表示；
- 明确未知字段和版本兼容策略；
- 解析 DTO 后再转换为领域类型；
- 错误中不要回显密钥和完整敏感输入。

## 5. 数据库 IO

- 使用参数化 SQL，不能拼接外部输入；
- 连接池属于应用级资源，查询结果和事务属于请求级资源；
- 事务明确提交或回滚；
- 设置获取连接、执行和总体超时；
- 流式读取大量结果，避免全部加载；
- 用真实数据库测试事务、锁、索引和驱动行为。

## 6. 常见错误

- 假设一次读取就得到完整消息；
- 忽略编码、字节序、长度和协议版本；
- 把大型响应全部放入一个 `std::string`；
- 没有 deadline，线程永久等待；
- 在公共业务头文件中暴露具体 HTTP/数据库库；
- 关闭只依赖正常路径，异常时泄漏资源。

## 7. 一次订单请求如何穿过 IO 边界

```text
HTTP adapter
→ 限制 body、解析 DTO、校验编码/字段
→ CheckoutService 只接收领域 command
→ InventoryClient adapter 执行有 deadline 的 HTTP
→ Repository adapter 开启事务并执行参数化 SQL
→ 领域结果映射为 HTTP response
```

业务核心不认识 socket、JSON DOM、驱动 row 或 HTTP status。adapter 负责协议和资源，application service 负责编排，领域对象负责不变量。

## 8. IO 等待仍占用资源

同步阻塞网络调用会占住当前线程；异步库/协程可以在等待时释放线程执行其他任务，但连接、buffer、请求对象和 coroutine frame 仍存在。线程池 100、数据库连接 20 时，并发 100 个查询只会让更多任务排队；容量必须一起设计。

## 9. 与其他语言对照

| 语言经验 | C++ 中的差异 |
| --- | --- |
| Java/Go/Node | C++ 标准库没有统一 HTTP/异步网络栈，项目必须固定并封装第三方库 |
| Python | 都需区分 text/bytes；C++ 字符串不自动表达 Unicode 编码 |
| Go Reader/Writer | C++ iostream/第三方 buffer 抽象不同，但部分读写和所有权问题相同 |

## 10. 动手验证

1. 用短读/短写 fake 验证循环是否处理完整消息；
2. 对超长长度字段、错误 UTF-8、截断 JSON 运行 fuzz + sanitizer；
3. 模拟 DNS、连接、TLS、读取和总 deadline；
4. 把连接池设小并逐步增加并发，观察排队和 P99；
5. 在异常路径验证文件、socket、result 和事务全部 RAII 释放。

## 11. 掌握标准

- [ ] 能区分文本、字节、消息和流；
- [ ] 文件与网络路径处理部分读写和 EOF；
- [ ] 外部输入具有大小、深度、字段和精度限制；
- [ ] HTTP/数据库调用具有超时、取消和容量边界；
- [ ] 所有资源通过 RAII 或明确所有者释放。
