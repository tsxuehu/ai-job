# C++：自定义类型、面向对象与抽象

自定义类型的目标不是把字段装进类，而是建立有效状态、行为边界和可替换的依赖契约。

## 1. 面向对象概念映射

| 概念 | C++ 如何实现 |
| --- | --- |
| 对象 | struct/class 的实例，具有存储期、生命周期和值/身份语义 |
| 类 | `struct`/`class` 定义数据布局、构造、析构和成员函数 |
| 封装 | private/protected/public、构造函数、成员函数与模块边界 |
| 继承 | `class Derived : public Base`，同时涉及实现复用与子类型关系 |
| 运行时多态 | 虚函数、抽象基类、类型擦除，通常通过引用/指针使用 |
| 编译期多态 | 函数重载、模板、Concept、CRTP |
| 组合 | 成员对象、RAII 包装和委托，通常优先于继承 |

C++ 完整支持经典面向对象，但“能继承”不等于“应该继承”。只有派生对象能遵守基类契约并安全替换时，才形成正确子类型。

## 2. struct、class 与 enum

- `struct` 与 `class` 能力基本相同，主要区别是默认可见性和默认继承方式。
- 用构造函数建立不变量，使对象一旦构造完成就是有效状态。
- 用 `enum class` 表达有限状态，避免整数和枚举之间的隐式混用。
- 公共字段适合简单数据载体；需要维护约束时通过成员函数控制修改。

```cpp
class Port {
public:
    static std::optional<Port> parse(int value);
    int value() const { return value_; }

private:
    explicit Port(int value) : value_{value} {}
    int value_;
};
```

## 3. 封装、继承与运行时多态

封装是隐藏表示并保护不变量，不等于“所有字段都写 getter/setter”。优先组合；只有存在稳定的 `is-a` 替换关系时才使用继承。

```cpp
class Storage {
public:
    virtual ~Storage() = default;
    virtual std::optional<Value> get(Key key) const = 0;
};
```

基类用于多态删除时需要虚析构函数。运行时多态通过虚函数或类型擦除实现，适合插件和稳定接口边界。

## 4. 模板、Concept 与静态多态

模板在编译期针对具体类型实例化。Concept 为模板参数提供可读约束，能更早暴露不满足接口的问题。

```cpp
template <typename T>
concept Identifiable = requires(const T& value) {
    { value.id() } -> std::convertible_to<std::string_view>;
};
```

模板可能增加编译时间和二进制体积；虚函数有动态分派和间接访问成本。选择依据是扩展边界和测量结果。

## 5. 易错点

- 公共 setter 允许对象进入无效状态。
- 为复用代码建立深继承树，破坏替换原则。
- 多态基类没有虚析构函数。
- 模板接口没有约束，错误在深层实例化中爆发。

## 6. 用支付案例看运行时多态

```cpp
class PaymentGateway {
public:
    virtual ~PaymentGateway() = default;
    virtual Receipt pay(const Order&) = 0;
};

class FakeGateway final : public PaymentGateway {
public:
    Receipt pay(const Order&) override { return Receipt{"test-1"}; }
};

void checkout(Order& order, PaymentGateway& gateway) {
    auto receipt = gateway.pay(order);
    order.mark_paid(receipt.id);
}
```

调用代码只认识基类合同。运行时通过对象的动态类型选择覆盖后的 `pay`。接口按引用传递避免对象切片；虚析构保证通过基类指针销毁派生对象时行为正确。

这里的虚函数调用是“已知 `pay` 合同，运行时选择实现”，不等于按名字查找成员的反射。RTTI、`typeid` 和 `dynamic_cast` 参见 [运行时与性能：RTTI](11-运行时与性能.md#7-rttic-只有有限的运行时类型识别)。

## 7. 同一个问题的静态多态

```cpp
template <typename G>
concept Gateway = requires(G gateway, const Order& order) {
    { gateway.pay(order) } -> std::same_as<Receipt>;
};

template <Gateway G>
void checkout_static(Order& order, G& gateway) {
    auto receipt = gateway.pay(order);
    order.mark_paid(receipt.id);
}
```

模板在实例化时检查约束，适合具体类型在编译期已知的通用算法。虚函数适合稳定运行时扩展边界。选择依据是扩展方式、编译依赖、二进制边界和测量结果，不是“虚函数一定慢”或“模板一定更高级”。

## 8. 组合优先解决什么

日志网关可以持有另一个网关并委托，而不是继承支付宝实现。组合把“使用关系”写成字段，避免基类同时承担代码复用和子类型合同。继承只用于派生类型能在所有基类使用场景中保持契约的 `is-a` 关系。

## 9. 与其他语言对照

| 语言经验 | C++ 中的差异 |
| --- | --- |
| Java | 都支持名义接口和虚分派；C++ 还要处理对象切片、析构和所有权 |
| Go | Go interface 隐式满足；C++ 基类继承显式，也可用模板做结构化约束 |
| Python/TypeScript | 结构化协议更常见；C++ template/Concept 在编译期实例化代码 |

## 10. 动手验证

1. 把 `FakeGateway` 按值赋给 `PaymentGateway` 形参，理解为什么抽象基类阻止或切片；
2. 删除虚析构函数，说明通过基类所有权删除的风险；
3. 分别实现虚函数版和 Concept 版 checkout，比较调用方依赖；
4. 用组合写 `LoggingGateway`；
5. 为 Order 建立构造不变量，证明外部不能直接伪造 paid 状态。
