# C++：表达式与逻辑控制

控制流程本身不复杂，难点在表达式求值、隐式转换和分支遗漏给程序语义带来的影响。

## 1. 表达式

- 算术、比较、逻辑和位运算符具有不同优先级；复杂条件主动加括号。
- `&&` 和 `||` 会短路，可用于先验证指针或范围再访问数据。
- 整数除法会截断；溢出和除零需要在运算前检查。
- 不要在一个复杂表达式里多次读取和修改同一状态。

```cpp
bool valid_port(int port) {
    return port > 0 && port <= 65535;
}
```

## 2. 分支

```cpp
if (!request.valid()) {
    return reject(request);
}

switch (state) {
case State::ready:
    return start();
case State::stopped:
    return Result::ok();
}
throw std::logic_error("unhandled state");
```

`switch` 默认允许贯穿下一分支，只有确实需要时才标记 `[[fallthrough]]`。对 `enum class` 穷举分支时，谨慎添加吞掉所有新枚举值的 `default`。

## 3. 循环

- 遍历容器默认使用 range-for，并根据是否修改选择 `auto&` 或 `const auto&`。
- 需要索引、步长或并行数组时再使用经典 `for`。
- `while` 适合终止条件主导的循环；必须明确状态如何推进。
- `break`、`continue` 和早返回可减少嵌套，但不能让清理逻辑散落在多个出口。

```cpp
for (const auto& task : tasks) {
    if (task.cancelled()) continue;
    process(task);
}
```

RAII 对象能保证所有出口都释放资源，因此“早返回”通常比深层嵌套更容易审查。

## 4. 易错点

- 把赋值 `=` 写成比较 `==`，或依赖复杂的隐式布尔转换。
- `switch` 忘记 `break`，执行意外分支。
- 循环边界少一次或多一次，或用已失效迭代器继续循环。
- 条件中执行有副作用的调用，导致重构时改变行为。

## 5. 用订单状态集中表达分支

```cpp
enum class Status { pending, paid, cancelled };

std::string_view next_action(Status status) {
    switch (status) {
    case Status::pending:   return "pay";
    case Status::paid:      return "ship";
    case Status::cancelled: return "stop";
    }
    std::unreachable(); // C++23；C++20 可抛 logic_error
}
```

有限状态应集中决策并由测试覆盖。新增枚举值时，编译器警告和测试应该迫使调用方处理，而不是被宽泛 `default` 静默吞掉。

## 6. 表达式背后的类型与求值

```cpp
if (order != nullptr && order->amount_cents() > 0) {
    // 左侧为 false 时右侧不执行。
}
```

先确定运算数类型，再判断转换、求值和副作用。特别关注：signed/unsigned 混算、整数提升、窄化、移位边界、除零、溢出和对象是否仍存活。对有符号整数溢出等未定义行为，不能用“这台机器结果看起来正确”作为保证。

## 7. 与其他语言对照

| 语言经验 | C++ 中的差异 |
| --- | --- |
| Java | 都有静态数值类型，但 C++ 存在更多隐式转换和未定义行为边界 |
| Python/JavaScript | 条件不会接受任意对象的动态真值规则；转换应更显式 |
| Go | C++ switch 默认可能贯穿；Go 默认不贯穿 |

## 8. 动手验证

1. 给订单新增 `refunded` 状态，观察没有 `default` 时的编译警告；
2. 混合 `size_t` 和负整数比较，用严格警告解释结果；
3. 用 UBSan 运行有符号溢出和非法移位示例；
4. 分别用 `const auto&`、`auto&` 和 `auto` 遍历订单，观察复制与修改；
5. 把有副作用的复杂条件拆成命名变量，比较可测试性。

## 9. 掌握标准

- 能解释短路、整数运算和隐式转换对分支的影响。
- 能选择清晰的 `if`、`switch` 和循环结构。
- 能用边界值测试覆盖空输入、首尾元素、溢出和未知状态。
