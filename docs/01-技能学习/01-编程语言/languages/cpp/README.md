# C++：从现代语义到生产工程

这套资料面向已经会其他后端语言的开发者。目标是建立对象生命周期、值类别、所有权、泛型和编译模型，并能说明代码何时正确、何时产生未定义行为、成本出现在哪里。

贯穿案例是订单服务：订单值、支付抽象、容器索引、文件和网络资源、并发任务、测试与 CMake 交付。每一章继续同一个案例，避免把指针、模板、RAII 和并发学成互不相关的知识点。

> 示例基线：C++20。先运行[订单示例](../../examples/README.md#可运行订单示例)，再边改边验证。

> 完成后使用 [C++ 分类面试题](../../面试题/cpp/README.md)检查表达，但最终证据应来自编译器、sanitizer、测试和 profile。

## 1. 最终要建立的心智模型

- 一个声明何时只是声明，何时产生定义，最终如何进入翻译单元和链接产物？
- 对象何时开始生命周期，何时结束，谁拥有它？
- 值、引用、指针、迭代器和智能指针分别表达什么关系？
- copy、move、析构和异常展开会调用哪些操作？
- 模板、Concept 和虚函数分别在编译期还是运行时完成多态？
- `vector` 扩容后哪些指针、引用和迭代器失效？
- RAII 为什么同时解决正常返回、异常和提前退出的资源释放？
- 线程共享了什么，停止、等待和异常由谁负责？
- 性能问题来自分配、缓存、分支、锁、系统调用还是错误的算法复杂度？
- 编译选项、ABI、依赖和 CMake target 为什么也是程序正确性的一部分？

## 2. 贯穿案例的增长路线

```text
可运行的 Order 值
→ 构造函数建立不变量
→ 引用参数修改同一个订单
→ PaymentGateway 实现运行时多态
→ template/Concept 表达编译期复用
→ vector/map 管理订单集合
→ exception + RAII 保证失败安全
→ jthread/stop_token 管理并发任务
→ sanitizer/test/profile 提供证据
→ CMake target 和 package manager 形成可交付工程
```

学习 C++ 时始终追踪：对象在哪里不重要，生命周期和所有权更重要；语法看起来合法也不代表行为有定义。

## 4. 从其他语言迁移时要修正的直觉

| 旧直觉 | C++ 中要改成 |
| --- | --- |
| Java/Python 对象变量主要是引用 | C++ 对象可以直接作为值；赋值可能复制或移动整个对象 |
| Go/Java GC 管理对象存活 | C++ 生命周期通常由作用域和所有权类型决定 |
| Node/Python 错误只影响当前调用链 | C++ 未定义行为可能破坏整个进程，甚至表面正常运行 |
| Java 泛型主要是类型检查 | C++ template 会参与实例化、重载解析和代码生成 |
| Go package/Java class 是主要边界 | C++ 还要理解头文件、翻译单元、链接、ODR 和 ABI |

## 6. 每章的学习动作

1. 先编译运行正例；
2. 画对象、引用、所有者和析构顺序；
3. 修改一处代码并预测编译、链接或运行结果；
4. 打开高警告级别和 sanitizer 验证；
5. 对照其他语言，只记录语义差异；
6. 把错误写法、可能后果和安全替代连起来；
7. 完成章节实验和掌握标准。

## 7. 综合实战与证据

实现一个订单 API/Worker 核心库：订单保持有效状态，支付实现可替换，容器没有失效引用，资源由 RAII 管理，并发任务可停止和等待；CMake 分离核心库、adapter、入口和测试。提交以下证据：

- 全警告构建、单元/集成测试；
- ASan、UBSan，涉及并发时运行 TSan；
- 一次异常路径资源安全验证；
- 一次 benchmark/profile 前后对比；
- target 依赖图、ABI/编译选项说明和可复现构建命令。

## 8. 权威资料怎么配合

- [C++ Primer](https://www.informit.com/store/c-plus-plus-primer-9780321714114)：从可运行程序、类型、标准库进入类、泛型和大型程序；
- [C++ Core Guidelines](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines)：用“理由、正反例、替代方案、可执行检查”训练现代 C++；
- [cppreference](https://en.cppreference.com/w/)：项目编码时查询精确语言和标准库语义；
- [CMake Tutorial](https://cmake.org/cmake/help/latest/guide/tutorial/)：建立 target 驱动的构建模型。

教程负责建立路线，Core Guidelines 负责安全规则，reference 用于裁决精确语义；三者不能互相替代。
