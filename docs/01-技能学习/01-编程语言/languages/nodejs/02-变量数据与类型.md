# Node.js / TypeScript：变量、数据与类型

JavaScript 是动态类型语言：变量绑定值，类型属于运行时值。TypeScript 在编译期为这些值建立静态近似模型。

## 1. JavaScript 值

- 原始值：`undefined`、`null`、boolean、number、bigint、string、symbol。
- 对象：普通对象、数组、函数、Date、Map、Set、Buffer 等。
- number 是 IEEE 754 双精度浮点，整数精确范围有限；大整数使用 bigint，金额用整数最小单位或十进制库。
- string 是 UTF-16 code unit 序列，长度不等于用户可见字符数。

## 2. 变量、引用和实际数据

JavaScript 不向普通代码暴露内存地址和指针运算。变量绑定一个值：原始值可以直接理解为值本身，对象值则可以理解为“找到运行时对象的引用”。

### 2.1 原始值赋值会复制值

```ts
let first = 100;
let second = first;
second = 200;
```

关系是：

```text
变量 first              变量 second
┌─────────────┐         ┌─────────────┐
│ number: 100 │         │ number: 200 │
└─────────────┘         └─────────────┘
```

`second` 后来绑定到 200，不影响 `first`。string、boolean、bigint、symbol、undefined 和 null 也属于原始值。

### 2.2 对象变量保存对象引用

```ts
const first = { name: "Alice" };
const second = first;
```

`second = first` 复制引用，没有复制对象：

```text
变量 first ──引用──┐
                   ├──▶ 对象 { name: "Alice" }
变量 second ─引用──┘
```

因此：

```ts
second.name = "Bob";
console.log(first.name); // Bob
```

### 2.3 `const` 限制重新绑定，不冻结对象

```ts
const user = { name: "Alice" };

user.name = "Bob";            // 可以：修改对象
// user = { name: "Carol" };  // TypeScript 报错；JavaScript 运行时也会报错
```

`const` 保护的是变量 `user` 中保存的引用不能被替换，不是让引用指向的对象自动变成不可变对象。

### 2.4 浅复制只创建新的外层对象

```ts
const first = {
  name: "Alice",
  address: { city: "Shanghai" },
};

const second = { ...first };
second.address.city = "Beijing";
```

此时关系是：

```text
first  ──▶ 外层对象 1 ──┐
                         ├──▶ 同一个 address 对象
second ──▶ 外层对象 2 ──┘
```

所以 `first.address.city` 也变成 `Beijing`。需要完全独立的数据时，必须明确复制哪些层；可序列化数据可考虑 `structuredClone`。

### 2.5 `null`、`undefined` 和对象

```ts
let selected: User | null = null;
let result: User | undefined;
```

两者都没有指向 `User` 对象：`null` 通常是程序主动表达“没有对象”，`undefined` 常表示尚未赋值或属性不存在。访问属性前必须收窄：

```ts
if (selected !== null) {
  console.log(selected.name);
}
```

### 2.6 实际对象由 V8 管理

对象、数组、函数、Map、Set 和 Buffer 的具体存储由 V8 与 Node.js 管理。垃圾回收器根据对象是否仍能从变量、闭包、缓存、监听器等位置到达来决定能否回收。代码应依赖“值还是引用、是否仍然可达”，不要假设对象具有稳定的物理地址。

## 3. TypeScript 类型建模

- 优先 `unknown` 接收未知输入，经过校验和收窄后使用。
- 联合类型配合字面量判别字段表达有限状态。
- `type` 可组合联合、映射等类型；`interface` 擅长对象契约和声明合并。
- `readonly` 是编译期约束，不能冻结运行时对象。
- 避免非空断言 `!` 和无证据 `as`，它们不执行校验。

```ts
type Result<T> =
  | { kind: "ok"; value: T }
  | { kind: "error"; error: AppError };
```

## 4. 相等、真值和转换

默认使用 `===`/`!==`，理解 `NaN`、`-0` 和对象引用比较。空字符串、0、NaN、null、undefined 等是假值；默认值只针对 nullish 时使用 `??`。从 HTTP/JSON 进入的数据显式校验，不依赖 `Number()` 等宽松转换。

## 5. 订单对象中引用如何共享

```ts
const first = new Order("order-1", 100);
const second = first;
second.markPaid();

console.log(first === second); // true
```

两个 const 绑定保存同一个对象引用。`const` 只禁止 `first = other`，不会禁止 `first.markPaid()`。函数参数同样按值传递：原始值复制值，对象参数复制引用值。

```ts
function replace(order: Order): void {
  order = new Order("other", 200); // 只改变局部参数绑定
}
```

## 6. TypeScript 类型擦除后的真实边界

```ts
const body: unknown = JSON.parse(text);
```

JSON.parse 返回的运行时对象不会自动成为 Order，也不会执行构造函数。先用 schema/type guard 验证基础数据，再显式创建领域对象。`as Order` 只让编译器相信，不会增加字段或方法。

## 7. 与其他语言对照

| 语言经验 | Node.js / TypeScript 中必须修正 |
| --- | --- |
| C++/Go 值对象 | JS 对象赋值复制引用，不复制对象本身 |
| Java | 引用使用感觉相似，但 TS interface 多数运行时不存在 |
| Python | 都是动态对象，但 JS 有 `undefined`、原型、number/BigInt 等独立规则 |

## 8. 动手验证

1. 比较原始值、对象、Array、Map、Buffer 赋值后的共享；
2. 用展开运算符复制嵌套订单对象，证明只是浅复制；
3. 将 JSON `as Order` 后调用方法，观察运行时结果，再加入 schema；
4. 比较 `Object.freeze`、readonly 和深层可变对象；
5. 验证超过安全整数范围的金额，改用字符串/BigInt/十进制方案。

## 9. 掌握标准

- 能画出原始值变量、对象引用、浅复制和实际对象之间的关系。
- 能区分原始值、对象引用和浅/深复制。
- 能用 unknown、联合类型和收窄表达可靠输入。
- 能识别 number 精度、Unicode、真值、nullish 和错误断言风险。
