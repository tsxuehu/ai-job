# Node.js / TypeScript：自定义类型、面向对象与抽象

TypeScript 同时提供结构类型、interface/type 和 class；设计时要分清编译期契约与 JavaScript 运行时对象模型。

## 1. 面向对象概念映射

| 概念 | Node.js / TypeScript 如何实现 |
| --- | --- |
| 对象 | JavaScript 对象，运行时通过原型链查找属性和方法 |
| 类 | `class` 是原型模型上的运行时语法；interface/type 只参与类型检查 |
| 封装 | 闭包、模块、运行时 `#field`；TS private/protected 主要是编译期约束 |
| 继承 | class `extends` 建立原型链，也可用 interface extends 组合类型契约 |
| 运行时多态 | 方法覆盖、鸭子类型和传入满足行为的对象 |
| 编译期多态 | 结构类型、联合类型、泛型和函数重载签名 |
| 组合 | 对象字段、函数组合和依赖注入，通常优先于 class 继承 |

TypeScript interface 在运行时会被擦除，因此“实现接口”不能完成输入校验、依赖定位或反射注册；这些需要运行时对象、token 或 schema。

## 2. type、interface 与判别联合

- interface 定义对象形状，可 extends 并支持声明合并。
- type 可表达联合、交叉、元组、映射和条件类型。
- 判别联合适合有限状态，通常比布尔字段组合更安全。
- 结构类型意味着形状兼容即可赋值，不要求显式 implements。

```ts
interface Store {
  get(id: TaskId, signal: AbortSignal): Promise<Task | undefined>;
}
```

## 3. class、封装与继承

class 是真实运行时构造器和原型对象。`private`/`protected` 主要由 TypeScript 检查；需要运行时私有使用 `#field`。构造器建立不变量，不要只把 DTO 包装成 getter/setter。

继承基于原型链并支持方法覆盖，但会耦合实现和子类型关系。优先组合依赖与小接口；只在稳定替换关系下继承。多态既可由 class 继承产生，也可由结构接口让无关对象满足同一契约。

## 4. 泛型与抽象边界

```ts
function indexBy<T, K extends PropertyKey>(
  items: readonly T[],
  key: (item: T) => K,
): Map<K, T> { /* ... */ }
```

泛型适合数据结构和算法关系；复杂条件类型会增加编辑器和团队理解成本。外部依赖通过由使用方定义的小接口隔离，运行时输入通过 schema 校验。

## 5. 用支付案例看结构类型多态

```ts
interface PaymentGateway {
  pay(orderId: string, amountCents: number, signal: AbortSignal): Promise<Receipt>;
}

class CheckoutService {
  constructor(private readonly gateway: PaymentGateway) {}

  async checkout(order: Order, signal: AbortSignal): Promise<void> {
    const receipt = await this.gateway.pay(order.id, order.amountCents, signal);
    order.markPaid(receipt.id);
  }
}
```

Fake 不必写 `implements PaymentGateway`，形状兼容即可赋值。运行时对象里没有 PaymentGateway 元数据；调用只是普通属性查找。若依赖注入容器需要 token，必须额外提供 symbol/class/string 等运行时标识。

## 6. class 何时有价值

Order 需要私有状态、构造校验和行为，class 合理；Receipt 只是不可变数据，可用 readonly object/type；有限结果状态更适合判别联合。不要把所有 DTO 都包装成 class，也不要因为 interface 容易写就为每个实现创建一层空抽象。

## 7. 组合比原型继承更清楚

日志、重试和指标网关可以持有 `next: PaymentGateway` 并委托。继承会同时耦合原型实现和子类型合同，只有稳定 `is-a` 关系才使用。运行时真正私有状态使用 `#field` 或闭包，而不是把 TS private 当安全隔离。

## 8. 与其他语言对照

| 语言经验 | TypeScript 中的差异 |
| --- | --- |
| Java | interface 结构兼容且运行时擦除；class 仍是 JavaScript 原型对象 |
| Go | 都可隐式满足小接口；TS 还有联合/交叉/条件类型等编译期运算 |
| Python | 都支持鸭子类型；TS 在编译期做结构检查，Python Protocol 是可选静态层 |
| C++ | TS 泛型不实例化本地机器码，也没有值对象/析构语义 |

## 9. 动手验证

1. 写一个未声明 implements 但满足接口的 fake；
2. 传入运行时缺少 pay 的 JSON 对象，观察类型断言不能保护；
3. 用判别联合替代互相矛盾的布尔状态；
4. 用组合实现 LoggingGateway；
5. 比较 TS private 和 `#private` 编译后的运行时行为。

## 10. 掌握标准

- 能区分 type、interface、class 和运行时对象。
- 能用私有状态、构造校验和组合维护不变量。
- 能解释结构类型、原型继承、接口多态与泛型擦除。
