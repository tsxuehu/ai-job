# Node.js / TypeScript：错误处理

Node.js 同时存在同步 throw、Promise rejection、callback error、EventEmitter `error` 事件和 Stream 错误，必须统一到明确边界。

## 1. 同步与异步错误

```ts
async function load(id: string, signal: AbortSignal): Promise<Task> {
  try {
    return await store.get(id, signal);
  } catch (cause) {
    throw new StorageError(`load task ${id}`, { cause });
  }
}
```

catch 中的值按 `unknown` 处理；错误可能不是 Error。async 函数失败表现为 rejected Promise，调用方必须 await、return 或显式 `.catch`。

## 2. 错误类型与边界

- 使用自定义 Error 子类或判别结果表达稳定类别。
- 设置 `cause` 保留原错误，不靠拼接字符串模拟链。
- HTTP/任务边界集中映射错误、记录一次并清理资源。
- 外部响应不返回堆栈、SQL、文件路径和敏感数据。
- 重试仅针对明确可重试错误，并包含退避和整体截止时间。

## 3. 未处理错误

未处理 rejection 和 uncaught exception 表明控制流失管。顶层处理器用于记录、停止接收、优雅关闭并退出；不要捕获后让未知状态进程无限继续。

EventEmitter 和 Stream 的 `error` 必须被消费。使用 `stream.pipeline` 统一传播错误和清理，而不是手工拼接多个 pipe。

## 4. 取消和超时

AbortSignal 应贯穿 HTTP、数据库和内部任务。超时不是只做 Promise.race：底层操作也必须观察取消，否则工作仍在后台占用资源。

## 5. 订单结算如何保留 cause

```ts
async function checkout(
  order: Order,
  gateway: PaymentGateway,
  signal: AbortSignal,
): Promise<void> {
  try {
    const receipt = await gateway.pay(order.id, order.amountCents, signal);
    order.markPaid(receipt.id);
  } catch (cause) {
    throw new CheckoutError(`pay order ${order.id}`, { cause });
  }
}
```

catch 值保持 unknown；CheckoutError 可以带稳定 code 和 cause。请求/任务边界只记录一次完整链并映射协议。不能用字符串匹配判断错误类别。

## 6. Promise 组合的失败语义不同

| API | 失败行为 |
| --- | --- |
| `Promise.all` | 首个 rejection 使结果 Promise 拒绝，但其他操作不会自动取消 |
| `Promise.allSettled` | 等待全部并返回每项结果 |
| `Promise.any` | 全部失败时抛 AggregateError |
| `Promise.race` | 首个 settle 决定结果，不自动停止其他工作 |

选择组合 API 时同时设计 AbortSignal，否则“上层不等了”不等于资源已经停止。

## 7. 进程级错误边界

uncaught exception 表示没有代码拥有失败；通常应停止接收、等待可控任务、记录并退出，让进程管理器重启。unhandled rejection 同样是失管信号。顶层 handler 不是继续运行未知状态进程的许可证。

## 8. 与其他语言对照

| 语言经验 | Node.js 中的差异 |
| --- | --- |
| Java/Python exception | async 函数错误装进 Promise，必须等待才能进入当前 try/catch |
| Go error | TS 函数类型默认不声明可能 throw 的错误集合 |
| C++ future | 都可能把异步异常存入结果对象，消费者必须取得它 |

## 9. 动手验证

1. 比较 `return promise`、`return await promise` 在 catch/stack 中的行为；
2. Promise.race 做超时后观察底层请求仍运行，再加入 AbortController；
3. 让 EventEmitter 无 error listener，观察进程行为；
4. 使用 pipeline 注入读写错误，确认清理和 cause；
5. 设计 uncaught/unhandled 时的优雅退出演练。

## 10. 掌握标准

- 能统一处理 throw、rejection、EventEmitter 和 Stream 错误。
- 能设计带 cause、稳定类别和协议映射的错误边界。
- 能让超时真正取消底层任务，并制定顶层崩溃退出策略。
