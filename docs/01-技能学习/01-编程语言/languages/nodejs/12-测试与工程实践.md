# Node.js / TypeScript：测试、调试与性能实践

目标：为类型边界、订单规则、异步取消、Stream、真实适配器和性能结论提供可重复的证据。workspace、构建与部署参见 [13-工程化](13-工程化.md)。

## 1. 类型检查不能替代测试

```ts
import assert from "node:assert/strict";
import test from "node:test";

test("rejects non-positive amount", () => {
  assert.throws(
    () => Order.create("o-1", 0),
    InvalidAmountError,
  );
});
```

`tsc` 证明已知源码满足静态约束；测试证明运行时行为；schema 测试证明外部 JSON 符合契约。三者不能互相替代。

## 2. 超时必须测试底层取消

```ts
test("aborts payment after timeout", async () => {
  const signalSeen = Promise.withResolvers<void>();
  const client = {
    pay: async (_order: Order, signal: AbortSignal) => {
      signal.addEventListener("abort", () => signalSeen.resolve(), { once: true });
      await new Promise(() => {});
    },
  };

  await assert.rejects(() => payWithTimeout(client, order, 10));
  await signalSeen.promise;
});
```

异步测试必须等待所有 Promise，并在结束后检查 timer、socket、listener、Stream、worker 和数据库连接是否关闭。

## 3. Stream 和真实 adapter

- 小缓冲和慢消费者验证背压。
- 中途断开验证取消与资源清理。
- 数据库测试使用真实 SQL、migration 和事务语义。
- 契约测试验证运行时 schema 与 TypeScript 类型没有漂移。

## 4. 固定质量命令

```bash
npm run format:check
npm run lint
npm run typecheck
npm test
npm run build
```

脚本名可以不同，但 CI 必须分别执行类型检查、测试和生产构建，不能只运行开发服务器。

## 5. 性能和内存定位

- CPU profile 找同步热点和长任务。
- event-loop delay/utilization 判断事件循环是否被阻塞。
- heap snapshot 看对象保留链，RSS/external/Buffer 指标看堆外内存。
- 活跃 handle、listener 和 worker 数量用于定位资源泄漏。

压测固定 Node、构建、数据和下游容量，同时报告吞吐、P95/P99、错误率、RSS、GC 和 event-loop delay。

## 6. 从风险选择证据

| 风险 | 最合适的证据 |
|---|---|
| 金额和状态规则写错 | Order 单元测试、性质测试 |
| JSON 形状与 TS 类型不一致 | runtime schema 测试、契约测试 |
| SQL、事务、锁行为错误 | 真实数据库集成测试 |
| 超时只返回但没有取消 | 可控 fake server + AbortSignal 断言 |
| Stream 忽略背压或断连泄漏 | 慢消费者、半关闭、资源检查 |
| 事件循环或内存退化 | 固定负载的 benchmark/profile/指标 |

测试层级由风险决定，不要为了“覆盖率”把所有测试都写成 mock 单元测试。

## 7. 异步测试不要依赖 sleep 猜时序

用可控 Promise、barrier、fake server 或测试时钟明确推进时序：

```ts
const started = Promise.withResolvers<void>();
const release = Promise.withResolvers<void>();

const gateway = {
  async pay(): Promise<PaymentReceipt> {
    started.resolve();
    await release.promise;
    return { id: "pay-1" };
  },
};
```

测试先等待 `started.promise`，再断言中间状态，最后调用 `release.resolve()`。这比 `setTimeout(100)` 更快，也不会因机器负载变化而随机失败。

## 8. 与其他语言对照

Node.js 测试特有的重点不是断言语法，而是 event loop 生命周期：遗漏的 Promise、timer、listener、socket 或 worker 会让测试假通过、报未处理 rejection，或使进程不能退出。TypeScript 还必须把 `typecheck` 与运行时测试分开执行。

## 9. 动手验证

1. 为“支付成功才改变订单状态”写单元测试和失败测试。
2. 用 fake server 证明 timeout 后连接确实中止。
3. 用慢 Stream 测背压，用测试结束后的 active handles 检查泄漏。
