# Node.js / TypeScript：基础语法

Node.js 是 JavaScript 运行时，TypeScript 是编译期类型检查层。TypeScript 类型通常会被擦除，生产输入必须在运行时重新校验。

## 1. 最小程序

```ts
const port: number = 8080;

function main(): void {
  console.log(`listen on ${port}`);
}

main();
```

- 语句可省略分号，但自动分号插入存在边界；交给格式化工具统一。
- `{}` 是代码块或对象字面量，含义由语法位置决定。
- 模板字符串支持插值和多行文本。
- JavaScript 按运行时值执行；TypeScript 编译错误不会自动变成线上保护。

## 2. 声明与模块

使用 `const` 表示绑定不再重新赋值，确需重新赋值时用 `let`，不使用函数作用域且有提升问题的 `var`。现代服务优先采用 ESM 的 `import`/`export`，项目统一 module 配置。

```ts
import { readFile } from "node:fs/promises";
export type Config = { port: number };
```

## 3. 常见语法设施

- `?.` 可选链和 `??` 空值合并只处理 `null/undefined`，不要与 `||` 的真值逻辑混淆。
- 解构、展开语法适合浅层数据组合，不会自动深复制。
- `async` 函数一定返回 Promise；调用后必须 await、return 或显式管理。
- `#field` 是 JavaScript 运行时私有字段，TypeScript `private` 主要是编译期约束。

## 4. 工具基线

启用 TypeScript `strict`，统一 formatter、lint、类型检查和测试。不要用 `any` 或大范围类型断言消除诊断；它们把错误推迟到运行时。

## 5. 从 TypeScript 到 Node 进程

```text
order.ts
→ TypeScript 检查类型并生成/准备 JavaScript
→ Node 解析 ESM/CommonJS 模块图
→ V8 编译并执行 JavaScript
→ libuv/Node API 提供定时器、网络、文件等能力
```

当前 Node 可以直接处理一部分可擦除 TypeScript 语法，但它不等于执行完整 `tsc` 类型检查，也不支持所有需要转换的 TS 特性。生产项目仍应把 `typecheck` 作为独立质量门，并明确发布的是源文件还是构建产物。

```bash
tsc --noEmit
node dist/main.js
```

## 6. 三层问题要分开定位

| 层次 | 典型问题 |
| --- | --- |
| JavaScript | 值、闭包、原型、Promise 语义错误 |
| TypeScript | 类型建模、收窄、泛型和声明不正确 |
| Node.js | 模块解析、事件循环、Stream、Buffer、进程资源问题 |

类型检查通过，只说明声明关系成立；不能证明外部 JSON 正确、Promise 已等待、Stream 有背压或事件循环没有被阻塞。

## 7. 与其他语言对照

| 语言经验 | Node.js / TypeScript 中的差异 |
| --- | --- |
| Java | TS 类型多数运行时擦除，不能靠 interface 反射验证对象 |
| Python | 都是动态运行时，但 JS 的值、原型、Promise 和模块规则不同 |
| Go/C++ | import 是运行时模块加载的一部分，不是本地链接模型 |

## 8. 动手验证

1. 编写类型错误但运行路径暂时正常的代码，比较 `tsc` 与 Node；
2. 查看 tsc 输出，确认 interface/type 在 JavaScript 中消失；
3. 混用 ESM/CommonJS 导入，记录 package `type` 和扩展名影响；
4. 分别制造类型检查、模块解析和运行时错误；
5. 固定 Node、TypeScript、module、target 和 strict 配置。

## 9. 掌握标准

- 能区分 Node.js、JavaScript、TypeScript 和类型擦除。
- 能正确使用 const/let、模块、模板字符串和空值运算符。
- 能建立 strict TypeScript 项目并解释编译期与运行时错误。
