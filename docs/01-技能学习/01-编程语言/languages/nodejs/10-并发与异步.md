# Node.js / TypeScript：并发与异步

Node.js 的 JavaScript 默认在一个事件循环线程执行；并发主要来自非阻塞 IO、Promise 调度以及 libuv/操作系统，CPU 密集代码仍会阻塞所有请求。

## 1. 事件循环心智模型

- 同步调用栈必须先清空，事件循环才能处理其他回调。
- Promise reaction 等 microtask 会在特定时机优先排空，递归 microtask 也可能饥饿 IO。
- 部分文件、DNS、加密工作使用 libuv 线程池；线程池大小不是通用并发开关。
- 网络 IO 多由操作系统事件通知，不是每个请求一条 JavaScript 线程。

## 2. Promise 组合

- `Promise.all` 全部成功或一个失败，适合有限且必须全部完成的任务。
- `allSettled` 收集全部结果，`race` 只等待首个 settle，`any` 等首个成功。
- 这些 API 不自动取消剩余操作；取消必须用 AbortSignal 传入底层。
- 对用户输入规模的数组建立并发限制，避免瞬时创建海量 Promise。

下面的订单批次是一个固定小集合。任务失败时，先通知其他任务取消，再等待它们真正结束：

```ts
async function reserveAll(orderIds: string[]): Promise<void> {
  const controller = new AbortController();
  const workers = orderIds.map((id) => reserve(id, controller.signal));

  try {
    await Promise.all(workers);
  } catch (error) {
    controller.abort();
    await Promise.allSettled(workers);
    throw error;
  }
}
```

`AbortSignal` 只是取消通知；`reserve` 必须把它传给 `fetch`、数据库驱动或自己的循环。数量由用户决定时，还要改为有界 worker 队列。

## 3. CPU 任务与多进程

CPU 密集计算放入 worker_threads、child process 或独立服务。worker 可共享/转移二进制内存，但消息、错误、终止和池容量都需设计。多进程用于隔离与利用多核，并不自动共享内存状态。

## 4. 上下文和生命周期

AsyncLocalStorage 可传播请求上下文，但要控制保存内容和边界。每个后台任务要有所有者、结果观察、超时、取消和停机等待。断开客户端后继续生成大响应是一种资源泄漏。

## 5. 有界订单 worker

批量处理订单时，不要先为全部订单创建 Promise。固定数量的 worker 从共享索引取任务，就能把在途操作限制为 `workerCount`：

```ts
async function processOrders(
  orderIds: string[],
  workerCount: number,
  signal: AbortSignal,
): Promise<void> {
  let next = 0;

  async function worker(): Promise<void> {
    while (!signal.aborted) {
      const index = next++;
      if (index >= orderIds.length) return;
      await processOrder(orderIds[index], signal);
    }
    signal.throwIfAborted();
  }

  await Promise.all(
    Array.from({ length: Math.min(workerCount, orderIds.length) }, worker),
  );
}
```

生产代码还要规定：第一个任务失败后是否取消其余任务、是否等待所有 worker 退出、哪些错误可以重试，以及停机时由谁触发根 `AbortController`。

## 6. 一次异步调用如何运行

```text
同步调用栈执行 fetch()
  → fetch 返回 Promise，网络交给 Node/OS
  → 当前调用栈清空
  → 网络完成，回调进入可执行队列
  → Promise reaction 作为 microtask 执行
  → async 函数从 await 后继续
```

`await` 是“暂停这个 async 函数并把控制权还给调用者”，不是新建线程。长时间同步循环仍占住唯一的 JavaScript 执行线程；连续制造 microtask 也会推迟其他 IO 回调。

## 7. AbortSignal 是合作式取消

调用 `controller.abort()` 只发出通知。底层函数必须接收 signal，并在等待 IO、循环或队列操作中响应它。不能接收 signal 的库，需要通过关闭 socket、销毁 Stream 或隔离进程等方式停止工作。

## 8. 与其他语言对照

| 语言 | 主要并发单位 | `await` 的含义 |
|---|---|---|
| Java | 线程、虚拟线程、Future | 等待结果；是否占线程取决于 API/运行时 |
| Python | 线程、进程、asyncio Task | asyncio 中把控制权交回 event loop |
| C++ | 线程、任务、框架 coroutine | coroutine 本身不规定调度器 |
| Node.js | event loop、Promise、worker | 续体稍后由事件循环调度，不创建 JS 线程 |

## 9. 动手验证

1. 分别运行同步死循环、递归 microtask 和定时器，观察哪一个推迟 IO。
2. 对 10 万个订单比较一次性 `Promise.all` 与 10 个 worker 的内存和尾延迟。
3. 超时后检查底层 HTTP/数据库调用是否收到 signal，而不是只检查调用方已返回。

## 10. 掌握标准

- 能解释调用栈、事件循环、microtask、libuv 与 OS IO 的关系。
- 能从源码判断会创建多少 Promise、多少 worker、阻塞在哪里。
- 能正确选择 Promise 组合、并发限制和 AbortSignal。
- 能隔离 CPU 任务并管理 worker/后台任务生命周期。
