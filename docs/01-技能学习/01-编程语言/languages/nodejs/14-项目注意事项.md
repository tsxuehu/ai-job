# Node.js / TypeScript：项目注意事项

目标：把 TypeScript 类型擦除、Node.js 事件循环、异步任务、Stream 和外部资源这些语言特有边界，落实为生产代码规则。

## 1. TypeScript 类型不是运行时校验

```ts
type Input = { timeout: number };

const input = JSON.parse(body) as Input; // 只是断言，没有验证
```

HTTP、JSON、环境变量、数据库和消息输入必须使用运行时 schema 校验。`as`、非空断言 `!` 和 `any` 都不会生成安全检查；DTO 通过校验后再转换为领域类型。

## 2. 事件循环不能被阻塞

- 大 JSON、同步文件 API、复杂正则、加密/压缩和 CPU 循环会阻塞所有请求。
- CPU 工作放 worker_threads、child process 或独立服务，并限制 worker 数量。
- microtask 递归和一次创建海量 Promise 也会让 IO 饥饿。
- 同时观察 event loop delay/utilization、CPU profile、队列和下游时间。

## 3. Promise 必须被管理

```ts
// 错误：forEach 不等待 async 回调
items.forEach(async (item) => process(item));

// 串行
for (const item of items) {
  await process(item);
}
```

需要并发时使用有上限的任务池，不对用户规模输入直接 `Promise.all`。每个 Promise 都要被 await、return 或显式收集；未处理 rejection 表明任务生命周期失管。

## 4. 取消和超时

Promise.race 只能让调用方先返回，不会自动停止底层请求。AbortSignal 必须传到 HTTP、数据库、Stream 和内部任务；客户端断开时取消后续生成。顶层未捕获异常用于记录、停止接收、清理并退出，不应吞掉后继续运行未知状态进程。

## 5. Stream 与背压

- chunk 不等于一条业务消息，协议需要分帧。
- writable 返回 false 时等待 drain；优先使用 pipeline 传播错误与关闭。
- 大文件/模型流不能一次读入内存。
- Stream 错误、取消、半关闭和客户端断连都要清理上下游。

## 6. 模块、this 与资源

- package.json `type`、tsconfig、扩展名和产物统一 ESM/CJS 策略。
- 普通函数的 this 由调用方式决定，方法作为回调可能丢失 this；箭头函数捕获外层 this。
- timer、listener、socket、数据库连接、worker 和长期闭包都可能泄漏。
- Buffer/ArrayBuffer 可能占用堆外内存；heapUsed 不等于进程 RSS。

## 7. 安全专项

- 合并不可信对象时防止 `__proto__`、`constructor` 等键造成原型污染；DTO 先经 schema 转换。
- 用户正则、复杂回溯表达式和超长字符串可能造成 ReDoS，限制模式与输入并做超时/隔离。
- 不使用 `eval`、`new Function` 或拼接 shell 命令执行外部输入。
- URL、重定向和代理目标使用 allowlist，防止 SSRF；上传路径不能逃出允许目录。
- 审查 npm 安装脚本、传递依赖、许可证和 lockfile 变化，CI 使用冻结安装。

## 8. PR 必查

- [ ] 外部输入是否经过运行时 schema，而不是只做类型断言？
- [ ] 是否有同步 CPU/IO 工作阻塞事件循环？
- [ ] Promise 是否全部被等待、收集或观察错误，并设置并发上限？
- [ ] 超时和客户端断开是否真正触发底层 AbortSignal？
- [ ] Stream 是否正确处理背压、分帧、错误和关闭？
- [ ] ESM/CJS、this、listener/timer/worker 生命周期是否明确？
- [ ] 是否监控 event loop、heap/RSS、Buffer、连接和队列？
- [ ] 是否防范原型污染、ReDoS、动态执行、SSRF 和恶意安装脚本？

## 9. 用生产故障检查是否真正理解

### 9.1 TypeScript 没报错，线上却读到 `undefined`

原因通常是把 JSON、环境变量或数据库结果 `as SomeType`。类型断言只影响编译器，运行时对象没有被检查。修复点在输入边界：先把值当 `unknown`，经过 schema 验证再转换。

### 9.2 CPU 不高，订单接口 P99 却突然升高

同时看 event-loop delay、连接池等待、下游耗时和队列。可能是大量短 microtask、连接池饱和或下游排队；只看平均 CPU 会漏掉这些等待。

### 9.3 timeout 已返回，数据库仍在执行

`Promise.race` 只决定哪个结果先返回，不能取消输掉的 Promise。需要把同一个 AbortSignal/deadline 传进驱动；若驱动不支持取消，就要通过连接或进程边界制定停止策略。

### 9.4 heapUsed 稳定，RSS 却持续上涨

检查 Buffer/ArrayBuffer、native addon、线程栈和其他堆外分配，同时观察 `external`、`arrayBuffers`。这不是增加 V8 heap 上限能解决的问题。

## 10. 专家级练习

1. 实现一个订单批处理器：固定并发、首错取消、等待全部 worker 退出、支持停机。
2. 实现一个大文件导入：正确分帧、schema 校验、背压、事务边界和中途断连。
3. 制造 listener、Buffer、未取消 fetch 三类泄漏，分别用 heap、RSS 和 active handle 证据定位。
4. 从源码解释一次请求会创建哪些 Promise、占用哪些外部资源、在哪里恢复执行、如何结束。

## 11. 掌握标准

- 能明确区分 TypeScript 编译期保证与 JavaScript 运行时事实。
- 能从调用栈、event loop、microtask、libuv 和 OS IO 解释异步行为。
- 能为 Promise、Stream、worker、timer、listener 和连接指定所有者与关闭路径。
- 能用指标与 profile 区分 CPU、event-loop、堆内、堆外和下游容量问题。
- 能把上述边界落实到评审清单、测试、发布和停机流程。
