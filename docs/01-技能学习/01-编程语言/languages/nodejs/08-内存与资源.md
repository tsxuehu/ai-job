# Node.js / TypeScript：内存与资源

V8 的 GC 回收不可达 JavaScript 对象，但 socket、文件、Stream、定时器、监听器、数据库连接和后台 Promise 仍需显式生命周期。

## 1. V8 内存

- JavaScript heap 保存普通对象，分代 GC 处理短命与长期存活对象。
- Buffer 的数据可能位于堆外，process RSS 不等于 heapUsed。
- 闭包、全局 Map、无界缓存、事件监听器和未完成 Promise 可持续保留对象。
- 大量短命对象和大对象复制会增加 GC 与内存压力。

观察 heapUsed、external、arrayBuffers、RSS、GC、对象保留链和增长趋势，不能只设置更大的 `--max-old-space-size`。

## 2. 资源生命周期

- 文件句柄、数据库连接/事务、HTTP 响应、Stream 按 API 契约关闭或销毁。
- timer/interval 在结束或取消时 clear。
- EventEmitter 监听器在作用域结束时移除。
- worker/child process 支持终止、等待和错误传播。
- 使用 `finally` 或框架生命周期钩子确保异常路径清理。

```ts
const timer = setTimeout(onTimeout, timeoutMs);
try {
  return await operation();
} finally {
  clearTimeout(timer);
}
```

## 3. 诊断

Heap snapshot 看对象和保留路径，allocation profile 看分配热点，process/系统指标看 native/Buffer/连接资源。拍快照可能暂停进程并占用额外内存，生产环境要有安全方案。

## 4. 用订单请求看对象与资源

一次订单请求会同时产生两类东西：

```text
JavaScript 对象                    外部资源
Order、DTO、Error、闭包      →     socket、timer、数据库连接、Stream
         │                              │
         └─ 不再可达后由 GC 回收         └─ 必须按 API 契约关闭或取消
```

GC 只回答“这个 JavaScript 对象以后还能不能被找到”，不会替你提交事务、归还连接或中止 HTTP 请求。因此资源的所有者必须清楚：

```ts
async function loadOrder(id: string, signal: AbortSignal): Promise<Order> {
  const client = await pool.connect();
  try {
    const row = await queryOrder(client, id, signal);
    return toOrder(row);
  } finally {
    client.release();
  }
}
```

`Order` 何时回收由可达性决定；`client` 何时归还则由 `finally` 决定。这是内存管理与资源管理的根本区别。

## 5. 为什么对象会一直活着

只要能从 GC root 沿引用找到对象，对象就不会被回收。常见 root 包括全局变量、当前调用栈、模块缓存和仍活跃的 native handle。

```ts
const orders = new Map<string, Order>();

function remember(order: Order): void {
  orders.set(order.id, order); // 不删除时，Map 会永久保留 Order
}
```

监听器和闭包也是引用。把请求对象捕获进长期 listener，即使请求早已结束，对象仍然可达。排查时在 heap snapshot 中看 retaining path，不要仅凭“这里已经 return 了”判断对象会回收。

## 6. 与其他语言对照

| 语言 | 普通对象 | 文件、连接等资源 |
|---|---|---|
| C++ | 作用域、RAII、智能指针 | 优先由 RAII 析构释放 |
| Java/Python/Node.js | GC 或引用计数负责普通对象 | 仍需 `try/finally`、上下文管理或显式关闭 |
| Node.js 特别注意 | V8 heap 之外还有 Buffer/native 内存 | 活跃 handle 还可能让进程无法退出 |

## 7. 动手验证

1. 循环创建大 Buffer，同时打印 `heapUsed`、`external` 和 `rss`，观察三者差异。
2. 向全局 Map 持续加入订单，再删除一半；比较两次 heap snapshot 的保留路径。
3. 故意不清理 interval 或 listener，观察测试进程为何不能正常退出或产生警告。

## 8. 掌握标准

- 能画出订单请求中的对象引用图和资源所有权图。
- 能区分 JS heap、Buffer/堆外内存与 RSS。
- 能通过 retaining path 解释闭包、监听器、timer、缓存和未完成任务泄漏。
- 异常、超时和停机时能清理连接、流与后台资源。
