# Node.js / TypeScript：容器与迭代

JavaScript 集合强调动态性；TypeScript 可以约束元素类型，但不会冻结对象、保证键合法或提供并发安全。

## 1. 常用集合

| 类型 | 适合场景 | 关键点 |
| --- | --- | --- |
| `Array<T>` | 默认有序序列 | 动态长度，方法有原地/返回新数组之分 |
| `Map<K, V>` | 任意类型键、明确键值 API | 保持插入顺序 |
| `Set<T>` | 去重与成员判断 | 对象按引用身份判断 |
| plain object | JSON 风格记录、固定字段 | 原型和字符串/symbol 键语义 |
| `WeakMap/WeakSet` | 不阻止对象键被回收 | 不可枚举，适合附加元数据 |
| `Buffer/TypedArray` | 二进制和固定元素宽度 | 与底层 ArrayBuffer 共享关系 |

`Record<string, T>` 是编译期类型，不保证任意字符串键运行时都存在；查询时仍需处理 undefined。

## 2. 迭代方式

- `for...of` 遍历 Iterable 的值。
- `for...in` 遍历对象可枚举属性键，需考虑原型属性。
- map/filter 返回新数组，sort/reverse/splice 等可能原地修改。
- async iterable 使用 `for await...of`，可自然表达流式数据。

```ts
for await (const chunk of stream) {
  await sink.write(chunk);
}
```

并发异步映射需要限制并发，不能对巨大数组直接 `Promise.all`。流数据优先使用 Stream/AsyncIterable，并保持背压。

## 3. 订单索引中的身份语义

```ts
const orders = new Map<string, Order>();
orders.set(order.id, order);
```

字符串按值作为 key；对象 key 按引用身份判断，两个字段相同的 `{ id: "1" }` 仍是不同 key。业务索引通常使用稳定的 string/number/symbol key，避免把临时对象当身份。

## 4. AsyncIterable 与 Stream 的关系

```ts
for await (const order of source) {
  await processOrder(order);
}
```

逐项 await 会自然限制消费速度，但具体 Node Stream 是否处于正确模式、错误和取消如何传播仍要看 API。处理字节流优先 `pipeline`，它会统一背压、错误和关闭；不要混用 `data` 事件、pipe 和 async iteration 造成多种消费模式。

## 5. Array 方法要分清复制和原地修改

`map/filter/toSorted` 返回新数组，`sort/reverse/splice` 修改原数组。即使新建数组，元素对象仍然共享。TypeScript `readonly T[]` 只提供编译期只读视图，不冻结元素和运行时数组。

## 6. 与其他语言对照

| 语言经验 | Node.js / TypeScript 中的差异 |
| --- | --- |
| Java HashMap | JS Map 对象 key 默认按引用身份，没有 equals/hashCode 钩子 |
| Python dict | 两者保持插入顺序，但 Python key 使用 hash/eq，JS Map 对象 key 用身份 |
| Go channel | AsyncIterable 是拉取协议，不等于跨 goroutine 通信 |
| C++ ranges | 都能惰性遍历；JS 对象由 GC 管理，没有迭代器悬垂同类合同 |

## 7. 动手验证

1. 用两个相同字段对象作为 Map key，观察身份结果；
2. 比较 sort 与 toSorted 对调用者数组的影响；
3. 对百万订单使用 Promise.all，再改成 async iterable + 并发限制；
4. 用 pipeline 处理慢 sink，观察背压；
5. 用 WeakMap 附加元数据，理解为何不可枚举。

## 8. 掌握标准

- 能根据键类型、顺序、去重和二进制需求选择集合。
- 能区分原地与非原地数组操作、for-in 与 for-of。
- 能正确迭代异步流并限制并发和内存占用。
