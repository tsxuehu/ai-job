# Node.js / TypeScript：编译、运行与调试命令

Node.js 直接执行 JavaScript；TypeScript 的类型检查和转译属于构建阶段。必须分清 `node`、TypeScript compiler、package manager 和项目 scripts 各自负责什么。

## 1. 检查运行时和项目环境

```bash
node --version
npm --version
node -p 'process.execPath'
node -p 'process.versions'
```

查看当前 package：

```bash
npm pkg get name type scripts engines
npm config get registry
```

项目应通过 `package.json`、lockfile 和版本管理方案固定 Node.js 与 package manager 版本，开发、CI 和生产使用同一主版本。

## 2. 安装依赖

开发时按 `package.json` 更新 lockfile：

```bash
npm install
```

CI 或干净环境按 lockfile 精确安装：

```bash
npm ci
```

添加依赖：

```bash
npm install fastify
npm install --save-dev typescript
```

查看依赖：

```bash
npm ls --depth=0
npm explain fastify
npm outdated
```

`npm ci` 要求 lockfile 与 `package.json` 一致，并会重建 `node_modules`，适合可复现构建；不要在 CI 中用普通 install 隐式修改锁文件。

## 3. 运行 JavaScript 和 TypeScript

运行 JavaScript：

```bash
node src/main.js
node --env-file=.env src/main.js
```

Node.js 24 可以直接执行仅包含可擦除类型语法的 `.ts` 文件：

```bash
node src/main.ts
```

这不等于 TypeScript 类型检查，也不保证支持项目需要转译的全部 TypeScript 特性、tsconfig path alias 或构建插件。企业项目仍应明确执行：

```bash
npm run typecheck
npm run build
node dist/main.js
```

典型 scripts：

```json
{
  "scripts": {
    "dev": "node --watch src/main.ts",
    "typecheck": "tsc --noEmit",
    "build": "tsc -p tsconfig.build.json",
    "start": "node dist/main.js",
    "test": "node --test"
  }
}
```

运行时使用：

```bash
npm run dev
npm run typecheck
npm run build
npm start
```

## 4. 测试和覆盖率

使用 Node.js Test Runner：

```bash
node --test
node --test test/order.test.js
node --test --test-name-pattern='checkout'
node --test --experimental-test-coverage
```

如果项目封装了测试框架，统一使用 package scripts：

```bash
npm test
npm run test:unit
npm run test:integration
```

测试 TypeScript 时，具体执行方式取决于 Node 版本和项目的转译/加载方案；不能假设编辑器能识别类型，测试进程就一定能加载同一份源码。

## 5. 类型检查、格式和 lint

```bash
npm run typecheck
npm run format:check
npm run lint
```

需要直接调用本地二进制时：

```bash
npm exec -- tsc --noEmit
npm exec -- eslint .
```

CI 要分别运行 typecheck、lint、test 和 production build。TypeScript 类型检查不会验证 HTTP/JSON 的真实内容，运行时 schema 测试仍不可缺少。

## 6. 使用 Inspector 调试

在第一行暂停并等待调试器：

```bash
node --inspect-brk=127.0.0.1:9229 dist/main.js
```

不暂停启动：

```bash
node --inspect=127.0.0.1:9229 dist/main.js
```

然后使用 Chrome DevTools 或 IDE 连接 `127.0.0.1:9229`，可以设置断点、查看作用域、Promise、调用栈和 heap。Inspector 可以执行进程内代码，不能绑定到公网地址。

命令行调试器：

```bash
node inspect dist/main.js
```

常用命令：

```text
cont
next
step
out
pause
watch('order')
repl
backtrace
scripts
quit
```

源码经过 TypeScript/bundler 转换时，要生成并部署正确 source map，否则断点和堆栈会指向产物而不是源码。

## 7. 警告、异常和诊断报告

```bash
node --trace-warnings dist/main.js
node --trace-uncaught dist/main.js
node --unhandled-rejections=strict dist/main.js
```

生成诊断报告：

```bash
node --report-on-fatalerror \
  --report-uncaught-exception \
  --report-directory=./diagnostics \
  dist/main.js
```

报告可能包含环境、路径和运行信息，应按敏感诊断产物保管。

## 8. CPU、heap 和事件循环分析

CPU profile：

```bash
mkdir -p profiles
node --cpu-prof --cpu-prof-dir=profiles dist/main.js
```

heap allocation profile：

```bash
node --heap-prof --heap-prof-dir=profiles dist/main.js
```

观察 GC：

```bash
node --trace-gc dist/main.js
```

这些 profile 可以在 Chrome DevTools 等工具中打开。排查接口变慢时，还要同时观察 event-loop delay、连接池等待和下游耗时；CPU profile 不能解释纯粹的 IO 排队。

## 9. package 和 module 排查

查看 ESM/CommonJS 判断：

```bash
node -p 'require("./package.json").type'
```

查看 module 解析结果：

```bash
node -p 'require.resolve("fastify")'
```

查看 package exports 和依赖来源：

```bash
npm pkg get type exports main
npm explain fastify
```

出现“开发环境能 import、产物不能 import”时，检查 `package.json` 的 `type/exports`、文件扩展名、tsconfig module 设置、构建产物目录和 Node 版本，不要只修改某一条 import 猜测。

## 10. 构建和发布验证

```bash
npm ci
npm run typecheck
npm run lint
npm test
npm run build
node dist/main.js
```

发布 package 前查看实际内容：

```bash
npm pack --dry-run
npm pack
```

应用容器或制品中通常只保留运行产物和生产依赖，但必须确认 source map、运行时 schema、迁移、原生依赖和许可证文件是否按发布策略包含。

## 11. 推荐的日常命令顺序

```bash
npm ci
npm run format:check
npm run lint
npm run typecheck
npm test
npm run build
node dist/main.js
```

开发时可以使用 `npm run dev`，交付前必须验证 production build 和真正的启动命令。

## 12. 掌握标准

- 能区分 Node.js 运行时、TypeScript 类型检查、转译和 package scripts。
- 能正确选择 `npm install` 与 `npm ci`，并查看依赖来源。
- 能运行 JavaScript/TypeScript、测试、类型检查和生产构建。
- 能使用 Inspector、source map、warning trace 和诊断报告。
- 能采集 CPU/heap profile，并结合 event-loop 和下游指标分析。
- 能检查 ESM/CommonJS、exports、构建产物和发布包内容。
