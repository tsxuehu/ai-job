# Python：模块化、依赖与 IO

Python 工程需要同时管理架构模块、import 副作用、可复现环境、流式 IO 和运行时数据校验。

## package 边界与显式组装

Python 允许动态导入和直接访问许多内部对象，因此模块化更多依靠稳定公共 API、依赖规则、类型检查和测试约束。

```text
src/app/task/domain.py
src/app/task/application.py
src/app/task/adapters/http.py
src/app/task/adapters/postgres.py
src/app/bootstrap.py
```

- `__init__.py` 只 re-export 稳定入口，内部名称使用下划线约定并避免跨模块导入。
- domain/application 不导入 Web 框架、ORM、具体 HTTP client 和模型 SDK。
- Protocol 由消费方定义最小端口，adapter 提供实现；bootstrap 显式创建并注入对象。
- import 会执行模块顶层代码，不能在导入时创建连接、启动线程、读取动态配置或注册全部全局状态。
- 出现循环 import 时调整职责、提取稳定概念或反转端口，不通过函数内动态 import 长期掩盖。

一个 Python distribution 可以包含多个业务 package；只有需要独立发布和版本管理时才拆 distribution。不要把所有跨模块内容放进 `common.py` 或全局单例。

## 模块与包

- 一个 `.py` 文件是模块，package 组织多个模块，`pyproject.toml` 描述项目与构建。
- import 首次执行模块顶层代码并缓存模块对象；避免顶层网络、数据库和重初始化。
- 使用绝对导入表达包边界，避免循环导入和修改 `sys.path`。
- `__init__.py` 暴露稳定 API，不把所有内部实现全量 re-export。

```text
project/
├── pyproject.toml
├── src/app/
│   ├── __init__.py
│   └── service.py
└── tests/
```

## 环境与依赖

每个项目使用独立虚拟环境，固定 Python 版本与直接/传递依赖，提交锁定结果。生产安装使用冻结依赖；升级检查许可证、安全公告、兼容性和性能。不要把本机可编辑路径当成部署依赖。

## 文件与文本 IO

- 文本读写显式指定 encoding，协议通常用 UTF-8。
- 大文件逐行/分块处理，不一次 read 全部。
- 区分 str 与 bytes，在系统或协议边界编码/解码。
- 使用 with，处理部分写入、权限、磁盘满和原子替换。

## JSON、HTTP 与数据库

JSON 解析只得到动态对象，使用 schema/model 做字段、类型、大小和语义校验。HTTP client 配置连接/读取/总体超时和连接池；数据库连接、事务、cursor/session 使用上下文管理器。同步库不能直接放进 async 事件循环热路径。

## 验收

- 能区分 module、package、distribution、虚拟环境与部署进程。
- 核心用例无需导入 Web/ORM 具体实现即可测试。
- 公共 API、import 方向和 bootstrap 明确，不依赖顶层副作用与全局单例。
- 能解释 import 执行、缓存、包 API 和循环依赖。
- 新环境可按锁定版本完成安装、测试和运行。
- 文件/HTTP/JSON/数据库边界有编码、校验、超时、容量和关闭策略。
