# Python：企业级项目结构

Python 企业项目需要用 src layout、package API、Protocol、显式组装和工程工具约束动态语言边界，同时隔离同步/异步与外部资源。公共原则参见 [企业级后端项目工程结构](../../../03-实战项目/企业级项目工程结构.md)。

## 推荐结构

```text
repository/
├── pyproject.toml
├── lockfile
├── src/company_app/
│   ├── modules/
│   │   ├── order/
│   │   │   ├── domain.py
│   │   │   ├── application.py
│   │   │   ├── ports.py
│   │   │   ├── public.py
│   │   │   └── adapters/
│   │   │       ├── http.py
│   │   │       ├── postgres.py
│   │   │       └── messaging.py
│   │   └── inventory/
│   ├── platform/
│   │   ├── observability.py
│   │   ├── database.py
│   │   └── config.py
│   └── entrypoints/
│       ├── api.py
│       ├── worker.py
│       └── bootstrap.py
├── contracts/
├── migrations/
├── tests/
│   ├── unit/
│   ├── integration/
│   ├── contract/
│   └── e2e/
├── deploy/
├── ops/
├── docs/
└── tools/
```

小模块不必把每个概念拆文件，可以先使用 `order/domain.py + application.py + adapters.py`。目录用于表达真实职责，不用于模拟大型组织。

## 依赖方向

```text
order.domain
      ▲
order.application ◄── adapters.postgres
      ▲              adapters.messaging
      │
adapters.http
      ▲
entrypoints.bootstrap（显式组装）
```

- domain/application 不导入 FastAPI/Django、ORM、HTTP SDK 和具体模型 client。
- Protocol 由消费方定义，adapter 结构化满足端口。
- bootstrap 创建配置、client、repository 和 service，再注入 entrypoint。
- 模块 import 不启动线程、连接数据库或读取远程配置。
- `public.py` 或谨慎的 `__init__.py` re-export 表达公共 API，其他模块不导入内部文件。

## src layout 与 distribution

- src layout 确保测试使用已安装 package，而不是仓库根目录的偶然 import。
- 一个 distribution 可以包含多个业务 package；确需独立发布和版本才拆 distribution。
- 固定 Python、虚拟环境、直接/传递依赖和构建后端。
- 本地 editable install 只用于开发，部署使用构建出的 wheel/镜像。
- 不通过修改 `sys.path` 或依赖当前工作目录维持 import。

## 同步与异步入口

- API/Worker 可以是不同 entrypoint，共享 domain/application。
- async application 调用异步端口；同步 SDK 通过线程适配，CPU 工作通过进程/native/外部服务。
- entrypoint 使用 TaskGroup、根取消信号和 async context manager 管理生命周期。
- 数据库/HTTP client 由应用作用域拥有，不为每个请求随意新建，也不在 import 时创建。
- 关闭时停止接收、取消任务、等待有限时间并关闭 client/pool。

## 配置与数据边界

- 环境变量先由 schema/model 解析成只读配置，缺失或非法时启动失败。
- HTTP、消息、数据库和模型输出在 adapter 做运行时校验。
- Pydantic/ORM/框架模型不直接充当 domain，转换代码是边界的一部分。
- migration 独立于普通应用启动，生产发布明确执行、校验和兼容窗口。

## 测试组织

- unit：domain、application、错误和纯转换；不启动 Web/数据库。
- integration：真实数据库、迁移、HTTP client 和消息 adapter。
- contract：OpenAPI、事件和模型输出 schema。
- async：超时、取消、TaskGroup、断连和资源清理。
- E2E：关键业务流程和进程优雅停机。
- performance：CPU、tracemalloc、RSS、event-loop delay 和依赖耗时。

## 常见错误

- 全局 views/services/models 分层，业务能力散落。
- `common.py`/`utils.py` 吸收所有无法归属的代码。
- import 时创建 app、连接池、后台任务和全局 client。
- 到处使用 Any、dict 和框架 Model，模块 API 没有稳定类型。
- async 入口调用同步数据库/HTTP/模型 SDK，阻塞事件循环。
- 测试从仓库根目录导入成功，构建 wheel 后却缺包或资源。

## 验收

- [ ] src layout、package API 和依赖方向清楚，无 sys.path 技巧。
- [ ] domain/application 不依赖 Web/ORM/SDK 具体实现。
- [ ] bootstrap 显式组装，同步/异步资源都有上下文生命周期。
- [ ] 外部数据运行时校验，框架模型不穿透 domain。
- [ ] Python、锁文件、wheel、migration 和部署产物可复现。
- [ ] 单元、异步、集成、契约和性能测试职责分离。
