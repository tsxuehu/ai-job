# Python：内存与资源

Python 实现通常结合引用计数和循环垃圾回收管理对象，但资源释放不能只依赖对象最终何时被回收。

## 对象生命周期

- 名称和容器持有对象引用；对象无引用后通常可回收。
- 循环引用由 GC 辅助处理，但回收时机不是业务契约。
- `__del__` 有循环、异常和解释器退出问题，不作为主要资源管理方式。
- 模块全局、缓存、闭包、线程和长期任务会让对象持续可达。

不同 Python 实现的回收时机可能不同，因此“在 CPython 上立即关闭”不能作为可移植设计。

## 上下文管理器

```python
with path.open(encoding="utf-8") as stream:
    return parse(stream)
```

`with` 通过 `__enter__/__exit__` 管理文件、锁、事务和临时状态；异步资源使用 `async with`。多个动态资源使用 `contextlib.ExitStack`/`AsyncExitStack`。

生成器、HTTP 响应、数据库 session/cursor、线程/进程池和异步 client 都要按契约关闭。异常和取消路径也必须执行清理。

## 可变性与内存保留

小切片通常创建新 list，但内层对象仍共享；缓存需要容量和淘汰策略。队列、任务集合和结果列表无界增长是常见逻辑泄漏。

使用 tracemalloc 比较分配快照，memory profiler/系统指标观察进程和 native 扩展内存；Python heap 不等于 RSS。

## 验收

- 能解释引用、循环 GC、可达性和回收时机边界。
- 能用 with/async with/ExitStack 管理同步与异步资源。
- 能定位缓存、任务、闭包、队列和 native 内存保留问题。
