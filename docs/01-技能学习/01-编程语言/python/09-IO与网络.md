# Python：IO 与网络

> 目标：处理文本、字节、文件、HTTP、JSON 和数据库时，明确编码、流式读取、超时、同步/异步边界、输入限制和资源关闭。

统一场景：读取订单文件，调用库存 HTTP 服务，再把订单写入数据库。

## 1. str、bytes 与编码

```python
data: bytes = text.encode("utf-8")
text_again: str = data.decode("utf-8")
```

- `str` 是 Unicode 文本，`bytes` 是字节；
- 只在文件、网络和协议边界编码/解码；
- 明确 UTF-8 等编码，不依赖平台默认值；
- 网络分块不等于完整消息；
- 非法字节如何处理必须有明确策略。

## 2. 文件与流式处理

```python
with path.open("r", encoding="utf-8") as input_file:
    for line in input_file:
        parse_order(line)
```

- 大文件逐行或分块处理，不一次 `read()` 全部；
- 使用 `with` 确保异常时也关闭；
- 写文件处理权限、磁盘满、flush 和原子替换；
- 二进制文件使用 `rb/wb`；
- 对行长、总大小和压缩解压后的大小设置上限。

## 3. HTTP：同步和异步不能混用

异步入口应使用异步客户端：

```python
async def load_inventory(client: AsyncClient, url: str) -> Inventory:
    response = await client.get(url, timeout=2.0)
    response.raise_for_status()
    return parse_inventory(response.json())
```

- 复用 client 和连接池；
- 配置连接、读取和总体业务 deadline；
- 限制响应体和并发量；
- 正确传播 asyncio 取消；
- 只对幂等操作和临时错误重试；
- 同步 SDK 放进 async 热路径会阻塞事件循环，应换异步实现或显式线程适配。

## 4. JSON 与运行时校验

```python
value: object = response.json()
request = CreateOrderRequest.model_validate(value)
```

类型标注不会自动验证外部数据。需要 schema/model 校验字段类型、必填项、长度、金额精度、时间格式、未知字段和版本，再转换为领域对象。

避免让无约束的 `dict[str, Any]` 穿过所有业务层。

## 5. 数据库

```python
async with pool.acquire() as connection:
    async with connection.transaction():
        await connection.execute(sql, order_id, total)
```

- pool 是应用级资源；connection/transaction/cursor 是操作级资源；
- 使用参数化 SQL；
- 上下文管理器保证释放和回滚；
- 配置池容量、获取超时和查询 deadline；
- 大结果集使用 cursor/流式迭代；
- ORM 不能消除 N+1、事务、锁和索引问题。

## 6. 常见错误

- 混淆 str 和 bytes；
- 未指定 encoding；
- 大文件或响应无上限读入内存；
- async 函数调用同步 HTTP/数据库 SDK；
- 类型注解代替运行时校验；
- 文件、client、connection、cursor 或 Task 没有明确所有者。
