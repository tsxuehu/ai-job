# Node.js / TypeScript：项目特性与注意事项

这篇汇总 Node.js/TypeScript 项目最重要的特殊边界：TypeScript 类型会擦除，JavaScript 运行在事件循环上，异步任务、Stream 和外部资源必须主动限流与取消。

## TypeScript 类型不是运行时校验

```ts
type Input = { timeout: number };

const input = JSON.parse(body) as Input; // 只是断言，没有验证
```

HTTP、JSON、环境变量、数据库和消息输入必须使用运行时 schema 校验。`as`、非空断言 `!` 和 `any` 都不会生成安全检查；DTO 通过校验后再转换为领域类型。

## 事件循环不能被阻塞

- 大 JSON、同步文件 API、复杂正则、加密/压缩和 CPU 循环会阻塞所有请求。
- CPU 工作放 worker_threads、child process 或独立服务，并限制 worker 数量。
- microtask 递归和一次创建海量 Promise 也会让 IO 饥饿。
- 同时观察 event loop delay/utilization、CPU profile、队列和下游时间。

## Promise 必须被管理

```ts
// 错误：forEach 不等待 async 回调
items.forEach(async (item) => process(item));

// 串行
for (const item of items) {
  await process(item);
}
```

需要并发时使用有上限的任务池，不对用户规模输入直接 `Promise.all`。每个 Promise 都要被 await、return 或显式收集；未处理 rejection 表明任务生命周期失管。

## 取消和超时

Promise.race 只能让调用方先返回，不会自动停止底层请求。AbortSignal 必须传到 HTTP、数据库、Stream 和内部任务；客户端断开时取消后续生成。顶层未捕获异常用于记录、停止接收、清理并退出，不应吞掉后继续运行未知状态进程。

## Stream 与背压

- chunk 不等于一条业务消息，协议需要分帧。
- writable 返回 false 时等待 drain；优先使用 pipeline 传播错误与关闭。
- 大文件/模型流不能一次读入内存。
- Stream 错误、取消、半关闭和客户端断连都要清理上下游。

## 模块、this 与资源

- package.json `type`、tsconfig、扩展名和产物统一 ESM/CJS 策略。
- 普通函数的 this 由调用方式决定，方法作为回调可能丢失 this；箭头函数捕获外层 this。
- timer、listener、socket、数据库连接、worker 和长期闭包都可能泄漏。
- Buffer/ArrayBuffer 可能占用堆外内存；heapUsed 不等于进程 RSS。

## PR 必查

- [ ] 外部输入是否经过运行时 schema，而不是只做类型断言？
- [ ] 是否有同步 CPU/IO 工作阻塞事件循环？
- [ ] Promise 是否全部被等待、收集或观察错误，并设置并发上限？
- [ ] 超时和客户端断开是否真正触发底层 AbortSignal？
- [ ] Stream 是否正确处理背压、分帧、错误和关闭？
- [ ] ESM/CJS、this、listener/timer/worker 生命周期是否明确？
- [ ] 是否监控 event loop、heap/RSS、Buffer、连接和队列？
