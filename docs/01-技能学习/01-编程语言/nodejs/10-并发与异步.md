# Node.js / TypeScript：并发与异步

Node.js 的 JavaScript 默认在一个事件循环线程执行；并发主要来自非阻塞 IO、Promise 调度以及 libuv/操作系统，CPU 密集代码仍会阻塞所有请求。

## 事件循环心智模型

- 同步调用栈必须先清空，事件循环才能处理其他回调。
- Promise reaction 等 microtask 会在特定时机优先排空，递归 microtask 也可能饥饿 IO。
- 部分文件、DNS、加密工作使用 libuv 线程池；线程池大小不是通用并发开关。
- 网络 IO 多由操作系统事件通知，不是每个请求一条 JavaScript 线程。

## Promise 组合

- `Promise.all` 全部成功或一个失败，适合有限且必须全部完成的任务。
- `allSettled` 收集全部结果，`race` 只等待首个 settle，`any` 等首个成功。
- 这些 API 不自动取消剩余操作；取消必须用 AbortSignal 传入底层。
- 对用户输入规模的数组建立并发限制，避免瞬时创建海量 Promise。

## CPU 任务与多进程

CPU 密集计算放入 worker_threads、child process 或独立服务。worker 可共享/转移二进制内存，但消息、错误、终止和池容量都需设计。多进程用于隔离与利用多核，并不自动共享内存状态。

## 上下文和生命周期

AsyncLocalStorage 可传播请求上下文，但要控制保存内容和边界。每个后台任务要有所有者、结果观察、超时、取消和停机等待。断开客户端后继续生成大响应是一种资源泄漏。

## 验收

- 能解释调用栈、事件循环、microtask、libuv 与 OS IO 的关系。
- 能正确选择 Promise 组合、并发限制和 AbortSignal。
- 能隔离 CPU 任务并管理 worker/后台任务生命周期。
