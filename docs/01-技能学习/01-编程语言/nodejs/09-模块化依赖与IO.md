# Node.js / TypeScript：模块化、依赖与 IO

Node.js 工程的常见故障来自架构边界不清、ESM/CommonJS 混用、依赖安装差异、Stream 背压和连接生命周期。

## 模块化与运行时依赖

TypeScript 类型 import 可能在编译后消失，真正的运行时依赖由生成的 JavaScript import、构造对象和全局注册决定。目录分开不代表模块隔离，应为每个业务模块建立唯一公共入口，并禁止深层导入。

```text
src/modules/task/domain
src/modules/task/application
src/modules/task/adapters/http
src/modules/task/adapters/postgres
src/modules/task/index.ts        # 公共 API
src/bootstrap.ts                 # composition root
```

- 核心不导入 Web 框架、ORM 和具体 SDK；adapter 负责运行时校验与数据转换。
- package `exports` 或 lint 规则限制可导入入口，不能依赖另一个模块的内部文件。
- TypeScript interface 会擦除；运行时组装通过构造参数、工厂、token 或具体对象完成。
- 谨慎使用 barrel `index.ts`，大范围 re-export 容易制造隐蔽循环 import 和初始化顺序问题。
- workspace/package 只有在需要独立版本、构建或发布时拆分，不能把每个目录都变成 npm package。

循环依赖在 CommonJS 与 ESM 下表现不同，可能得到未初始化绑定或部分 exports。应修正依赖方向，而不是用动态 import 或全局容器掩盖架构环。

## ESM 与 CommonJS

- ESM 使用 `import/export`，CommonJS 使用 `require/module.exports`。
- package.json 的 `type`、扩展名、tsconfig 与构建输出必须一致。
- ESM 导入解析、顶层 await 和 `__dirname` 替代方式与 CommonJS 不同。
- 不在同一项目随意混用两套语义；第三方互操作先建立小适配层。

## package 与依赖

- 区分 dependencies、devDependencies 和 peerDependencies。
- 提交 lockfile，CI 使用冻结安装，固定 Node 与包管理器版本。
- 审查安装脚本、许可证、维护状态、传递依赖和安全公告。
- package exports 只暴露稳定入口，避免消费者导入内部文件。

## Buffer、Stream 与背压

Buffer 是字节容器，文本转换必须显式编码。不要用 JavaScript string 处理任意二进制，也不要假设一个 chunk 等于一条消息。

Stream 通过 highWaterMark 和写入返回值表达缓冲与背压。优先使用 `pipeline`/`finished`，统一错误、取消和资源关闭；大文件和大响应不要一次性读入内存。

## HTTP、JSON 与数据库

- 外部 JSON 使用 schema 做运行时验证，TypeScript 类型不生效。
- HTTP 设置连接、请求、响应和总体截止时间，限制 body 大小。
- 数据库连接池有容量和获取超时，事务在 finally 中提交/回滚/释放。
- DTO 与领域模型分离，处理版本、未知字段和数字精度。

## 验收

- 能区分 TypeScript 类型依赖与 JavaScript 运行时依赖。
- 每个业务模块有窄公共入口，工具能阻止跨模块深层 import。
- 核心逻辑无需启动 Web/ORM 即可测试，bootstrap 显式组装依赖。
- 能统一 ESM、tsconfig、package exports 和构建输出。
- 能复现依赖安装并说明 direct/transitive 依赖风险。
- 能构建带编码、大小、背压、超时、取消和关闭的 IO 边界。
