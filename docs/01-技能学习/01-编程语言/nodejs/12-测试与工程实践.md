# Node.js / TypeScript：测试与工程实践

TypeScript 服务必须同时验证类型契约、运行时输入、异步失败、资源清理和生产容量。

## 质量门禁

- formatter 与 lint 保持一致风格和 Promise 规则。
- `tsc --noEmit` 在 strict 配置下做独立类型检查。
- 测试、构建、依赖审计和 lockfile 冻结安装进入 CI。
- 固定 Node、包管理器、tsconfig 和 ESM/CJS 策略。

## 测试分层

- 单元测试：纯函数、领域状态、错误映射和 schema。
- 组件测试：HTTP handler、Stream、数据库适配和中间件。
- 集成测试：真实数据库、队列、网络协议和迁移。
- 契约测试：API/事件 schema 与调用方兼容。
- 异步故障测试：超时、取消、断连、部分写入和优雅停机。

测试需要等待所有 Promise 和清理句柄；进程不能退出通常说明 timer、socket、listener 或 worker 泄漏。

## 生产基线

- 所有外部输入运行时校验，错误集中转换。
- 请求、连接、并发、队列、body、Stream 缓冲有上限。
- 外部调用传递 AbortSignal 和整体超时，断连及时取消。
- 记录流量、错误、延迟、饱和度、event loop、GC 和内存指标。
- 捕获终止信号，停止接收、等待有限时间并关闭连接池/worker。

## 综合项目

实现流式任务 API：运行时 schema、数据库、超时与取消、并发限制、Stream 背压、CPU 隔离、优雅停机和指标；补齐单元/集成/断连测试，并分析一次事件循环阻塞或堆增长。

## 最终验收

- [ ] 能独立构建、测试、部署和诊断 TypeScript 服务。
- [ ] 能排查未处理 Promise、事件循环阻塞、连接和内存泄漏。
- [ ] 编译期类型与运行时校验边界明确。
- [ ] 所有后台任务和资源有容量、取消、观测与关闭策略。
