# Node.js / TypeScript 面试题：并发、Stream 与背压

## 1. CPU 密集任务应该放 `worker_threads` 还是子进程？

**答案：** `worker_threads` 适合并行执行 JavaScript CPU 计算，可通过消息传递并在必要时共享内存；子进程隔离更强，可以运行其他程序，崩溃和内存边界也更清晰，但通信更重。无论选哪种，都不能每个请求无限创建，应使用有界工作池并设置队列、超时和过载策略。

## 2. Node.js 只有一个线程吗？

**答案：** JavaScript 业务回调通常运行在事件循环线程，但 Node 进程还包含 V8、垃圾回收和 libuv 等线程。部分文件系统、DNS、加密操作会使用 libuv 线程池，网络 IO 多由操作系统异步机制驱动。因此“异步”不等于“每个操作一个线程”，调整线程池大小也只影响使用该线程池的工作。

## 3. Stream 的背压是什么？为什么不能忽略 `write()` 的返回值？

**答案：** 下游消费慢时，上游必须暂停生产，否则数据会积在内存中。可写流的 `write()` 返回 `false` 表示内部缓冲已达到阈值，上游应等待 `drain`；使用 `pipeline()` 可以组合流并统一传播错误和关闭。忽略背压在小文件测试中可能正常，上线遇到慢客户端就会内存暴涨。

## 4. 为什么数据库请求也要限制并发？

**答案：** 异步 API 让发起请求很便宜，但数据库连接、下游 QPS 和内存都有上限。一次对十万条数据执行 `Promise.all` 会制造巨大排队、占用连接并放大失败。应使用分页、批处理和有界并发，并让应用并发与连接池、超时、重试预算共同设计。
