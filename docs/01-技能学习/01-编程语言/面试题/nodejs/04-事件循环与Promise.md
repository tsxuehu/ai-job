# Node.js / TypeScript 面试题：事件循环与 Promise

## 1. Node.js 的事件循环在解决什么问题？

**答案：** JavaScript 回调主要在一个事件循环线程上执行；网络等异步工作完成后，把后续回调排队等待执行。这样少量线程可以管理大量等待 IO 的连接，但一个长时间执行的 JavaScript 回调会挡住同一进程的所有请求。Promise 回调属于微任务，会在进入后续事件循环阶段前被清空。

## 2. `Promise.all` 是串行还是并行？一个失败后其他任务会停止吗？

**答案：** 传入的异步操作通常已经开始，`Promise.all` 并发等待全部结果；任意一个拒绝时，返回的 Promise 立即拒绝，但其他操作不会自动取消。若失败后必须停止剩余工作，需要给任务传入 `AbortSignal` 或实现显式取消；任务数量很大时还要加并发上限。

## 3. 为什么 `array.forEach(async item => ...)` 经常不符合预期？

**答案：** `forEach` 不等待回调返回的 Promise，外层函数会直接继续，异常也不在预期的等待链中。需要串行时使用 `for...of` 加 `await`；需要全量并发时用 `Promise.all(items.map(...))`；需要受控并发时用任务池或限流器。选择依据是顺序、失败语义和下游容量。

## 4. 未处理的 Promise rejection 为什么危险？

**答案：** 它表示某个异步失败脱离了调用链，业务状态可能已经不确定。所有启动的 Promise 都应被 `await`、返回给调用者或明确附加错误处理；后台任务还要有生命周期所有者。进程级 `unhandledRejection` 监听只用于记录并触发受控退出，不能替代局部正确处理。
