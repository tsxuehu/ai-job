# Node.js / TypeScript 面试题：场景题与项目深挖

## 1. 服务 CPU 没完全打满，但所有接口偶尔同时卡住，怎么查？

**答案：** 先看事件循环延迟和请求时间线，再用 CPU profile 寻找同步热点，重点检查 JSON 编解码、正则、压缩、加密、日志格式化和大循环。总 CPU 是多核平均值，一个事件循环线程满载时总占用可能并不高。确认热点后再拆分计算、流式处理或移到 Worker，并用延迟分位数验证。

## 2. 一次批处理创建了几十万个 Promise，进程内存暴涨，怎么改？

**答案：** 根因通常是任务和结果同时常驻、下游并发失控。将输入分页或流式读取，用固定大小工作池限制在途任务，并及时写出结果；明确单条失败是停止、重试还是记录后继续。并发值应根据连接池、下游限额和压测结果确定，不是越大越快。

## 3. Node.js 服务如何优雅关闭？

**答案：** 收到终止信号后先标记不再就绪并停止接收新请求，再给在途请求、消费者和后台任务一个有限的完成时间；停止拉取新消息，关闭 server、连接池和遥测，超时后强制退出。信号处理要幂等，并在容器终止宽限期内完成。只调用 `process.exit()` 会直接截断异步清理。

## 4. 面试中怎样讲一个 Node.js 性能优化案例？

**答案：** 说明流量、延迟目标和故障现象，用 event-loop delay、profile、trace、堆快照或连接池指标证明瓶颈；解释为何选择流式处理、并发限制、缓存或 Worker，以及其失败边界；最后给出 P95/P99、吞吐、内存或成本变化。不要把“改成 async”本身当成优化结果。
