# Node.js / TypeScript 面试题：工程化、测试与安全

## 1. Node.js/TypeScript 仓库如何划分包和模块？

**答案：** 按订单、支付等业务能力划分高内聚模块，用导出入口限制公开 API；共享代码只放确实稳定的能力，避免形成无边界 `utils`。多个可独立发布的服务或库可用 workspace 管理，但 monorepo 不能替代依赖方向和所有权规则。

## 2. 有 TypeScript 后为什么还要校验 HTTP 输入？

**答案：** 编译后的 JavaScript 不保留大部分 TypeScript 类型，客户端 JSON、环境变量和数据库数据不会因为写了接口就自动正确。边界必须做运行时解析，并把验证后的值转换成内部类型。类型断言 `as Order` 只是告诉编译器相信开发者，不会产生任何检查。

## 3. 异步代码怎样测试才可靠？

**答案：** 测试必须 `await` 被测 Promise，并覆盖成功、拒绝、超时、取消和部分完成。单元测试用可控依赖验证业务规则，集成测试连接真实数据库或协议实现；涉及计时器时可用假时钟，但要明确微任务和 IO 不一定受同一时钟控制。测试结束还应检查未关闭 server、socket 和 timer。

## 4. Node.js 后端常见安全风险有哪些？

**答案：** 包括原型污染、ReDoS、SSRF、路径穿越、命令注入、不安全反序列化和依赖供应链风险。禁止把外部对象无条件合并进配置或查询条件，正则要限制复杂度，出站地址要校验最终解析结果，执行命令优先传参数数组而非拼接字符串，并锁定、审计依赖。
