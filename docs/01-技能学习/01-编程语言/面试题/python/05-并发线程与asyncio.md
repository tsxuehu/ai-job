# Python 面试题：并发、线程与 asyncio

## 1. GIL 是什么？是不是用了线程就完全不能并发？

**答案：** 在常规 CPython 构建中，GIL 使同一解释器内通常只有一个线程执行 Python 字节码，所以 CPU 密集 Python 代码难以靠多线程利用多核。但线程等待网络、文件或某些释放 GIL 的扩展时，其他线程仍可运行，因此 IO 密集工作仍可能受益。GIL 也不等于业务代码线程安全，复合操作和共享状态仍要同步。

## 2. 线程、进程和 asyncio 怎么选？

**答案：** 大量高并发网络 IO 且依赖支持异步协议时选 asyncio；需要调用阻塞库、并发量有限时线程更直接；纯 Python CPU 密集计算通常用多进程或移到原生实现。选择还要考虑隔离、序列化成本、取消方式和团队可维护性，不应只用“IO/CPU”一句话结束。

## 3. `asyncio.TaskGroup` 有什么价值？

**答案：** 它把一组子任务纳入明确的生命周期：退出作用域前等待任务；一个任务发生未处理失败时，取消其余任务并汇总异常。相比随手 `create_task`，结构化并发更不容易留下孤儿任务。取消通过 `CancelledError` 协作传播，清理后通常应继续传播，不应无条件吞掉。

## 4. 在 async 函数中调用阻塞函数会怎样？

**答案：** 普通阻塞函数会占住事件循环线程，在它返回前其他协程也无法前进，表现为所有请求一起延迟。应使用异步客户端；无法替换时可用 `asyncio.to_thread` 隔离短期阻塞工作，并设置并发上限和超时。把 CPU 重任务丢进线程也不一定绕过常规 CPython 的 GIL。
