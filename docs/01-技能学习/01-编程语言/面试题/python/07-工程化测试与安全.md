# Python 面试题：工程化、测试与安全

## 1. 为什么 Python 项目常使用 `src/` 布局？

**答案：** 包放在 `src/project_name` 下，可避免测试时意外从仓库根目录导入未安装源码，从而更接近真实安装后的行为。无论是否使用 `src/`，都应有明确包边界、绝对导入和统一入口，避免依赖当前工作目录及随意修改 `sys.path`。

## 2. 怎样保证依赖和运行环境可复现？

**答案：** 声明支持的 Python 版本和直接依赖，提交由工具生成的锁定结果，在隔离环境中安装，并让 CI 从零构建验证。应用通常需要锁定完整依赖树，库则要给下游保留合理版本范围。不要把本机虚拟环境提交进仓库，也不要只靠一份长期不更新的 `requirements.txt`。

## 3. Python 后端测试应该怎样分层？

**答案：** 纯函数和领域规则用快速单元测试；数据库查询、事务、序列化和框架配置用真实组件的集成测试；少量关键接口做端到端测试。异步测试要等待所有任务并清理 loop 资源。mock 用于稳定边界和故障注入，不应用来证明真实 SQL 或第三方协议兼容。

## 4. Python 中哪些功能不能直接处理不可信输入？

**答案：** 不可信数据不能直接交给 `pickle`、`eval/exec` 或不安全的 YAML 加载器，也不能拼接 shell 命令、SQL 和文件路径。还要防 SSRF、压缩炸弹和超大 JSON。使用安全解析器、参数化 API、白名单、大小与时间限制；数据校验模型不是任意代码执行的防护替代品。
