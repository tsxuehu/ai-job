# Python 面试题：异常、资源与迭代

## 1. `raise ... from ...` 有什么作用？

**答案：** 它在转换异常时显式保留因果链，例如把数据库异常转换为仓储异常，同时让日志仍能看到根因。只写 `raise` 会重新抛出当前异常并保留 traceback；`raise NewError()` 若不管理 cause，调用者可能只看到缺少业务语义或混乱的上下文。边界转换异常时不要丢掉原始原因。

## 2. 上下文管理器解决什么问题？

**答案：** `with` 把获取资源与必定执行的退出逻辑配对，无论代码正常返回还是抛异常都能关闭文件、归还连接或释放锁。对象可实现 `__enter__/__exit__`，也可用 `contextlib` 构建。GC 时间不确定，外部资源不应依赖析构时顺便释放。

## 3. iterable、iterator 和 generator 有什么区别？

**答案：** iterable 能返回迭代器，iterator 保存遍历状态并通过 `__next__` 逐项产出；generator 是用 `yield` 方便创建的 iterator。生成器可按需处理大数据，减少一次性内存，但它通常只能消费一次，并且持有尚未结束的局部状态和资源。

## 4. 异步生成器和异步上下文管理器适合什么场景？

**答案：** 异步生成器用 `async for` 逐批产生需要等待 IO 的数据；异步上下文管理器用 `async with` 管理需要异步获取和释放的连接等资源。消费者提前退出时仍要确保生成器关闭，清理代码应放在 `finally` 中。它们提供异步协议，不会自动增加合理的超时和背压。
