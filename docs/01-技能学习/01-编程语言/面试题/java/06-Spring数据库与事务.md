# Java 面试题：Spring、数据库与事务

## 1. Spring Bean 从创建到可用大致经历什么？

**答案：** 容器读取定义，实例化对象，注入依赖，执行 aware、前后置处理和初始化回调，必要时返回代理对象，关闭时执行销毁回调。理解这一点是为了判断“拿到的是原对象还是代理”“初始化时依赖是否可用”，而不是死背完整回调名单。构造器注入通常最容易保证依赖完整和便于测试。

## 2. 为什么同一个类内调用 `@Transactional` 方法可能不生效？

**答案：** 常见 Spring 声明式事务由代理拦截外部方法调用。`this.createOrder()` 是对象内部直接调用，没有经过代理，事务拦截器就不会执行；`private` 方法也通常无法被代理覆盖。应把事务边界放在清晰的应用服务公开方法上，或拆分职责，而不是依赖自调用技巧。

## 3. 什么是 ORM 的 N+1 查询？怎么确认和处理？

**答案：** 先查一批主对象，再因懒加载对每个对象各查一次关联数据，最终产生 1+N 条 SQL。不能只凭代码猜测，应打开 SQL/指标确认查询次数。可按用例使用 join fetch、实体图、批量加载或 DTO 投影；不要把所有关联都改成 eager，那可能产生更大的笛卡尔积和无用数据。

## 4. `@Transactional` 能保证远程调用和数据库一起回滚吗？

**答案：** 普通本地事务只控制同一事务管理器下的资源，不能撤销已经成功的 HTTP 请求或消息发送。跨边界一致性通常用事务内写 outbox、可靠消息、幂等键和补偿流程。事务还应尽量短，避免在持有数据库连接和锁时执行慢网络请求。
