# Java 面试题：异常、资源与语言机制

## 1. checked exception 和 unchecked exception 怎么使用？

**答案：** checked exception 必须捕获或在签名中声明，适合调用者确实能够处理的可恢复失败；`RuntimeException` 不强制声明，常用于参数错误、状态冲突和编程错误。企业项目不要机械地把所有异常都包装一遍，应在能够增加业务语义或决定恢复策略的边界转换，并保留原始 cause。

## 2. `try-with-resources` 解决了什么问题？

**答案：** 它对实现 `AutoCloseable` 的资源保证逆序关闭，即使业务代码抛异常也会执行。若业务代码和 `close()` 都抛异常，业务异常保留为主异常，关闭异常可通过 `getSuppressed()` 查看。数据库连接、文件和流应优先使用这种结构，不依赖 GC 释放外部资源。

## 3. 反射和注解分别是什么？有什么代价？

**答案：** 注解是附着在代码元素上的元数据；反射让程序在运行时检查类型、字段、方法并调用它们。Spring 等框架用二者完成扫描、依赖注入和代理。代价包括类型错误延迟到运行时、调用路径不直观、原生镜像配置更复杂；热点路径还应避免无缓存的重复扫描。

## 4. `Optional` 应该用在哪里？

**答案：** 它适合作为返回值明确表示“可能没有结果”，迫使调用者处理缺失。不建议把它用作实体字段、方法参数或集合元素，也不要用 `isPresent()` 后立刻 `get()` 模拟空判断。集合没有结果通常直接返回空集合；业务失败应使用异常或明确的结果类型，而不是 `Optional.empty()` 隐藏原因。
