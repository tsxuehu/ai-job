# Java 面试题：场景题与项目深挖

## 1. 线程池队列持续增长，接口越来越慢，怎么处理？

**答案：** 先确认任务进入速率、完成速率、活跃线程、队列长度和下游耗时，区分瞬时流量、下游变慢和任务阻塞。立即保护系统可采用有界队列、超时、拒绝、降级和入口限流；根治要减少慢依赖、拆分不同任务池并建立容量模型。只扩大队列通常只是延后故障。

## 2. JVM 堆曲线稳定，但容器内存不断上涨，可能是什么原因？

**答案：** 重点检查线程栈、直接内存、JNI、本地分配、内存映射和 allocator 未及时归还 OS 的内存。对照 RSS、堆、Metaspace、线程数、direct buffer 指标和 NMT 数据，再做前后快照。不能因为 heap dump 不大就判断“没有内存问题”。

## 3. 支付回调可能重复到达，怎样保证订单不会重复入账？

**答案：** 使用支付平台事件 ID 或业务幂等键建立唯一约束，在同一数据库事务中记录回调并执行合法状态迁移；重复事件读取已有结果后安全返回。若还要发消息，结合 outbox 保证事务提交后可重试发送。进程内锁既挡不住多实例，也挡不住重启后的重复请求。

## 4. 面试中怎样讲一个 Java 项目优化案例？

**答案：** 先交代业务量、SLO 和自己的职责，再给出优化前的可量化现象；说明通过 trace、JFR、GC 日志、SQL 等得到的证据，以及为何选择当前方案；最后给出延迟、吞吐、错误率或资源成本的前后数据，并说明回滚方案和遗留限制。重点是证明判断过程，不是罗列框架名。
