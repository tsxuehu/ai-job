# Java 面试题：并发与 Java 内存模型

## 1. 什么是 happens-before？为什么没有报错也可能有数据竞争？

**答案：** happens-before 是 Java 内存模型规定的可见性和顺序关系，例如解锁先于随后对同一锁的加锁，线程启动前的写入对新线程可见。两个线程无同步地读写同一可变数据，就可能发生数据竞争；单次运行结果正确不能证明程序正确，编译器、CPU 和缓存都可能让另一个线程看到旧值或不同顺序。

## 2. `volatile` 和 `synchronized` 有什么区别？

**答案：** `volatile` 保证该变量读写的可见性和一定的顺序约束，但不能让“读取—计算—写回”整体原子化，所以 `count++` 仍不安全。`synchronized` 同时提供互斥与可见性，适合保护一组关联状态。简单计数可用 `AtomicLong`，复杂不变量通常用锁更清楚。

## 3. 线程池最重要的参数和风险是什么？

**答案：** 要结合任务是 CPU 密集还是 IO 等待，设置线程数、队列容量、拒绝策略、线程命名和关闭流程。无界队列会把过载变成高延迟和 OOM；线程过多会增加上下文切换和内存。提交任务时还要传播或显式重建日志上下文、超时和取消信号。

## 4. 虚拟线程适合什么场景？它会让代码自动变快吗？

**答案：** 虚拟线程适合大量“每请求一线程”的阻塞式 IO 任务，让等待期间不长期占用平台线程。它主要提高并发吞吐和代码可读性，不会让 CPU 计算或单次网络请求更快；数据库连接池、下游限流仍是硬上限，也不应为了复用而池化虚拟线程。需要用目标 JDK 和真实依赖验证固定线程、锁竞争等行为。
