# Java 面试题：集合、泛型与 Stream

## 1. `ArrayList` 和 `LinkedList` 怎么选？

**答案：** 后端项目通常先选 `ArrayList`。它连续存放引用，随机访问快、缓存局部性好；尾部追加的均摊成本低。`LinkedList` 只有在已经拿到节点位置并频繁插删时才有理论优势，按下标查找仍是 O(n)，每个节点还会增加对象和指针开销。

## 2. `HashMap` 为什么不是线程安全的？key 有什么要求？

**答案：** `put`、扩容和桶内结构变化是多个步骤，并发执行没有互斥与可见性保证，可能丢更新或读到不一致状态。key 的 `equals`、`hashCode` 必须一致，参与计算的字段在作为 key 期间不能变化。并发共享通常使用 `ConcurrentHashMap`，但跨多个调用的复合操作仍要用 `compute` 等原子 API 或额外同步。

## 3. Java 泛型为什么说是类型擦除？什么是 PECS？

**答案：** 大部分泛型信息用于编译期检查，运行时通常只保留擦除后的类型，因此不能直接 `new T()`，也不能可靠判断 `obj instanceof List<String>`。PECS 是容器只向外提供值时用 `? extends T`，只接收值时用 `? super T`：Producer Extends，Consumer Super。

## 4. Stream 的优点和常见陷阱是什么？

**答案：** Stream 把过滤、转换、聚合表达成流水线，中间操作惰性执行，终止操作才触发计算。避免在流水线中修改外部状态；不要默认 `parallelStream()` 更快，它使用公共线程池，拆分、合并和上下文切换可能更贵，也可能干扰同进程其他任务。数据库分页、网络调用不能因为写成 Stream 就自动获得合理并发。
