# Java 面试题：工程化、测试与安全

## 1. Java 后端项目应该按技术层还是业务功能组织？

**答案：** 小项目可以从 controller/service/repository 分层开始；规模增大后更适合先按订单、支付、用户等业务功能形成边界，再在功能内部区分接口、应用、领域和基础设施。判断标准不是目录是否整齐，而是一次业务修改能否集中完成，以及模块能否限制不合理依赖。

## 2. 单元测试、集成测试和端到端测试分别测什么？

**答案：** 单元测试验证纯业务规则，速度快、失败定位准；集成测试验证 SQL、序列化、事务和框架配置，应尽量使用与生产一致的真实组件；端到端测试覆盖少量关键链路。不要把所有依赖都 mock 掉后声称数据库功能已验证，也不要让大量慢测试取代细粒度规则测试。

## 3. 一个可维护的 API 错误响应应包含什么？

**答案：** 对调用者返回稳定的业务错误码、可理解的消息和 request/trace id，不泄露堆栈、SQL 或密钥。服务端日志保留异常链和必要上下文；指标按错误类型、接口和依赖聚合。HTTP 状态码表达协议层结果，业务错误码表达具体原因，两者不要互相替代。

## 4. Java Web 项目常见的安全风险有哪些？

**答案：** 除 SQL 注入外，还要关注不安全反序列化、表达式注入、路径穿越、任意文件上传、SSRF、日志注入和存在漏洞的依赖。输入校验不能代替参数化查询；出站网络、文件类型和大小都应设白名单与限制，并通过依赖扫描和及时升级管理供应链风险。
