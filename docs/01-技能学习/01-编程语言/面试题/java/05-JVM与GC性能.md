# Java 面试题：JVM、GC 与性能

## 1. Java 进程的内存只有堆吗？

**答案：** 不是。对象主要在堆中，类元数据通常在 Metaspace；每个线程还有栈，另外还有代码缓存、直接内存、JNI 和 JVM 自身结构。因此“堆使用稳定但进程 RSS 一直涨”不能只看 GC，要检查线程数量、`ByteBuffer`、本地库和内存映射等堆外来源。

## 2. 类加载和 JIT 编译大致做了什么？

**答案：** 类加载经历加载、链接和初始化，并遵循类加载器的可见性规则。字节码先由 JVM 执行，热点方法会被 JIT 编译和优化；运行信息变化时还可能去优化。这解释了为什么基准测试需要预热，也解释了反射、动态类和类加载器泄漏为什么会影响运行时。

## 3. 有 GC 为什么仍会内存泄漏？

**答案：** GC 只能回收不可达对象。对象如果仍被静态集合、缓存、监听器、`ThreadLocal`、未结束任务或类加载器引用，即使业务上已经无用，也不会回收。排查时先确认增长的是堆还是堆外，再比较 heap dump 的对象数量、占用和引用链，最后回到创建与释放路径。

## 4. 线上 CPU 高、频繁 GC、接口慢分别怎么查？

**答案：** 先保留时间线和基础指标，再按症状取证：CPU 高看 JFR/async-profiler 和线程栈；GC 异常看 GC 日志、分配速率和堆转储；接口慢结合 trace、线程池队列、数据库与下游耗时。先区分 CPU、分配、锁等待还是 IO，不要一上来就改 JVM 参数。
