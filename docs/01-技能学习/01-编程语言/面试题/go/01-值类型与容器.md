# Go 面试题：值、类型与容器

## 1. Go 的参数是值传递还是引用传递？

**答案：**

Go 只有值传递。调用函数时，传入的参数会被复制。

- 传 `int`、`string` 或结构体，复制的是值。
- 传指针，复制的是地址，两边仍然指向同一对象。
- 传 slice、map、channel 时，复制的是内部描述信息，其底层数据可能共享。

所以“全部按值传递”与“可以修改共享数据”并不矛盾。

## 2. 数组和 slice 有什么区别？

**答案：**

`[3]int` 是数组，长度是类型的一部分；`[]int` 是 slice，长度可变。

数组赋值和传参会复制全部元素。slice 赋值只复制一份描述信息，两个 slice 可能共享同一个底层数组。

## 3. slice 内部有什么？为什么 `append` 要接收返回值？

**答案：**

slice 可以理解为“底层数组地址 + 长度 + 容量”。`append` 会返回一个新 slice 描述值；如果容量不足，还可能分配新数组。

```go
func add(items []string, item string) []string {
	return append(items, item)
}

items = add(items, "new-order")
```

如果不接收返回值，调用者保存的仍然是旧长度、旧容量和可能的旧数组地址。

## 4. nil slice 和空 slice 有什么区别？

**答案：**

```go
var a []int       // nil slice
b := []int{}      // 非 nil，长度为 0
c := make([]int, 0)
```

它们的 `len` 都是 0，都可以 `range` 和 `append`。主要差别是 `a == nil`，而 `b` 和 `c` 通常不是 nil；在 JSON、API 协议和测试比较中可能呈现不同结果，需要统一边界约定。

## 5. map 的遍历顺序稳定吗？可以并发读写吗？

**答案：**

map 的遍历顺序没有保证，不能依赖。需要稳定输出时，先取 key，排序后再访问。

map 不支持无同步的并发读写或并发写。应使用 `Mutex`/`RWMutex`、单 goroutine 所有权模型，或者在“key 通常只写一次却频繁读取”、“多个 goroutine 操作互不重叠的 key”等适合场景使用 `sync.Map`。`sync.Map` 不是所有 map 的默认替代品。

## 6. `string`、`[]byte` 和 `rune` 有什么区别？

**答案：**

`string` 是不可变的字节序列，不保证内容一定是合法 UTF-8。`[]byte` 是可修改字节序列。`rune` 是 `int32` 的别名，常用来表示一个 Unicode code point。

`len(s)` 返回字节数，不是字符数。`range` 遍历 string 时按 UTF-8 解码为 rune。string 与 `[]byte` 普通转换通常需要复制，热点路径要通过 profile 判断是否值得优化。

## 7. `new` 和 `make` 有什么区别？

**答案：**

`new(T)` 分配一个 T 的零值，返回 `*T`。`make` 只用于 slice、map 和 channel，返回已初始化、可直接使用的值。

```go
p := new(int)             // *int
m := make(map[string]int) // map 可直接写入
```

`new` 不等于一定在堆上分配，具体位置仍由逃逸分析和编译器优化决定。

## 8. 哪些类型可以比较？哪些可以作为 map key？

**答案：**

bool、数字、string、指针、channel、interface，以及元素全部可比较的数组和结构体可以使用 `==`。slice、map、func 不能互相比较，只能与 nil 比较。

map key 必须是可比较类型。interface 虽然可作 key，但如果它里面装入了 slice 等不可比较的动态值，运行时会 panic。
