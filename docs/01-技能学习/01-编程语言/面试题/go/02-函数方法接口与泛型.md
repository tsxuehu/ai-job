# Go 面试题：函数、方法、接口与泛型

## 1. Go 支持函数或方法重载吗？

**答案：**

不支持。同一作用域内不能定义同名但参数不同的函数；同一类型也不能定义多个同名方法。

Go 通常使用不同函数名、不同类型、接口、函数值或泛型表达不同行为。“不支持重载”不等于“不支持多态”。

## 2. 值接收者和指针接收者怎么选？

**答案：**

方法要修改接收者、类型很大、类型含锁或需要表示同一实体时，通常使用指针接收者。小型且希望保持值语义的类型可以使用值接收者。

同一类型的方法接收者风格应尽量一致。不要只凭“指针更快”决定，因为指针还会引入 nil、共享状态、逃逸和并发问题。

## 3. 值类型和指针类型的方法集有什么区别？

**答案：**

若 `T` 定义了值接收者方法，该方法同时属于 `T` 和 `*T` 的方法集。若定义的是指针接收者方法，它只属于 `*T` 的方法集。

编译器可以对可寻址值的直接方法调用自动取地址，但这不会改变接口实现时的方法集规则。

## 4. Go 类型如何实现 interface？

**答案：**

隐式实现。一个类型只要拥有接口要求的全部方法，就实现了该接口，不需要写 `implements`。

```go
var _ PaymentGateway = (*AlipayGateway)(nil)
```

这行是常见的编译期断言：如果 `*AlipayGateway` 没有实现 `PaymentGateway`，编译就会失败。

## 5. interface 变量中保存什么？方法怎么调用？

**答案：**

概念上，接口值包含“动态类型 + 动态值”。当接口中装入 `*AlipayGateway` 时，调用 `gateway.Pay` 会执行 `(*AlipayGateway).Pay`。

当前 Go 运行时可以通过类似 `itab` 的结构建立“接口类型 + 具体类型”的方法表，调用时从固定槽位取函数地址，而不是每次按字符串搜索方法。`itab` 是实现细节，不是语言规范保证的 API。

## 6. 为什么接口里装了 nil 指针，接口却不等于 nil？

**答案：**

接口只有在“动态类型和动态值都为 nil”时才等于 nil。

```go
var p *AlipayGateway = nil
var gateway PaymentGateway = p

fmt.Println(gateway == nil) // false
```

此时接口的动态类型是 `*AlipayGateway`，只有动态值是 nil。项目中不要把有类型的 nil 指针作为接口返回；没有对象时直接返回 nil 接口。

## 7. 结构体嵌入是继承吗？

**答案：**

不是传统类继承。嵌入可以提升字段和方法，帮助组合行为，但没有父类子类的子类型关系、虚函数覆盖和保护成员。

Go 通常使用“组合 + interface”实现封装和多态。嵌入不应只为了减少几行代码，要确认被嵌入类型的公开方法是否应该成为外层类型的 API。

## 8. 普通函数能不能实现可替换行为？

**答案：**

可以。函数是值，可以作为参数、返回值或结构体字段。

```go
type PayFunc func(ctx context.Context, orderID string, amount int64) error

func Checkout(ctx context.Context, pay PayFunc) error {
	return pay(ctx, "order-1", 100)
}
```

这是函数策略或回调，适合只需要一个行为的场景。需要多个关联方法或对象状态时，interface 通常更清晰。

## 9. 泛型和 interface 有什么区别？Go 1.27 的泛型方法是什么？

**答案：**

泛型用类型参数表达“同一算法适用多种类型”；interface 值则常用于“运行时可替换实现”。不要为了去掉几行重复就引入难懂的泛型。

Go 1.27 允许方法声明自己的类型参数。但 interface 方法仍不能声明类型参数，泛型方法也不能用来实现接口方法。面试中应区分“类型约束”和“运行时多态”。
