# C++ 面试题：性能、工具链与工程

## 1. 什么是 ABI？为什么只保持头文件不变还不够？

**答案：**

ABI 是已编译组件之间的二进制约定，包括调用约定、符号命名、对象布局、虚表、异常和标准库实现边界。公开头文件文本不变，不代表编译器、标准库、编译开关和依赖的 ABI 一致。

稳定库边界应固定工具链和构建参数，控制公开类布局，并通过版本化、PImpl、C ABI 或进程协议隔离变化。

## 2. 为什么算法复杂度相同，性能仍可能差很多？

**答案：**

大 O 忽略常数、内存布局、cache miss、分支预测、分配、锁竞争和向量化等真实硬件成本。连续 `vector` 的线性扫描常可胜过节点容器上理论操作数更少的访问。

性能回答应包含真实数据布局、热点 profile 和稳定 benchmark，不根据“手写指针一定快”或“无锁一定快”做决策。

## 3. ASan、UBSan 和 TSan 分别查什么？

**答案：**

ASan 主要发现越界、use-after-free 等内存错误；UBSan 检查多种未定义行为；TSan 检测数据竞争。它们会改变时序、内存和性能，通常分别运行，不用 sanitizer 构建的性能数据代表生产。

工程上在 CI 对核心测试建立 sanitizer 构建，配合严格警告、静态分析、fuzz 和真实故障回归测试。

## 4. 现代 CMake 为什么强调 target？

**答案：**

target 是可编译库或可执行程序的工程边界。源文件、头文件路径、编译特性、宏和依赖应通过 `PRIVATE`/`PUBLIC`/`INTERFACE` 挂在 target 上，让使用要求沿依赖图传播。

不要用全局 include 路径、全局编译开关和手写链接顺序污染整仓库。测试、benchmark 和生产程序也应作为明确 target，复用同一核心库。
