# C++ 面试题：模板、泛型与编译

## 1. 模板什么时实例化？为什么常放在头文件？

**答案：**

模板本身是生成代码的模板，当编译单元需要某个具体参数组合时才实例化。隐式实例化通常需要在使用点看到完整模板定义，因此定义常放在头文件。

大型项目可以用显式实例化统一生成常用类型，减少编译量，但会限制可用类型集合，需要按库 API 设计。

## 2. concept 比传统 SFINAE 改善了什么？

**答案：**

concept 把模板参数需要满足的操作和语义条件显式写入接口，可用于重载选择，并提供更接近失败原因的诊断。

concept 不应只是把巨大 `enable_if` 换个写法。好的 concept 表达可重用的能力和语义，例如可排序、可写入，而不是偶然查看某个成员是否存在。

## 3. 什么是 ODR？它为什么会导致难查的问题？

**答案：**

ODR 是 One Definition Rule，规定对象、函数、类和模板在程序中可以有多少个声明和定义，以及多个编译单元中的定义必须保持一致。

宏、编译开关、不同头文件版本和 ABI 不一致可能让同一 inline/template 定义在不同单元中产生差异。某些 ODR 违反不一定有编译或链接诊断，可能以随构建参数变化的异常行为出现。

## 4. 编译期多态、虚函数和类型擦除如何选？

**答案：**

模板适合类型集合在编译时可知、需要内联和零额外调度开销的场景，代价是编译时间、代码膨胀和 API 错误更复杂。

虚函数适合运行时对象类型可替换、有清晰类层次的场景。类型擦除如 `std::function` 可以在不暴露具体类型和继承结构的情况下提供统一值语义容器，但可能有间接调用和分配成本。
