# C++ 面试题：内存、资源与异常

## 1. 什么是 RAII？它只管内存吗？

**答案：**

RAII 把资源的获取与对象初始化绑定，把释放与析构绑定。对象离开作用域时，无论正常返回还是异常展开，析构函数都负责释放。

资源不只是内存，还包括文件、socket、锁、线程、事务和底层句柄。`vector`、`unique_ptr`、`lock_guard` 都是 RAII 资源句柄。

## 2. `unique_ptr`、`shared_ptr` 和 `weak_ptr` 如何选？

**答案：**

`unique_ptr` 表示唯一所有权，可移动不可复制，应是动态对象的默认选择。`shared_ptr` 表示多个所有者共同延长对象生命，带来控制块、原子引用计数和共享销毁责任。

`weak_ptr` 不拥有对象，用于观察 `shared_ptr` 对象并打破循环引用。不要为了“避免想生命周期”全部使用 `shared_ptr`；应先定义清晰所有者。

## 3. `shared_ptr` 为什么会泄漏？`make_shared` 有什么特点？

**答案：**

两个对象相互保存 `shared_ptr` 会让引用计数永远无法归零，应让其中非拥有关系使用 `weak_ptr`。

`make_shared` 通常可以把对象和控制块合并分配，减少分配次数并提高异常安全。但只要还有 `weak_ptr` 保留控制块，合并分配的大对象内存也可能无法立即返还给分配器。

## 4. 异常安全有哪些保证？`noexcept` 有什么影响？

**答案：**

基本保证是失败后对象仍有效且无资源泄漏；强保证是失败后可观察状态与调用前一样；不抛保证是操作绝不传出异常。

`noexcept` 是接口承诺。若 `noexcept` 函数让异常逃出，程序调用 `std::terminate`。容器在可能时更倾向使用 noexcept 移动保持强保证，因此资源类的移动操作通常应在真正安全时标记 `noexcept`。
