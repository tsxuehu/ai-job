# C++ 面试题：并发与内存模型

## 1. 什么是 data race？后果是什么？

**答案：**

多个线程并发访问同一内存位置，至少一个访问是写，且没有合适同步，就形成 data race。在 C++ 中，data race 通常导致未定义行为，不能依赖“机器字写入看起来原子”。

使用 mutex、atomic 或更高层任务所有权模型建立 happens-before。用 ThreadSanitizer 扩大发现概率，但测试未报错不是无竞争的证明。

## 2. `volatile` 能用于线程同步吗？

**答案：**

不能。C++ `volatile` 主要表示对象可在程序常规推理之外被修改，常见于特定内存映射 IO；它不提供线程间原子性和同步顺序保证。

共享计数器或标志使用 `std::atomic`，多字段不变式通常使用 mutex。不要因为 Java/C# 中同名关键字的语义而误用 C++ volatile。

## 3. 如何避免死锁？

**答案：**

减少共享可变状态和持锁时间，对多把锁建立统一获取顺序，或使用 `std::scoped_lock` 协调同时获取。不在持锁时执行未知回调、阻塞 IO 和跨组件调用。

资深回答还要说明诊断：采集所有线程栈，建立“线程等待哪把锁、当前持有哪把锁”的等待图，再找环。

## 4. `std::jthread` 和 `stop_token` 解决了什么？

**答案：**

`std::thread` 对象析构时仍 joinable 会终止程序，调用者必须手动 join 或 detach。C++20 `std::jthread` 析构时会请求停止并 join，把线程等待变成 RAII。

`stop_token` 是协作式取消信号，不会强制杀死线程。任务必须在循环、等待和阻塞边界主动检查停止，并保证每条路径都能释放资源。
