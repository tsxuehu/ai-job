# C++ 面试题：场景题与项目深挖

## 1. 设计一个返回对象的 API，如何表达所有权？

**答案：**

小型或可移动结果优先按值返回，依靠消除拷贝和移动语义。独占动态所有权返回 `unique_ptr<T>`；真正共同所有时才返回 `shared_ptr<T>`；非拥有观察则用引用、裸指针或 view，并明确生命周期。

不返回指向局部对象的指针或引用，也不把“调用者记得 delete”当成所有权协议。

## 2. 只在 Release 环境崩溃，如何排查？

**答案：**

先保留崩溃转储、符号、构建 ID、编译器和依赖版本，确保能还原线程栈。比较 Debug/Release 宏、优化、链接和 ABI 差异，重点怀疑未初始化、越界、悬空、data race、时序依赖和 ODR 违反。

用带调试信息的优化构建复现，分别运行 ASan/UBSan/TSan，最小化输入和变更范围。不用关闭优化或增加 sleep 作为最终修复。

## 3. 如何评估一个无锁队列设计？

**答案：**

先问为什么普通 mutex 队列不能满足需求，然后明确单/多生产者、单/多消费者、有界容量、背压和停止语义。无锁正确性还涉及内存序、ABA、对象回收和 false sharing。

通过压力测试、TSan 能覆盖的部分、模型检查/严格推理和真实负载 benchmark 验证。无锁不等于无等待，也不等于在所有竞争强度下更快。

## 4. 如何回答“你做过的 C++ 性能优化”？

**答案：**

给出基线和证据：业务负载、P99/吞吐、CPU、RSS、分配率和 profile 热点。说明根因是算法、复制/分配、cache、锁、系统调用还是 IO，以及为什么选当前修改。

最后给出优化前后数据、正确性回归、代价和容量上限。“把 `map` 换成 `unordered_map`”或“换成指针”没有 profile 和端到端结果，不是完整资深回答。
