# C++ 面试题：容器、迭代器与算法

## 1. `vector` 和 `list` 如何选？

**答案：**

`vector` 连续存储，遍历局部性好，支持常数时间随机访问，通常应作为序列容器默认选择。`list` 的节点分散分配，持有已知位置迭代器时插入删除不移动其他节点，但随机访问慢且 cache 局部性差。

不能只看渐进复杂度选容器。元素大小、遍历频率、分配成本、cache miss 和迭代器稳定性一起决定真实性能。

## 2. 什么是迭代器失效？

**答案：**

容器修改后，以前保存的迭代器、指针或引用可能不再指向有效元素。继续解引用失效迭代器是未定义行为。

`vector` 扩容会让所有指向元素的迭代器、引用和指针失效；不扩容的插入删除也可能让操作位置及其后的迭代器失效。面试应查具体容器和操作的规则，不要概括为“STL 迭代器都稳定”。

## 3. `unordered_map` 一定比 `map` 快吗？

**答案：**

不一定。`unordered_map` 平均查找接近常数时间，但有哈希计算、bucket、内存和最坏退化成线性的成本。`map` 保持有序，操作通常是对数复杂度，支持范围查询并有更稳定的最坏界。

选择取决于是否需要顺序、范围操作、key 分布、内存上限和真实基准。面向不可信 key 还要考虑哈希碰撞导致的拒绝服务风险。

## 4. `string_view` 和 `span` 最大的风险是什么？

**答案：**

它们是非拥有视图，只保存指向外部数据的地址和长度，不会延长底层对象生命。若原 string/vector 已销毁、扩容或修改导致存储失效，视图就悬空。

适合把它们作为同步、不保存的函数参数。异步回调、跨线程任务和长期成员中要明确证明底层数据活得更久，否则应拷贝或转移所有权。
