# 学习、项目与面试能力映射

面试准备不是独立背题。每个面试方向都应关联学习内容和工程证据，让回答能够经受连续追问。

| 面试方向 | 核心学习内容 | 推荐实践证据 | 回答时必须体现 |
| --- | --- | --- | --- |
| 编码与算法 | 数据结构、复杂度、主语言 | 限时编码、测试和错题复盘 | 澄清、正确性、边界、复杂度 |
| 主语言 | 运行时、并发、内存、框架 | P0/P1、性能或故障实验 | 原理、工具、真实问题和取舍 |
| 操作系统与网络 | 进程、内存、IO、TCP、HTTP | 请求链路、抓包和系统实验 | 从现象到证据的排查过程 |
| 数据库 | 建模、索引、事务、锁、复制 | 迁移、执行计划、慢 SQL 分析 | 数据规模、查询、取舍和风险 |
| Redis 与消息队列 | 一致性、热点、幂等、积压 | P1 与故障注入 | 失败场景、补偿、观测和恢复 |
| 分布式与系统设计 | 容量、一致性、高可用、成本 | P1 架构图、ADR、压测 | 需求、量级、方案比较和演进 |
| 故障排查 | 指标、日志、Trace、假设验证 | 实验报告和事故复盘 | 发现、止损、定位、恢复、防复发 |
| RAG | 数据、检索、权限、引用、评测 | P2 数据集与评测报告 | 分组指标、失败样本和上线门槛 |
| Agent | 工具、状态、权限、幂等、审批 | P2 执行轨迹和安全测试 | 可控性、恢复、审计和成本 |
| 项目深挖 | 需求、贡献、决策、结果 | README、指标、ADR 和复盘 | 真实性、个人行动、数据和反思 |
| 行为面试 | Ownership、协作、冲突、成长 | 六个 STAR-R 故事 | 情境、行动、结果和复盘 |

## 证据等级

| 等级 | 回答特征 | 面试风险 |
| --- | --- | --- |
| E0 无证据 | 只会名词或结论 | 一次追问后暴露 |
| E1 学习证据 | 能解释原理和示例 | 缺少个人实践 |
| E2 实验/项目证据 | 有代码、测试、指标和失败场景 | 适合应届生核心证明 |
| E3 生产证据 | 有真实业务规模、事故和长期结果 | 必须如实说明个人责任 |

应届生不必伪装 E3。高质量 E2 证据比无法解释的“线上百万 QPS”更可信。

## 回答结构

技术问题优先使用：

> 结论 → 原理 → 适用场景 → 失败模式 → 技术取舍 → 项目证据

故障问题优先使用：

> 影响确认 → 止损 → 建立假设 → 数据验证 → 恢复 → 根因 → 防复发

系统设计优先使用：

> 需求与量级 → API 与数据 → 高层架构 → 关键路径 → 可靠性与安全 → 观测与成本 → 演进
