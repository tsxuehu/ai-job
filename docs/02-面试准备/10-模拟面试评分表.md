# 模拟面试评分表

每次模拟只使用与真实面试相同的时间和工具限制。面试结束后先独立复盘，再查看资料修改答案。

## 评分等级

每项 1—5 分：

| 分数 | 表现 |
| ---: | --- |
| 1 | 无法回答或大量事实错误 |
| 2 | 能说概念，但结构混乱、缺少验证和边界 |
| 3 | 回答基本正确，有常见场景和合理过程 |
| 4 | 能说明失败模式、取舍，并提供项目证据 |
| 5 | 在不确定条件下仍能澄清、推理、校准并形成完整方案 |

## 通用评分维度

| 维度 | 权重 | 观察点 | 得分 |
| --- | ---: | --- | ---: |
| 需求澄清 | 10% | 主动确认目标、输入、规模和限制 |  |
| 基础正确性 | 20% | 概念、代码和推理没有关键错误 |  |
| 分析结构 | 15% | 从结论到依据，重点清晰 |  |
| 边界与失败 | 15% | 识别异常、并发、安全和恢复问题 |  |
| 技术取舍 | 15% | 比较方案，说明适用条件和代价 |  |
| 项目证据 | 15% | 使用真实代码、数据、决策或复盘 |  |
| 沟通与校准 | 10% | 接受提示、修正错误、控制时间 |  |

总分不是唯一结果。任何“基础正确性”低于 3 分的问题都应优先修复。

## 编码面试附加检查

- [ ] 编码前确认输入、输出、规模、重复和异常。
- [ ] 先说明思路和复杂度，再开始实现。
- [ ] 命名、结构和错误处理符合主语言习惯。
- [ ] 主动测试空值、最小值、重复、溢出和极端规模。
- [ ] 能发现并修正错误，不靠面试官给出完整答案。

## 系统设计附加检查

- [ ] 明确功能范围、非功能目标和容量假设。
- [ ] 给出 API、数据模型和核心链路。
- [ ] 说明一致性、可用性、延迟、安全和成本取舍。
- [ ] 覆盖超时、重试、限流、降级、观测和回滚。
- [ ] 先设计满足当前规模的方案，再说明演进路径。

## 项目深挖附加检查

- [ ] 能在一分钟内说明背景、行动、结果和个人贡献。
- [ ] 每个数字都有环境、测量方法和证据。
- [ ] 能解释至少两个关键技术决策及替代方案。
- [ ] 能说明一次失败、限制或判断错误。
- [ ] 不把团队成果全部描述成个人成果。

## AI 专项附加检查

- [ ] 区分模型、检索、工具和业务链路问题。
- [ ] 说明评测数据、基线、分组指标和上线门槛。
- [ ] 覆盖权限、提示注入、数据泄漏、审批和审计。
- [ ] 覆盖模型超时、降级、版本、延迟和成本。
- [ ] 不把 Prompt 调整描述成无法验证的质量提升。

## 复盘输出

每次模拟结束后记录：

1. 得分最低的三个维度。
2. 一个知识缺口、一个实践缺口和一个表达缺口。
3. 对应需要补充的文档、实验或项目证据。
4. 下次模拟前可以验收的具体动作。
5. 下一次模拟日期与相同问题的目标分数。
