# 职业成长复盘

建议每半年进行一次，使用事实和证据判断成长，而不是只统计工作时长、需求数量和学习课程。

## 结果

- 我负责的业务或系统目标是什么？
- 哪些指标发生了变化？如何确认与我的工作有关？
- 哪些结果没有达到预期？原因是什么？

## 责任边界

- 我目前主要负责任务、模块、服务还是跨系统结果？
- 哪些关键决策由我推动？哪些仍依赖他人？
- 面对事故、迁移和不确定需求时，我承担了什么责任？

## 技术判断

- 哪个技术决策最成功？证据是什么？
- 哪个判断后来被证明错误？我如何修正？
- 我是否在不需要复杂度时主动选择了简单方案？

## 组织影响

- 哪些文档、工具、规范或平台被他人持续使用？
- 我指导了谁，对方现在能独立承担什么？
- 哪个跨团队问题因为我的推动得到解决？

## 下一阶段计划

只选择一个主要成长主题：

```text
目标责任边界：
需要解决的真实问题：
当前差距：
计划承担的项目或职责：
需要寻找的导师或协作者：
六个月后的验证证据：
```

如果无法获得真实责任和反馈，继续阅读更多知识通常不能解决成长瓶颈。应主动寻找项目、轮岗、导师、开源协作或更合适的工作环境。
