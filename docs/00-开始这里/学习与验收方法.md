# 学习与验收方法

学习目标不是“看完”，而是形成可重复、可证明、可讲解的能力。

## 四步学习法

### 1. 原理

用自己的话回答：它解决什么问题、核心机制是什么、有哪些限制、替代方案是什么。

### 2. 实验

构造最小环境验证一个关键结论。记录环境、步骤、预期、实际结果和解释，让其他人可以复现。

### 3. 项目

把能力接入当前阶段项目，处理正常流程、异常流程、测试、观测和文档。

### 4. 表达

完成一次五分钟讲解，并接受连续追问：为什么这样做、失败怎么办、如何证明有效、还有什么替代方案。

## 任务完成定义

一项工程任务至少满足：

- 目标和验收条件明确。
- 代码可以构建、运行并通过相关测试。
- 关键失败路径得到处理。
- 日志和指标足以定位主要问题。
- README 或设计文档说明使用方法和边界。
- 记录关键决策、数据结果和遗留问题。

只提交代码，不等于完成工程交付。

## 每周计划模板

```markdown
# 第 N 周

## 本周唯一核心目标

## 与目标 JD 的关系

## 项目改进

## 指标与证据链接

## 模拟讲解反馈

## 本周失败与下周调整
```

## 如何使用 AI

可以使用 AI：

- 帮助拆解问题、生成测试思路和解释错误信息。
- 对设计方案提出反例、风险和追问。
- 辅助生成脚手架、重复代码和文档初稿。
- 模拟面试官、代码审查者和事故复盘评审者。

必须由自己完成：

- 确认需求、边界、数据和安全约束。
- 阅读并解释最终提交的代码。
- 运行测试、验证输出并检查失败场景。
- 对技术决策、结果和引用资料负责。

如果关闭 AI 后无法解释、修改或排查生成内容，这项能力还没有掌握。

## 实验记录要求

每个实验至少包含：

1. 问题与假设。
2. 环境与版本。
3. 操作步骤和输入数据。
4. 预期与实际结果。
5. 指标、日志或截图证据。
6. 结论、限制和下一步。

可以直接使用 [实验报告模板](../../templates/实验报告模板.md)。
