# 后端工程师能力模型

能力模型用于发现差距和记录证据，不用于给自己贴标签。不同能力可以处在不同等级，例如数据库 L2、网络 L1、项目交付 L2。

## 评分规则

| 等级 | 判断标准 | 可接受证据 |
| --- | --- | --- |
| L0 不了解 | 不能准确解释基本概念 | 无 |
| L1 能解释 | 能说明原理和常见场景，但不能独立完成 | 学习笔记、口头讲解、简单题目 |
| L2 能交付 | 能独立实现、测试、部署和处理常见失败 | 代码、测试、实验、项目、指标 |
| L3 能负责 | 有真实生产责任，能排障、优化并推动改进 | SLO、事故复盘、线上指标、架构决策 |
| L4 能引领 | 能解决跨系统问题，建立方法并指导他人 | 组织级方案、平台、规范、长期收益 |

没有可验证证据时，评分不得超过 L1。个人项目可以支持 L2，但不能替代 L3 所需的真实生产责任。

## 能力维度

### 1. 编程与代码质量

- L1：掌握语法、标准库、数据结构、错误处理和基本测试。
- L2：理解运行时、并发、内存与性能工具，能维护中等规模服务。
- L3：能处理复杂并发、性能、可维护性和工程规范问题。
- L4：能制定跨团队语言与工程实践，解决框架或运行时级问题。

### 2. 计算机基础

- L1：理解操作系统、网络、数据结构和算法的核心概念。
- L2：能使用抓包、系统指标、调试器和分析工具验证问题。
- L3：能定位跨进程、网络、存储和运行时的疑难故障。
- L4：能把底层机制转化为系统级性能和稳定性方案。

### 3. 数据与中间件

- L1：理解 SQL、索引、事务、缓存和消息队列用途。
- L2：能设计数据模型，处理慢 SQL、缓存一致性和消息幂等。
- L3：能负责迁移、分片、容量、数据一致性和故障恢复。
- L4：能制定跨业务的数据架构与中间件治理方案。

### 4. API 与业务建模

- L1：能实现 CRUD、参数校验、鉴权和错误处理。
- L2：能划分领域边界，设计幂等、安全、可演进的 API。
- L3：能处理复杂业务规则、兼容迁移和跨团队契约。
- L4：能抽象平台能力，并平衡业务速度与长期演进。

### 5. 分布式与系统设计

- L1：理解复制、分片、一致性、超时和重试等概念。
- L2：能对常见业务完成容量估算和高层设计。
- L3：能在真实约束下负责高可用、容灾和系统演进。
- L4：能解决跨系统架构问题并推动复杂迁移。

### 6. 生产工程

- L1：理解测试、容器、CI/CD、日志、指标和 Trace。
- L2：能部署、观测、压测、告警、回滚和演练故障。
- L3：能制定 SLO，主导事故处理和稳定性、成本治理。
- L4：能建立组织级交付、可观测性和可靠性体系。

### 7. AI 应用工程

- L1：理解模型 API、Prompt、RAG、Agent 和 Evals 的基本边界。
- L2：能实现含权限、引用、评测和受控工具调用的 AI 功能。
- L3：能负责质量、延迟、安全、成本和多模型治理。
- L4：能建立跨产品的 AI 应用平台、评测体系和安全标准。

### 8. 业务与影响力

- L1：能澄清任务并清楚汇报进展。
- L2：能独立完成需求，说明个人贡献和量化结果。
- L3：能推动跨团队项目、管理风险并指导新人。
- L4：能识别组织级问题、建立共识并持续培养团队。
