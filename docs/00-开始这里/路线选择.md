# 路线选择

路线选择的目标是控制学习范围。主语言需要达到能够编码、测试、排障、优化和参加面试的深度，辅助语言只承担明确用途。

## 先根据岗位选择

从目标 JD 中统计语言和技术栈，不要仅凭热度或个人印象决定。选择时考虑：

- 目标城市、行业和公司的岗位数量。
- 自己已有课程、实习和项目积累。
- 是否有高质量项目、导师或社区资源。
- 语言与目标业务场景是否匹配。
- 是否愿意长期理解其运行时和工程生态。

## 三条参考路线

### 通用业务后端

- 主语言：从目标 JD 高频的 Java、Go、Node.js 等技术栈中选择一门。
- 核心能力：API、数据库、Redis、消息队列、事务、分布式和生产工程。
- 项目顺序：P0 → P1；AI 内容作为加分项或业务集成能力。
- 面试重点：主语言、数据库、缓存、消息、系统设计、项目和排障。

### AI 应用后端

- 主语言：选择一门成熟后端语言；Python 常作为模型、数据和评测辅助语言。
- 核心能力：传统后端全部基础，加上模型 API、RAG、Agent、Evals 和 AI 安全。
- 项目顺序：P0 → P1 → P2。
- 面试重点：系统可靠性、权限、评测、延迟、成本和工具调用安全。

### 平台与基础设施

- 主语言：根据目标岗位选择 Go、Java、Rust、C++ 或 Python 等。
- 核心能力：操作系统、网络、并发、存储、调度、可观测性和性能分析。
- 项目顺序：P0 → P1，再增加网关、任务平台或可观测性专项。
- 面试重点：底层机制、故障排查、分布式系统、容量和性能。

AI 基础设施中的 GPU、CUDA、推理引擎和分布式训练需要单独的专项路线，本仓库暂不完整覆盖。

具体实施清单参见 [Java 后端路线](../../tracks/Java后端路线.md)、[Go 后端路线](../../tracks/Go后端路线.md) 和 [Python AI 应用后端路线](../../tracks/Python-AI应用后端路线.md)。如果目标栈不在其中，按 [技术栈路线的共同要求](../../tracks/README.md) 和学习章节模板建立自己的路线。

## 主语言的掌握标准

主语言至少需要满足：

- 能在限定时间内完成编码题，并主动覆盖边界测试。
- 能解释运行时、并发模型、内存管理和错误处理。
- 能实现超时、取消、重试、限流和优雅停机。
- 能使用分析工具定位 CPU、内存、阻塞和竞争问题。
- 能用该语言完成 P0 和 P1 的核心服务。

详细内容参见 [编程语言学习策略](../01-技能学习/01-编程语言/README.md)。
