# 开始这里

本目录帮助你把仓库转换成自己的学习计划。不要先收集更多课程，先确定目标、差距和需要交付的证据。

## 第一步：明确目标

收集 10—20 个目标岗位的 JD，统计以下要求的出现频率：

- 主语言、框架和开发工具。
- 数据库、缓存、消息队列和分布式能力。
- Docker、Kubernetes、云平台、CI/CD 和可观测性。
- AI、RAG、Agent、模型服务和数据工程。
- 行业、业务、学历、实习及项目要求。

把能力分成“必需”“高频加分”“低频专项”，不要对所有岗位使用同一份计划。

## 第二步：完成自评

使用 [能力模型](能力模型.md) 为每项能力标记 L0—L4，并为评分附上证据链接。

没有代码、实验、指标、设计文档或真实经历支持的“熟悉”，最高只能记为 L1。

## 第三步：选择路线

阅读 [路线选择](路线选择.md)，确定：

- 一门主语言：用于算法、项目、面试和深入原理。
- 一门辅助语言：用于脚本、数据处理或 AI 集成。
- 一个目标岗位族：传统后端、AI 应用后端或平台工程。
- 当前阶段项目：P0、P1 或 P2。

## 第四步：建立周循环

按照 [学习与验收方法](学习与验收方法.md)，每周只承诺少量可验证结果：

1. 一个需要理解的核心问题。
2. 一个可复现实验或代码提交。
3. 一个接入项目的工程改进。
4. 一次讲解、模拟面试或复盘。

## 第五步：每四周校准一次

- 目标 JD 是否发生变化？
- 哪些能力只有笔记，没有实现证据？
- 项目是否可以被其他人在新环境中运行？
- 是否能解释失败场景和技术取舍？
- 面试模拟中的重复失分点是什么？

根据结果删除低价值任务，而不是不断延长清单。
