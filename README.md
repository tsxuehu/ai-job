# AI 时代后端工程师学习与面试指南

## 核心判断

> **AI 时代更有竞争力的后端工程师，不只是写接口快，而是能够把不确定的业务需求和概率性的 AI 输出，建设成稳定、安全、可观测、可回滚、成本可控的生产系统。**

AI 没有让后端基本功失效。语言、算法、操作系统、网络、数据库、缓存、消息队列、分布式系统和生产排障依然是核心；RAG、Agent、评测、AI 安全及成本治理，是建立在这些能力之上的新增部分。

学习时不要把重点全部放在 Prompt 技巧或某个热门框架上：

- **传统后端能力是地基。** 决定系统能否正确、稳定地运行。
- **AI 应用工程是新增能力。** 解决模型非确定性、质量、安全、延迟和成本问题。
- **AI 开发工具是效率放大器。** 工程师仍需理解、测试、审查并对生成代码负责。

## 需要具备的技能

### 1. 编程语言

从 Node.js、Python、Java、Go、Rust、C++ 中选择一门主语言，达到可以独立编码、测试、排障和优化的程度；再选择一门辅助语言完成跨领域工作。

掌握语言不能停留在框架 API，还需要理解：运行时、并发模型、内存管理、错误处理、资源释放、标准库、测试和性能分析。

### 2. 计算机与后端基础

- 数据结构与算法：能在限定时间内澄清问题、编写代码、分析复杂度并验证边界。
- 操作系统与网络：理解进程/线程/协程、内存、IO、TCP、HTTP、TLS、连接池和流式传输。
- 数据库：掌握数据建模、索引、事务、MVCC、锁、执行计划、复制和迁移。
- 缓存与消息：处理一致性、热点、重复、丢失、乱序、积压、幂等和失败恢复。
- 分布式系统：掌握服务治理、超时、重试、限流、熔断、分片、一致性和分布式事务。

### 3. 生产工程

能够负责代码合并之后的完整生命周期：测试、Docker、CI/CD、灰度、回滚、日志、指标、链路追踪、SLO、压测、故障处理和事故复盘。

### 4. AI 应用工程

- 模型 API、流式输出、结构化输出、工具调用和多模型适配。
- RAG 的解析、切分、检索、重排、权限、引用、更新和评测。
- Agent 的状态、工具、权限、幂等、审批、沙箱和失败恢复。
- Evals、回归测试、线上反馈和全链路可观测性。
- 提示注入、工具越权、数据泄漏等 AI 安全问题。
- token 成本、首 token 延迟、缓存、路由、限流、熔断和降级。

### 5. 业务与协作

能够澄清需求、识别业务指标、解释技术取舍、编写设计文档、推动跨团队项目，并用数据说明项目价值。

## 面试主要考察内容

| 考察方向 | 重点内容 |
| --- | --- |
| 编码与算法 | 数据结构、复杂度、正确性、边界、测试和表达 |
| 主语言 | 运行时、并发、内存、框架原理和故障排查 |
| 后端基础 | 网络、操作系统、数据库、Redis、消息队列和分布式系统 |
| 项目深挖 | 项目真实性、个人贡献、规模、技术取舍、量化结果和复盘 |
| 系统设计 | 需求、容量、API、数据模型、一致性、高可用、安全和成本 |
| 故障排查 | CPU、内存、GC、连接池、慢查询、消息积压和 P99 延迟 |
| AI 专项 | RAG、Agent、Evals、模型可靠性、权限、安全、延迟和 token 成本 |
| 行为面试 | Ownership、协作、冲突处理、推动能力和失败复盘 |

普通后端岗位仍以后端基本功、项目和系统设计为主；AI 应用后端会在相应职级要求上增加模型集成与治理能力；AI 基础设施岗位还可能考察 GPU、调度、存储、网络和推理性能。

## 学习与准备优先级

普通后端岗位可以参考：

| 方向 | 建议投入 |
| --- | ---: |
| 主语言、算法、操作系统、网络 | 35% |
| 数据库、缓存、消息队列、分布式系统 | 25% |
| 项目深挖、系统设计、故障排查 | 25% |
| AI 应用工程 | 15% |

AI 原生公司或明确包含 RAG、Agent 的岗位，可把 AI 应用工程提高到 25%—30%，但不应以牺牲数据库、分布式系统和生产工程基础为代价。

## 面试前至少能回答的问题

1. 主语言的并发模型是什么，常见问题有哪些？
2. 一条 SQL 很慢，如何定位和优化？
3. 缓存与数据库如何保持业务可接受的一致性？
4. 如何处理消息重复、丢失、乱序和积压？
5. 如何设计幂等的支付回调或订单接口？
6. 如何设计一个高并发、高可用的后端系统？
7. 服务 P99 延迟突然升高，如何排查？
8. 如何设置超时和重试，并避免重试风暴？
9. 如何设计带权限控制和引用来源的 RAG 系统？
10. 如何证明一个 AI 功能确实变好了？
11. 如何防止提示注入、数据泄漏和工具越权？
12. 能否讲清一次自己真正负责的故障、取舍或失败？

## 使用方法

1. 先阅读“需要具备的技能”，完成能力自评，确定一门主语言和一门辅助语言。
2. 按学习路线补基础、工程、架构和 AI 应用能力。
3. 通过实战项目把技能转化为代码、指标、评测和故障复盘。
4. 再阅读“面试考察内容”，按目标岗位和主语言准备。
5. 用检查表模拟面试；不会解释、不能实现、没有项目证据的内容，都不算真正掌握。
