# 阶段晋级检查表

晋级意味着已经稳定满足当前阶段门槛，而不是刚刚接触下一阶段知识。每个勾选项都要附证据链接。

## L0 → L1

- [ ] 能用主语言独立完成中等规模编码任务和边界测试。
- [ ] 能解释一次请求经过进程、网络、服务和数据库的过程。
- [ ] 完成至少两个操作系统、网络或运行时实验。
- [ ] 熟练使用 Git、Linux、调试器、测试和依赖管理工具。
- [ ] 有一个包含测试、日志和错误处理的小型程序。

## L1 → L2

- [ ] P0 可以由其他人在新环境中一条命令启动。
- [ ] 能设计 API、表结构、索引、事务和对象级权限。
- [ ] 核心流程包含单元、集成和端到端测试。
- [ ] 完成慢 SQL 和并发正确性分析。
- [ ] 能说明 P0 的三个已知限制和下一步演进方向。

## L2 → 求职就绪

- [ ] P1 通过幂等、一致性、观测、压测和故障演练验收。
- [ ] 有架构图、容量估算、至少两个 ADR 和一次事故复盘。
- [ ] 有两个可深挖项目和六个真实行为故事。
- [ ] 完成三次完整模拟面试，基础正确性均不低于 3 分。
- [ ] 简历中的每个技术和数字都有可解释证据。
- [ ] AI 岗位已完成 P2 的权限、引用、评测、安全和成本闭环。

## L2 → L3

这一阶段需要真实生产责任：

- [ ] 持续负责一个重要服务的需求、发布、SLO 和故障处理。
- [ ] 主导一次有量化结果的性能、稳定性或成本改进。
- [ ] 完成复杂迁移、架构演进或跨团队项目。
- [ ] 有真实事故从发现到防复发的完整复盘。
- [ ] 能让其他工程师依据文档和工具接手系统。

## L3 → L4

- [ ] 解决多个团队共同面对的系统性问题。
- [ ] 建立被持续采用的平台、标准或工程方法。
- [ ] 能用业务和工程数据说明长期收益。
- [ ] 成功培养可以独立负责系统的工程师。
- [ ] 能说明重要判断错误及方法如何因此改进。
- [ ] 影响力不依赖个人英雄式救火。

详细阶段定义参见 [成长路线图](../ROADMAP.md)。
