# 实验：数据库与缓存一致性

## 目标

验证 Cache Aside 在并发读写、删除失败和缓存过期时可能出现的不一致，并设计业务可接受的处理方式。

## 任务

1. 为一个读多写少的资源实现数据库读取和缓存。
2. 对比“先更新缓存”“先删缓存”和“提交后删缓存”的行为。
3. 使用并发测试构造旧值回填、缓存删除失败和热点 Key 失效。
4. 加入重试、消息补偿、版本号或短 TTL 中至少两种机制。
5. 记录一致性窗口、数据库负载和缓存命中率。

## 必须回答

- 为什么缓存和数据库通常不能形成普通本地事务？
- 哪些业务允许短暂不一致，哪些不能？
- 删除缓存失败如何被发现和修复？
- 热点 Key 失效时如何避免流量直接击穿数据库？

## 验收证据

- 可重复触发的不一致测试。
- 两种方案在正确性、复杂度和性能上的对比。
- 对最终选择、残余风险和监控方式的说明。
