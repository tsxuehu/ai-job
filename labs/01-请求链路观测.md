# 实验：请求链路观测

## 目标

观察一次客户端请求从 DNS、连接建立、HTTP 服务、数据库到响应返回的完整路径，并区分各阶段延迟。

## 任务

1. 启动一个连接数据库的最小 API。
2. 记录 DNS、TCP/TLS、首字节和总请求时间。
3. 为请求生成唯一 Request ID，并贯穿应用日志和数据库访问日志。
4. 接入 Trace，确认父子 Span 和依赖耗时。
5. 分别制造慢 SQL、连接等待和服务端处理延迟。
6. 比较日志、指标和 Trace 对三类问题的定位效果。

## 必须回答

- Keep-Alive 对连接和延迟有什么影响？
- 首字节慢与响应体传输慢分别可能说明什么？
- 应用耗时与客户端总耗时为什么可能不同？
- Request ID、结构化日志和 Trace 各自解决什么问题？

## 验收证据

- 一张请求链路图。
- 三类故障的 Trace 或指标对比。
- 一份说明排查顺序和观测盲区的实验报告。
